# Theory & Concepts
Counting the number of palindromic substrings in a given string is closely related to finding the longest palindromic substring. Instead of keeping track of the maximum length, we just increment a counter every time we identify a valid palindrome.

To do this efficiently, we employ the **Expand Around Center** technique. A string of length $N$ has $2N - 1$ possible centers (each character is a center, and the space between each adjacent pair of characters is also a center). For each center, we expand outwards as long as the characters match, counting each valid expansion as one palindromic substring.

This method operates purely on indices and avoids constructing any intermediate substrings, which is vital for keeping our space complexity minimal and our runtime highly performant.

# Code Implementation

public:
    int countSubstrings(string s) {
        int count = 0;
        
        auto countPalindromesAroundCenter = [&](int left, int right) {
            int localCount = 0;
            while (left >= 0 && right < s.length() && s[left] == s[right]) {
                localCount++;
                left--;
                right++;
            }
            return localCount;
        };
        
        for (int i = 0; i < s.length(); i++) {
            count += countPalindromesAroundCenter(i, i);     // Odd length
            count += countPalindromesAroundCenter(i, i + 1); // Even length
        }
        
        return count;
    }
};"

# Common Pitfalls
<Warning>
- **Forgetting Single Characters:** Single characters are valid palindromes. The algorithm correctly counts them when expanding from `(i, i)`, so ensure your base logic handles 1-length palindromes implicitly.
- **DP Memory Overhead:** While a 2D Dynamic Programming table can solve this, it requires $O(N^2)$ space. In an interview, allocating a large boolean matrix can be a red flag when an $O(1)$ space solution exists.
</Warning>
