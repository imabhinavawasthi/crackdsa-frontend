# Theory & Concepts
Strings are fundamentally sequences of characters. To effectively manipulate them, understanding how characters are encoded and represented in memory is crucial.
The two most common encoding standards are **ASCII** (American Standard Code for Information Interchange) and **Unicode**. 

**ASCII** uses 7 bits (or 8 bits for extended ASCII) to represent 128 (or 256) characters, which include English letters, digits, and control characters. The most important ASCII values to memorize for interviews are:
- `'A'` to `'Z'`: 65 to 90
- `'a'` to `'z'`: 97 to 122
- `'0'` to `'9'`: 48 to 57

You can easily convert a character to its integer index relative to the alphabet using standard subtraction: `'c' - 'a' = 2`.

**Unicode** was introduced to support a wider array of characters, including emojis and characters from various languages. It's often encoded as UTF-8, UTF-16, or UTF-32. While most basic coding interview problems assume an ASCII character set, you should always clarify this with your interviewer, as a Unicode string might require a hash map instead of a fixed-size integer array to track character frequencies.

# Common Pitfalls
<Warning>
- Assuming all characters are ASCII when the problem includes Unicode characters or emojis.
- Hardcoding ASCII integer values (like 97) instead of using character subtraction (`'c' - 'a'`), which is far more readable and less error-prone.
- Forgetting that uppercase and lowercase letters have different ASCII ranges. A common trick to convert between cases in C++ or Java is flipping the 5th bit or simply adding/subtracting 32.
</Warning>
