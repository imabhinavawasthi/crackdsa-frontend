# Theory & Concepts
A **palindrome** is a word, phrase, or sequence that reads the same backwards as forwards (ignoring non-alphanumeric characters and casing).

**Valid Palindrome I:**
The classic approach uses the **Two-Pointer technique**. One pointer starts at the beginning (`left = 0`) and the other at the end (`right = N - 1`). We move both pointers inward, skipping any non-alphanumeric characters. If the characters at the two pointers don't match, it's not a palindrome.

**Valid Palindrome II (Allowing 1 deletion):**
Here, we can delete at most one character to make the string a palindrome. We run the same two-pointer approach. When we find a mismatch at `left` and `right`, we have two choices:
1. Delete the character at `left`, meaning we check if the substring `(left + 1, right)` is a palindrome.
2. Delete the character at `right`, meaning we check if the substring `(left, right - 1)` is a palindrome.
If either option forms a palindrome, the original string is valid.

    bool validPalindrome(string s) {
        int left = 0, right = s.length() - 1;
        while (left < right) {
            if (s[left] != s[right]) {
                return isPal(s, left + 1, right) || isPal(s, left, right - 1);

            left++;
            right--;
        }

    }

# Common Pitfalls
<Warning>
- Using `s.replace()` to strip punctuation or `s[::-1]` to reverse strings out of habit. This creates $O(N)$ extra space, failing constraints requiring $O(1)$ space.
- In Valid Palindrome II, eagerly deleting the first mismatch without checking both possibilities (skip left vs. skip right).
</Warning>
