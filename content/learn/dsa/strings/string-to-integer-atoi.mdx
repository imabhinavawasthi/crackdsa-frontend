# Theory & Concepts
Implementing **`atoi`** (String to Integer) is a ubiquitous interview question that tests your defensive programming skills. The problem doesn't require advanced algorithmic data structures; rather, it assesses your ability to strictly follow parsing rules and handle systemic integer overflow.

The algorithm flows sequentially:
1. **Whitespace:** Ignore leading whitespaces.
2. **Sign:** Check for a `+` or `-` symbol.
3. **Digits:** Read digits until a non-digit character is encountered.
4. **Overflow:** Ensure the value remains within the bounds of a 32-bit signed integer $[-2^{31}, 2^{31} - 1]$. If it goes beyond, clamp it.

The overflow check is the critical step. We cannot just store the parsed number in a 64-bit integer, as interviewers often stipulate a strictly 32-bit environment. We must detect overflow *before* it happens by checking if `current_result > INT_MAX / 10`.

# Common Pitfalls
<Warning>
- **Python's Auto-Scaling Integers:** Python integers automatically scale to handle arbitrarily large values, avoiding hardware overflow. You MUST still implement manual overflow clamping to adhere to the 32-bit constraint of the problem.
- **Double Signs:** An input like `+-12` is invalid. The sign check should happen exactly once. Using a `while` loop for the sign check is a common bug.
</Warning>
