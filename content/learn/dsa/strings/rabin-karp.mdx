# Theory & Concepts
The **Rabin-Karp Algorithm** is an elegant string searching algorithm that uses hashing to find a pattern within a text. Unlike checking characters one by one, Rabin-Karp computes a numerical hash of the pattern and compares it against the hash of sliding windows of the text.

The secret sauce is the **Rolling Hash**. Calculating the hash of a string from scratch takes $O(M)$ time. If we did this for every window, we'd be back to $O(N \times M)$ time. A rolling hash allows us to compute the hash of the *next* window in $O(1)$ time by subtracting the value of the character dropping out of the window, multiplying by the base, and adding the value of the new character entering the window.

To avoid integer overflow, all hash computations are done modulo a large prime number. Note that because of modulo arithmetic, a hash match doesn't guarantee a string match (hash collision). We must perform a direct character comparison when hashes match.

# Common Pitfalls
<Warning>
- **Negative Modulo Handling:** When subtracting the outgoing character in the rolling hash, the result can become negative. Languages like C++ and Java can produce negative modulo results, so always check `if (t < 0) t += q;`.
- **Not Verifying Collisions:** Never assume a hash match means a guaranteed string match. Always verify the actual characters $O(M)$ when a hash match occurs.
</Warning>
