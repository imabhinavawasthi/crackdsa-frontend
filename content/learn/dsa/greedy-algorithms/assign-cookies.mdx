# Theory & Concepts
The **Assign Cookies** problem is a fantastic introductory Greedy algorithm. You are given two arrays: one representing the greed factors of children `g`, and another representing the sizes of cookies `s`. A child will only be content if they receive a cookie with a size greater than or equal to their greed factor (`s[j] >= g[i]`). You want to maximize the number of content children.

### The Greedy Strategy
To maximize the number of content children, we should always try to satisfy the **least greedy children first**, using the **smallest possible cookie** that meets their demand. 
Why? Because giving a massive cookie to a child with a small greed factor is a waste. That massive cookie could have been used to satisfy a much greedier child!

1. Sort the children's greed factors `g` in ascending order.
2. Sort the cookie sizes `s` in ascending order.
3. Use two pointers, one for the children and one for the cookies. 
4. If the current cookie can satisfy the current child, move both pointers. If not, the cookie is too small for this child (and all subsequent children), so just move the cookie pointer to try a bigger cookie.

# Code Implementation
<CodeBlock
  cpp="#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        sort(g.begin(), g.end());
        sort(s.begin(), s.end());
        
        int child_i = 0;
        int cookie_j = 0;
        
        while (child_i < g.size() && cookie_j < s.size()) {
            if (s[cookie_j] >= g[child_i]) {
                // Cookie fits, child is happy
                child_i++;
            }
            // Always move to the next cookie
            cookie_j++;
        }
        
        return child_i; // child_i represents the number of content children
    }
};"

# Common Pitfalls
<Warning>
- Forgetting to sort both arrays! The greedy two-pointer logic entirely relies on both arrays being processed from smallest to largest.
- Trying to iterate with nested loops resulting in an O(N*M) solution. A simple two-pointer approach is much more efficient.
</Warning>
