# Theory & Concepts
The **Candy Problem** is a famous LeetCode Hard problem that is beautifully solved using a two-pass Greedy algorithm. You have an array representing the `ratings` of children standing in a line. You must distribute candies following two rules:
1. Every child must have at least one candy.
2. Children with a higher rating must get more candies than their immediate neighbors.

Your goal is to find the minimum number of candies required.

### The Greedy Strategy
Trying to satisfy the left and right neighbors simultaneously in one pass leads to complex cascading updates. The greedy insight here is to **decouple the problem**:
- First, make sure every child has more candies than their **left** neighbor if their rating is higher.
- Second, make sure every child has more candies than their **right** neighbor if their rating is higher.

1. Create a `candies` array initialized to `1` for every child.
2. **Left-to-Right Pass**: Iterate from left to right. If `ratings[i] > ratings[i-1]`, set `candies[i] = candies[i-1] + 1`.
3. **Right-to-Left Pass**: Iterate from right to left. If `ratings[i] > ratings[i+1]`, you must ensure `candies[i]` is strictly greater than `candies[i+1]`. Set `candies[i] = max(candies[i], candies[i+1] + 1)`.
4. The answer is the sum of the `candies` array.

class Solution {

            }

        // Sum up all candies
        int totalCandies = 0;

# Common Pitfalls
<Warning>
- In the right-to-left pass, forgetting to take the `max()` of the current candy value and `candies[i+1] + 1`. Overwriting it directly will destroy the validity achieved during the left-to-right pass!
- Confusing rules regarding equal ratings. If two neighbors have the same rating, there is NO rule saying they must have the same number of candies.
</Warning>
