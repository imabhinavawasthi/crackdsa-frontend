# Theory & Concepts
The **Activity Selection Problem** is one of the most classic examples of a Greedy Algorithm. You are given `N` activities, each with a start time and an end time. Your goal is to select the maximum number of non-overlapping activities that can be performed by a single person or machine.

### The Greedy Strategy
The optimal heuristic for this problem is to always pick the activity that **ends the earliest**.
Why? Because picking the activity that finishes first leaves the maximum possible free time for subsequent activities. 

To implement this:
1. Sort all activities based on their **end times** in ascending order.
2. Select the first activity in the sorted list.
3. Iterate through the remaining activities. If the start time of the current activity is greater than or equal to the end time of the previously selected activity, select it and update the end time.

# Common Pitfalls
<Warning>
- Sorting by start time or duration instead of end time. Sorting by start time fails when an early-starting activity has a massive duration, blocking many shorter activities.
- Forgetting to pair the start and end times together before sorting.
- Mishandling edge cases where `start[i] == currentEnd`. Clarify if contiguous activities are allowed (usually yes).
</Warning>
