# Theory & Concepts
When dealing with arrays that contain duplicates, a standard binary search will return *any* index where the target is found. However, many problems require finding the very first or very last occurrence of a target. This leads us to the concepts of Lower Bound and Upper Bound.

### First Occurrence (Lower Bound Concept)
To find the first occurrence, we use binary search. When we find the target (`arr[mid] == target`), we record the index but we **do not stop**. Instead, we continue searching in the left half (`right = mid - 1`) because there might be earlier occurrences.

### Last Occurrence
Similarly, to find the last occurrence, when we find the target, we record the index and continue searching in the right half (`left = mid + 1`) because there might be later occurrences.

This modification ensures we push the boundaries of our search space to exactly the edges of the duplicated elements block.

# Common Pitfalls
<Warning>
- Stopping the search immediately upon finding `arr[mid] == target`. You must continue to shrink the search space to find the extreme bounds.
- Doing a linear scan left and right after finding the target. While it finds the bounds, it destroys the `O(log N)` complexity, turning it into `O(N)` in the worst case (if all elements are duplicates).
</Warning>
