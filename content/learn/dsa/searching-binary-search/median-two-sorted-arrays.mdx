# Theory & Concepts
Finding the median of two sorted arrays in `O(log(min(N, M)))` time is widely considered one of the hardest Binary Search problems. 

### What is a Median?
In a sorted array, the median divides the array into two equal halves. 
- Left half contains elements strictly smaller than or equal to the right half.
- If the total length is odd, the median is the center element.
- If the total length is even, the median is the average of the two center elements.

### The Binary Search Partition Logic
If we merge the two arrays into one, it would have a total of `N + M` elements. The left half of this merged array would have exactly `(N + M + 1) / 2` elements.
Instead of actually merging them (which takes `O(N+M)` time), we can guess how many elements from `Array1` should be in the left half of the merged array.
Let's call this cut `cut1`. If we take `cut1` elements from `Array1`, we MUST take `cut2 = (N + M + 1) / 2 - cut1` elements from `Array2`.

Now we have 4 edge elements to look at:
- `left1`: The largest element taken from `Array1`
- `right1`: The smallest element NOT taken from `Array1`
- `left2`: The largest element taken from `Array2`
- `right2`: The smallest element NOT taken from `Array2`

A partition is PERFECT if:
`left1 <= right2` AND `left2 <= right1`.
If `left1 > right2`, our `cut1` is too far to the right, we must move it left.
If `left2 > right1`, our `cut1` is too far to the left, we must move it right.

# Common Pitfalls
<Warning>
- **Not swapping the arrays:** If you don't ensure `nums1` is the smaller array, `cut2` can become negative, leading to Out of Bounds errors.
- **Handling Out of Bounds:** When `cut1 == 0`, it means we took 0 elements from `nums1` for the left half. We must simulate `left1` as `-INFINITY` so it doesn't break the `left1 <= right2` condition. Missing these `INT_MIN` / `INT_MAX` fallback values guarantees a crash.
</Warning>
