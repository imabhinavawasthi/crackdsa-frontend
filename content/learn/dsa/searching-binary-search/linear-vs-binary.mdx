# Theory & Concepts
Understanding the difference between Linear Search and Binary Search is crucial for any programmer. The choice between these two algorithms dictates how effectively your code will scale with larger datasets.

### Linear Search
Linear search involves scanning an array sequentially from start to finish. It is straightforward and requires no prerequisites on the data (like sorting). However, its linear time complexity means it scales poorly. If you have 1 million elements, you might need to make 1 million comparisons.

### Binary Search
Binary search uses a divide-and-conquer strategy. It requires the data to be sorted (or to have a monotonic property). By comparing the middle element of the search space with the target, it eliminates half of the search space in a single step. For 1 million elements, binary search needs at most 20 comparisons.

### Key Differences
- **Prerequisites:** Linear search works on any collection. Binary search strictly requires sorted or monotonic data.
- **Data Structures:** Linear search works well on linked lists. Binary search requires random access, making it suitable for arrays but highly inefficient for linked lists.
- **Time Complexity:** Linear search is `O(N)`. Binary search is `O(log N)`.

        while(left <= right) {

            if(arr[mid] == target) return mid;
            if(arr[mid] < target) left = mid + 1;
            else right = mid - 1;
        }
        return -1;
    }

# Common Pitfalls
<Warning>
- Applying Binary Search to an unsorted array, which yields completely incorrect results.
- Over-optimizing small arrays: For tiny datasets (e.g., n < 10), linear search can sometimes be faster in practice due to better cache locality and no branch misprediction penalties.
- Forgetting that sorting an array takes `O(N log N)`, so if you only need to search once, just use Linear Search.
</Warning>
