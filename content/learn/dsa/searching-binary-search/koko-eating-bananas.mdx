# Theory & Concepts
This is a classic "Binary Search on Answer" problem. Koko loves to eat bananas. There are `n` piles of bananas, and the `i-th` pile has `piles[i]` bananas. The guards have gone and will come back in `h` hours. Koko can decide her bananas-per-hour eating speed `k`. We need to find the **minimum** integer `k` such that she can eat all the bananas within `h` hours.

### The Monotonic Property
If Koko can eat all bananas at speed `k`, she can definitely eat them at any speed `> k`. 
If she cannot eat them at speed `k`, she definitely cannot eat them at any speed `< k`.
This monotonic behavior (False, False, ..., True, True) is the perfect signal to use Binary Search on the speed `k`.

### Search Space
- **Minimum speed (`low`)**: `1` banana per hour. (She has to eat at least something).
- **Maximum speed (`high`)**: The maximum number of bananas in a single pile. (Eating faster than the largest pile doesn't save any time, because she can only eat from one pile per hour anyway).

### The Validation Function
For a proposed speed `mid`, we calculate the total hours required. For each pile, the hours needed is `ceil(pile / mid)`. If the `total_hours <= h`, this speed is valid.

# Common Pitfalls
<Warning>
- **Integer Overflow in Hours Calculation:** The total hours accumulated across all piles can easily exceed the 32-bit integer limit if the piles are large and the speed is small. Always use a `long long` (C++) or `long` (Java) for the `hours` accumulator.
- **Ceiling Division Logic:** Doing `ceil(p / speed)` using floating-point math can introduce precision errors or be slower. Use integer math `(p + speed - 1) / speed` in C++ and Java.
</Warning>
