# Theory & Concepts
This problem asks us to split an array into `k` contiguous sub-arrays such that the **largest sum among these sub-arrays is minimized**. 
This is the textbook definition of a "Minimize the Maximum" problem, making it a perfect candidate for Binary Search on the Answer Space.

### Search Space
Instead of trying all combinations of splits (which is `O(2^N)` or `O(N^2)` with DP), we guess the answer! We binary search for the *maximum allowed sum for any single sub-array*.
- **Minimum possible answer (`low`)**: The largest single element in the array. Why? Because even if we split the array such that every element is its own sub-array, the largest sum will be the maximum element.
- **Maximum possible answer (`high`)**: The sum of all elements in the array. Why? Because if `k=1`, we don't split the array at all, and the largest sum is simply the total sum.

### The Validation Function
For a guessed max sum `mid`, we greedily add elements to a sub-array. If adding the next element exceeds `mid`, we are forced to close the current sub-array and start a new one. At the end, we count how many sub-arrays we created. 
- If `subarrays <= k`, it means `mid` was generous enough, and we might be able to squeeze the max sum even lower.
- If `subarrays > k`, it means `mid` was too restrictive, forcing us to make too many splits. We must increase `mid`.

        int maxElement = 0;

            totalSum += num;

        long long ans = right;

# Common Pitfalls
<Warning>
- Initializing `left = 0`. If `left` is 0 and you check `mid=0`, the validation function will fail if there are any non-zero elements, but conceptually it's wrong because the max sum must be AT LEAST the largest single element in the array.
- Initializing `subarrays = 0` inside the validation function. Before any iteration begins, you are essentially filling the 1st sub-array, so it must start at `1`.
</Warning>
