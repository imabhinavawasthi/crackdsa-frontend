# Theory & Concepts
Finding the minimum element in a rotated sorted array is a variation of binary search where we don't have a specific `target` value to look for. Instead, we are looking for the "inflection point"—the exact place where the rotation happened.

### Core Intuition
In a perfectly sorted array without rotation, the first element is the minimum. When rotated, the minimum element gets pushed somewhere inside the array.
The key property to exploit is comparing the middle element with the rightmost element:
1. If `arr[mid] > arr[right]`: The minimum MUST be in the right half. Why? Because in a normal sorted array, mid is always less than right. If mid is greater, it means the large elements have wrapped around, and the "cliff" (the minimum element) lies to the right.
2. If `arr[mid] <= arr[right]`: The right half is properly sorted. This means the minimum is either at `mid` or somewhere in the left half.

By following this logic, we can always shrink our search space by half.

# Code Implementation
<CodeBlock
  cpp="class Solution {
public:
    int findMin(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;
        
        while (left < right) { // Notice the strictly less than!
            int mid = left + (right - left) / 2;
            
            if (nums[mid] > nums[right]) {
                // The minimum is definitely in the right half, EXCLUDING mid
                left = mid + 1;
            } else {
                // The right half is sorted, the minimum is in the left half,
                // BUT it could BE mid itself, so we don't do mid - 1
                right = mid; 
            }
        }
        
        // At the end, left == right, pointing to the minimum element
        return nums[left];
    }
};"

# Common Pitfalls
<Warning>
- Using `while(left <= right)` and returning mid. This causes an infinite loop because `right = mid` does not aggressively shrink the bounds when `left == right`. Use `while(left < right)` instead.
- Setting `right = mid - 1`. If `nums[mid]` happens to be the absolute minimum, `mid - 1` completely skips over the right answer.
- Comparing `nums[mid]` to `nums[left]` instead of `nums[right]`. Comparing with the left pointer introduces nasty edge cases when the array is fully sorted (not rotated). Always compare with `right`.
</Warning>
