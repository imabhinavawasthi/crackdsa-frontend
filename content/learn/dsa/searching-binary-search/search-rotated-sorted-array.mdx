# Theory & Concepts
A Rotated Sorted Array is an array that was initially sorted in ascending order, but then shifted cyclically by some unknown number of positions. For example, `[0,1,2,4,5,6,7]` might become `[4,5,6,7,0,1,2]`.

The challenge is to find a target value in this array in O(log N) time. Standard binary search fails because the entire array isn't monotonically increasing.

### The "One Sorted Half" Rule
The beautiful property of a rotated sorted array is this: **if you pick any middle index, at least one half of the array (either left to mid, or mid to right) will ALWAYS be perfectly sorted.**

To solve this, we:
1. Find the mid-point.
2. Check which half is sorted.
3. Check if our target falls strictly within the bounds of the sorted half.
4. If it does, we binary search in that sorted half. If it doesn't, we know the target *must* be in the other, unsorted half.

                // Check if target is strictly within the sorted left half
                if (target >= nums[left] && target < nums[mid]) {
                    right = mid - 1; // Target is here

                    left = mid + 1;  // Target is in the other half
                }

                    left = mid + 1;  // Target is here
                } else {
                    right = mid - 1; // Target is in the other half
                }
            }
        }
        
        return -1;
    }

# Common Pitfalls
<Warning>
- Using `<` instead of `<=` when checking if the left half is sorted (`nums[left] <= nums[mid]`). If `left == mid`, it IS sorted (a single element), and failing to catch this leads to wrong logic.
- Misunderstanding the target bounds check. You must check `nums[left] <= target < nums[mid]`, not just `target < nums[mid]`.
- Forgetting that the array could potentially be un-rotated (a fully sorted array), which is just a special case handled perfectly by the `>=` checks.
</Warning>
