# Theory & Concepts
This problem is a quintessential "Binary Search on Answer Space" challenge. You are given an integer array `bloomDay` where `bloomDay[i]` is the day the `i-th` flower blooms. You need to make `m` bouquets, each consisting of exactly `k` **adjacent** flowers. We must find the minimum number of days required.

### The Monotonic Property
If you wait longer, more flowers bloom. If you can make `m` bouquets on day `X`, you can certainly make them on day `X+1`. 
Conversely, if you cannot make them on day `X`, you cannot make them on day `X-1`. 
This creates a clear monotonic boundary (False, False, ..., True, True). We binary search to find the very first `True`.

### Search Space
- **Minimum possible days (`low`)**: The minimum value in the `bloomDay` array. (No bouquet can be made before the first flower blooms).
- **Maximum possible days (`high`)**: The maximum value in the `bloomDay` array. (By this day, all flowers have bloomed).
- **Impossible Case**: If `m * k > n` (total flowers needed > total flowers available), it's impossible, return `-1`.

### The Validation Function
For a given day `mid`, iterate through the array. If `bloomDay[i] <= mid`, the flower has bloomed, so we increment a counter of adjacent bloomed flowers. If the counter reaches `k`, we successfully made one bouquet, increment our bouquet count, and reset the flower counter. If a flower hasn't bloomed, the adjacent chain is broken, so we reset the flower counter to 0.

# Common Pitfalls
<Warning>
- **Integer Overflow:** The impossible check `m * k > n` will easily overflow a 32-bit integer if `m` and `k` are large (e.g., both 10^5). Cast `m` to `long long` before multiplying.
- **Forgetting the adjacency rule:** You cannot sort the `bloomDay` array. The flowers must be picked in adjacent indices. Sorting destroys the sequence order required by the problem.
- **Not resetting the counter:** If an unbloomed flower is encountered, `adjacentFlowers` MUST be reset to 0 immediately.
</Warning>
