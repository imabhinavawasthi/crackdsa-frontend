# Theory & Concepts
Finding the K-th element of two sorted arrays is essentially the exact same problem as finding the Median of Two Sorted Arrays, but generalized. 
Instead of looking for the middle element, we are looking for the `k-th` element. 

### The Partition Logic
Just like the median problem, we want to split the two arrays such that exactly `k` elements exist in the left halves combined.
If we make a cut `cut1` in `Array1`, then `cut2` MUST be exactly `k - cut1`.

### Updating Search Space Bounds
Unlike the median problem where `cut1` can range from `0` to `N`, here `k` restricts our bounds!
- **Minimum `cut1` (`low`)**: If `k` is very large (larger than the entirety of `Array2`), we *must* take at least `k - M` elements from `Array1`. So `low = max(0, k - M)`.
- **Maximum `cut1` (`high`)**: We can never take more than `k` elements, nor can we take more than the total elements in `Array1`. So `high = min(N, k)`.

Once the bounds are set properly, the validation logic (`left1 <= right2` and `left2 <= right1`) remains exactly the same as the Median problem.

# Common Pitfalls
<Warning>
- **Setting bounds to `0` and `N`**: This is the most common mistake. If `k` is very large, say `k = N + M`, and you set `cut1 = 0`, then `cut2 = k - 0 = N + M`. But `Array2` only has `M` elements! This causes a massive Out of Bounds error. You MUST use `left = max(0, k - M)` and `right = min(N, k)`.
</Warning>
