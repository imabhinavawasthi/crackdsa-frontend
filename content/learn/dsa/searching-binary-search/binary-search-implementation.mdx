# Theory & Concepts
Binary search can be implemented in two distinct ways: Iteratively and Recursively. While both approaches achieve the same O(log N) time complexity, they differ significantly in terms of space complexity and practical implementation nuances.

### Iterative Implementation
The iterative approach uses a `while` loop to repeatedly halve the search space. It maintains `left` and `right` pointers and updates them until the target is found or `left > right`. This is generally preferred in technical interviews and production code because it avoids the overhead of function calls and requires only `O(1)` auxiliary space.

### Recursive Implementation
The recursive approach defines a function that calls itself on either the left or right half of the array. The base cases are when the target is found, or when `left > right` (signifying the target is not in the array). While sometimes considered more elegant and closer to the mathematical definition of divide-and-conquer, it inherently uses `O(log N)` space due to the call stack.

# Common Pitfalls
<Warning>
- In the recursive implementation, forgetting to return the recursive call (`return helper(...)`). This leads to undefined behavior or returning void/null.
- Missing the base case `if (left > right)` in recursion, which causes a StackOverflow error.
- Writing `mid = (left + right) / 2` causing integer overflow on large datasets.
</Warning>
