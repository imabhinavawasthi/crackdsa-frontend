# Theory & Concepts
Searching in a 2D matrix that possesses sorted properties is a classic application of binary search. The most common variation of this problem defines the matrix as follows:
1. Each row is sorted in non-decreasing order.
2. The first integer of each row is greater than the last integer of the previous row.

### Core Intuition
If you look closely at these two properties, they imply that if you were to flatten this 2D matrix into a 1D array, it would be perfectly sorted. 
However, flattening it would take `O(M * N)` time and `O(M * N)` space, defeating the purpose of an efficient search.

Instead of actually flattening it, we can virtually treat the 2D matrix as a 1D array. 
For a matrix of size `M x N`:
- The 1D array length is `M * N`.
- Valid indices range from `0` to `(M * N) - 1`.
- A 1D index `idx` can be mapped back to a 2D coordinate `(row, col)` using division and modulo operations:
  - `row = idx / N` (where N is the number of columns)
  - `col = idx % N`

With this mapping, we can perform a standard binary search exactly as we would on a 1D array.

public:
    bool searchMatrix(vector<vector<int>>& matrix, int target) {
        if (matrix.empty() || matrix[0].empty()) return false;
        
        int m = matrix.size();
        int n = matrix[0].size();
        
        // Treat as a 1D array from 0 to m*n - 1
        int left = 0;
        int right = m * n - 1;
        
        while (left <= right) {
            int mid = left + (right - left) / 2;
            
            // Map 1D index 'mid' to 2D coordinates
            int row = mid / n;
            int col = mid % n;
            int midValue = matrix[row][col];
            
            if (midValue == target) {
                return true;
            } else if (midValue < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        
        return false;
    }
};"

# Common Pitfalls
<Warning>
- Using `idx / m` instead of `idx / n`. The division and modulo must ALWAYS be by the number of COLUMNS (`n`), because that determines when the 1D array wraps around to the next row.
- Not handling edge cases where the matrix is completely empty `[]` or contains empty rows `[[]]`. Always do a sanity check at the start.
- Integer overflow: If `m * n` is incredibly large, `right` could overflow a standard 32-bit integer.
</Warning>
