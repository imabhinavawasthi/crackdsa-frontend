# Theory & Concepts
Most people learn Binary Search as a tool to find a target value inside a sorted array. However, its true power in competitive programming and top-tier interviews lies in the **"Binary Search on Answer"** pattern.

Instead of searching over given indices, we search over the *possible range of answers*. 

### When to use this pattern?
You should immediately think of this pattern when a problem asks you to:
1. Find the **minimum** value that satisfies a certain condition.
2. Find the **maximum** value that satisfies a certain condition.
3. Optimize a value (e.g., "Minimize the Maximum", "Maximize the Minimum").

### How it works
1. **Define the Search Space:** Identify the absolute minimum possible answer (`low`) and the absolute maximum possible answer (`high`).
2. **The Verification Function:** Create a helper function `isValid(mid)` that returns `true` or `false`. This function checks if a proposed answer `mid` is possible according to the problem constraints.
3. **The Monotonic Property:** The answer space MUST be monotonic. For example, if `mid` is valid, all numbers greater than `mid` must also be valid (or vice versa). This allows us to eliminate half of the search space.

# Common Pitfalls
<Warning>
- Defining the search space incorrectly. If `high` is too small, the true answer might never be checked. If `low` is too large, the same applies. Always be pessimistic and set `high` to the absolute theoretical maximum.
- Over-complicating the `isValid` function. This function should just simulate the process greedily assuming `mid` is the answer.
- Returning `left` or `right` at the end instead of using a dedicated `ans` variable. Using `ans` is much safer and easier to reason about.
</Warning>
