# Theory & Concepts
In C++ STL, `lower_bound` and `upper_bound` are highly optimized binary search functions. However, knowing how to implement them from scratch is essential because many algorithmic problems require you to apply this exact logic without relying on built-in libraries.

### Lower Bound
The **lower bound** of a `target` is defined as the first element in a sorted array that is **greater than or equal to** (`>=`) the target. 
If all elements are smaller than the target, the lower bound is typically considered to be the size of the array (out of bounds).

### Upper Bound
The **upper bound** of a `target` is defined as the first element in a sorted array that is **strictly greater than** (`>`) the target.
Just like lower bound, if no such element exists, it returns the size of the array.

These concepts are incredibly powerful. For example, to find the number of elements equal to `target`, you can simply compute `upper_bound(target) - lower_bound(target)`.

# Common Pitfalls
<Warning>
- Confusing the conditions: Lower bound uses `>=` while upper bound uses `>`.
- Initializing `ans` to `-1` instead of `array.size()`. If all elements are smaller than the target, the correct bound is conceptually at index `N`, not `-1`.
- Forgetting to shrink the right side when you find a valid condition. You must keep searching leftward to find the *first* occurrence.
</Warning>
