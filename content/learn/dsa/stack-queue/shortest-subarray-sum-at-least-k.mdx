# Theory & Concepts

**Shortest Subarray with Sum at Least K** is one of the most notoriously difficult problems on LeetCode. It combines Prefix Sums with a Monotonic Deque.

**Why not standard Sliding Window?**
Standard sliding window (two pointers) only works if all numbers are positive, because adding a number strictly increases the sum. If there are negative numbers, expanding the window might decrease the sum, breaking the monotonic property required for a standard two-pointer approach.

**Intuition**
1. We compute the **Prefix Sum** array. The sum of a subarray from index `i` to `j` is `prefix[j] - prefix[i]`. We want `prefix[j] - prefix[i] >= K`, which rearranges to `prefix[j] - K >= prefix[i]`.
2. As we iterate through `prefix[j]`, we want to find the largest index `i` (to make the subarray shortest) that satisfies the condition.
3. We use a **Monotonic Increasing Deque** to store the indices of the prefix sums.
   - **Optimization 1 (Shortest Subarray):** If `prefix[j] - prefix[dq.front()] >= K`, we found a valid subarray! Since we want the shortest one, we record the length `j - dq.front()` and pop `dq.front()`. We will never need this `dq.front()` again because any future `j` will result in a longer subarray.
   - **Optimization 2 (Monotonicity):** Before pushing `j`, we pop all elements from the back of the deque where `prefix[dq.back()] >= prefix[j]`. Why? Because `prefix[j]` is smaller AND comes later. It is objectively better for future calculations than `prefix[dq.back()]`.

# Common Pitfalls

<Warning>
- **Integer Overflow:** The sum of elements can easily exceed the 32-bit integer limit. Always use 64-bit integers (`long long` in C++, `long` in Java) for the Prefix Sum array.
- **Forgetting Prefix[0]:** Your prefix array must have a size of `N + 1` with `prefix[0] = 0`. This is necessary to evaluate subarrays that start from the very first index `nums[0]`.
</Warning>
