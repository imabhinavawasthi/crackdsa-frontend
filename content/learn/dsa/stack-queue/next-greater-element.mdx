# Theory & Concepts

The **Next Greater Element** problems evaluate your ability to apply a Monotonic Stack to arrays, and then extend that logic to *circular arrays*.

**Next Greater Element I**
You are given two arrays, `nums1` and `nums2`, where `nums1` is a subset of `nums2`. For each element in `nums1`, find the next greater element in `nums2`. 
*Solution:* We can find the next greater element for *all* elements in `nums2` using a Monotonic Decreasing Stack and store the results in a Hash Map. Then, we just iterate through `nums1` and look up the answer in O(1) time per element.

**Next Greater Element II (Circular Array)**
You are given a circular array (the next element of the last element is the first element). Find the next greater element for every element.
*Solution:* Since the array is circular, we can simulate traveling around it by looping through the array twice (length `2 * n`). We use the modulo operator `i % n` to wrap around. The Monotonic Stack logic remains exactly the same!

# Common Pitfalls

<Warning>
- **Pushing indices in the second pass:** In a circular array, you only need to *resolve* pending items during the second pass. If you push indices onto the stack during the second pass, you are doing unnecessary work and could potentially overwrite valid results if you aren't careful.
- **Not using Modulo:** Forgetting to use `i % n` when accessing the array will lead to an `IndexOutOfBounds` exception.
</Warning>
