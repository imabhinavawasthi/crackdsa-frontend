# Theory & Concepts

Implementing a Stack using Queues (or a Queue using Stacks) is a classic interview question that tests your deep understanding of how LIFO and FIFO properties operate fundamentally. 

**Implementing a Queue using Stacks**
A queue is FIFO, but a stack is LIFO. To simulate FIFO behavior with Stacks, we need two stacks: an `input_stack` and an `output_stack`. 
When enqueuing elements, we push them onto the `input_stack`. When dequeuing or peeking, we need the oldest element. If `output_stack` is empty, we pop everything from `input_stack` and push it onto `output_stack`. This reverses the order, placing the oldest element at the top of the `output_stack`, ready for O(1) removal.

**Implementing a Stack using Queues**
To simulate LIFO using queues, we can use a single queue. Every time we push an element, we enqueue it to the back. To make it behave like a stack (where the newest element is at the front), we immediately dequeue all previously existing elements in the queue and re-enqueue them behind the newly added element.

# Common Pitfalls

<Warning>
- **Transferring Elements Unnecessarily:** A common mistake is to transfer elements back and forth between the two stacks for every push/pop. This destroys amortized O(1) time and results in O(N) per operation. Only transfer from `input` to `output` when `output` is completely empty.
- **Forgetting Amortized Cost:** In interviews, candidates often state pop() is strictly O(N). Remember to explain the concept of *amortized time* complexity to show a deeper understanding.
</Warning>
