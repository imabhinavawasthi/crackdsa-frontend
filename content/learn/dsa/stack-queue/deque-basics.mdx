# Theory & Concepts

Building upon the basics of Deques, the most advanced use-case for a Deque is the **Monotonic Deque**. Just as a Monotonic Stack maintains elements in a sorted order to find the "next greater" element, a Monotonic Deque maintains a sorted order of elements to find the "maximum or minimum" element in a moving sliding window.

When we combine the O(1) front/back removal capabilities of a Deque with monotonicity, we can dynamically add new elements to our window, remove old elements that fall out of the window, and constantly know the max/min of the window simply by looking at the front of the Deque!

**How a Monotonic Decreasing Deque Works:**
1. **Adding Elements:** We add elements to the back. But before adding, we must maintain the decreasing order. If the new element is larger than the elements at the back, those back elements are useless (they are smaller and older, so they will never be the maximum!). We pop them from the back.
2. **Removing Elements:** If the element at the front of the Deque (the maximum) has "expired" (its index is no longer inside our sliding window), we pop it from the front.

from collections import deque

class MonotonicDeque:
    def __init__(self):
        self.dq = deque() # stores indices
        
    def push(self, nums: list[int], i: int):
        while self.dq and nums[self.dq[-1]] <= nums[i]:

        self.dq.append(i)

# Common Pitfalls

<Warning>
- **Storing Values Instead of Indices:** A Monotonic Deque must store indices! If you store values, you have no way to know if the maximum value at the front of the Deque has expired and needs to be popped out of the sliding window.
- **Popping the Wrong End:** When maintaining monotonicity, pop from the `back`. When removing expired elements, pop from the `front`. Mixing these up will completely break the logic.
</Warning>
