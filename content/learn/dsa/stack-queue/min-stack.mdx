# Theory & Concepts

Designing a **Min Stack** is a classic problem that tests your ability to augment a standard data structure to answer queries efficiently. The goal is to design a stack that supports `push`, `pop`, `top`, and retrieving the minimum element (`getMin`)—all in **O(1) time**.

**Intuition**
A standard stack easily supports `push`, `pop`, and `top` in O(1) time. But finding the minimum element normally takes O(N) time because we would have to scan all elements. To make it O(1), we can trade space for time.

We maintain an auxiliary stack (or store pairs in a single stack) that keeps track of the minimum value at each level of the stack. Whenever we push a new element `x`, the new minimum for this level is simply `min(x, current_minimum)`. When we pop an element, we also pop from our minimum tracker, naturally restoring the previous minimum!

  python="class MinStack:
    def __init__(self):
        # We will store tuples of (value, min_so_far)
        self.stack = []

    def push(self, val: int) -> None:
        if not self.stack:
            self.stack.append((val, val))
        else:
            current_min = self.stack[-1][1]
            self.stack.append((val, min(val, current_min)))

    def pop(self) -> None:
        self.stack.pop()

    def top(self) -> int:
        return self.stack[-1][0]

    def getMin(self) -> int:
        return self.stack[-1][1]"

# Common Pitfalls

<Warning>
- **Using a single variable to track the minimum:** This fails when the minimum element is popped off the stack, because you lose track of what the *previous* minimum was.
- **Forgetting to update the min stack during pops:** If you use two separate stacks, a common bug is popping from the main stack but forgetting to pop from the min stack if the values match. Storing pairs is less error-prone.
</Warning>
