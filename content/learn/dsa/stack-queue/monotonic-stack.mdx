# Theory & Concepts

A **Monotonic Stack** is simply a stack whose elements are strictly increasing or strictly decreasing. It is not a new data structure, but rather a specific *way* of using a stack.

Why is this useful? By enforcing monotonicity, the stack automatically keeps track of the "next greater" or "next smaller" elements for any given item in an array in **O(N)** time instead of O(N²).

**Two Types of Monotonic Stacks:**
1. **Monotonic Increasing Stack:** Elements from the bottom to the top of the stack are strictly increasing. If a new element is smaller than the top of the stack, we pop the top until the stack is increasing again. This is used to find the **Next Smaller Element**.
2. **Monotonic Decreasing Stack:** Elements from the bottom to the top are strictly decreasing. If a new element is larger than the top of the stack, we pop until the stack is decreasing again. This is used to find the **Next Greater Element**.

# Common Pitfalls

<Warning>
- **Storing Values Instead of Indices:** It is almost always better to store the *indices* of the array in the stack rather than the values themselves. Storing indices gives you access to both the value (via `arr[index]`) and the position (which is needed to calculate distances or update a result array).
- **Infinite Loops:** Forgetting to pop elements inside the while loop will cause an infinite loop. Always ensure the condition that breaks the loop is eventually met by popping.
</Warning>
