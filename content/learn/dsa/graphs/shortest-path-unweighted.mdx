# Theory & Concepts
Finding the shortest path from a source node to all other nodes is a fundamental graph problem. When dealing with an **undirected graph with unit weights** (meaning every edge has a weight of 1), the optimal approach is to use **Breadth-First Search (BFS)**.

Unlike Dijkstra's algorithm, which requires a priority queue and `O((V + E) log V)` time, BFS on an unweighted graph achieves this in simple linear time `O(V + E)`.

### Core Intuition
- BFS explores nodes level by level, radiating outwards from the source.
- Because all edges have a weight of 1, the first time you reach a node during a BFS traversal, you are guaranteed to have found the shortest path to it.
- We maintain a `dist` array, initialized to infinity, to store the shortest distance from the source to every node.
- Start by setting `dist[source] = 0` and push the source into the queue.
- Pop a node, iterate through its neighbors. If `dist[neighbor]` is greater than `dist[current_node] + 1`, update `dist[neighbor]` and push the neighbor into the queue.

# Common Pitfalls
<Warning>
- **Using DFS:** A very common mistake is attempting to use DFS to find the shortest path in an unweighted graph. DFS does not guarantee the shortest path; BFS does.
- **Forgetting unreachable nodes:** Always remember to map the default infinity value back to `-1` (or whatever the problem specifies) for nodes that cannot be reached from the source.
</Warning>
