# Theory & Concepts
A **Bipartite Graph** is a graph whose vertices can be divided into two disjoint sets such that every edge connects a vertex in one set to a vertex in the other set. 

Alternatively, a graph is bipartite if it can be colored using exactly **2 colors** such that no two adjacent vertices have the same color.

### Key Intuitions
- Any graph with NO cycles is automatically bipartite.
- Any graph with an **even-length cycle** is bipartite.
- A graph with an **odd-length cycle** is **NOT bipartite**.

Using BFS, we can try to "color" the graph level by level. We start by assigning color `0` to a node, then color `1` to all its neighbors, then color `0` to their neighbors, and so on. If we ever find an adjacent node that is already colored with the *same color* as the current node, the graph is not bipartite.

    queue<int> q;
    q.push(start);
    color[start] = 0; // Assign first color
    
    while (!q.empty()) {
        int node = q.front();
        q.pop();
        
        for (int neighbor : adj[node]) {
            // If uncolored, color with opposite color and enqueue
            if (color[neighbor] == -1) {
                color[neighbor] = !color[node];
                q.push(neighbor);
            } 
            // If colored with the SAME color, it's not bipartite!
            else if (color[neighbor] == color[node]) {
                return false;
            }
        }
    }
    return true;
}

# Common Pitfalls
<Warning>
- Using a `visited` boolean array AND a `color` array. You only need the `color` array! Initialize it with `-1` (uncolored) and check if it's `-1` to see if it's visited.
- Forgetting to handle disconnected components with a `for` loop over all vertices.
</Warning>
