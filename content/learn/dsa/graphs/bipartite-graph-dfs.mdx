# Theory & Concepts
A **Bipartite Graph** is a graph whose vertices can be divided into two disjoint sets such that every edge connects a vertex in one set to a vertex in the other set. A common way to check if a graph is bipartite is to try to color it using two colors such that no two adjacent vertices have the same color. 

If we can successfully color the graph with 2 colors, it is a bipartite graph. If we encounter a node that is already colored with the same color as its adjacent node, the graph is not bipartite. An interesting property of a bipartite graph is that **it cannot contain an odd-length cycle**.

Using **Depth First Search (DFS)**, we can recursively traverse the graph, passing the expected color to adjacent nodes. We use an array to keep track of the colors. 

### Core Intuition
- Start from an uncolored node, color it with `0`.
- Traverse its neighbors using DFS. If a neighbor is uncolored, color it with the opposite color (`1 - current_color`) and recursively call DFS.
- If a neighbor is already colored and has the **same color** as the current node, the graph is not bipartite.
- Since the graph can be disconnected, ensure you check all components by iterating through all nodes.

# Common Pitfalls
<Warning>
- **Disconnected Graphs:** Do not assume the graph is connected. Always iterate through all vertices to handle disconnected components.
- **Cycle lengths:** Remember that graphs with even-length cycles CAN be bipartite, but graphs with odd-length cycles can NEVER be bipartite.
</Warning>
