# Theory & Concepts
The **Word Ladder** problems are classic interview questions that require you to find the shortest transformation sequence from a `beginWord` to an `endWord`. 
- **Rule 1:** Only one letter can be changed at a time.
- **Rule 2:** Each transformed word must exist in the given `wordList`.

Since we want the *shortest* path in a scenario where every transformation costs 1 step (unweighted), **Breadth-First Search (BFS)** is the perfect tool.

### Core Intuition (Word Ladder I)
- Instead of building a massive explicit graph (which is too slow), we generate neighbors dynamically.
- Store the `wordList` in an unordered set (hash set) for `O(1)` lookups.
- Push the `beginWord` into a queue alongside its current step count (initially 1).
- Pop a word, and for every character in the word, replace it with letters from 'a' to 'z'.
- If the new generated word exists in the set, it's a valid neighbor! Remove it from the set (to prevent cycles and mark as visited) and push it into the queue.

                        st.erase(word);
                        q.push({word, steps + 1});
                    }
                }
                word[i] = original; // Backtrack
            }
        }
        return 0;
    }

        Queue<Pair> q = new LinkedList<>();
        
        q.add(new Pair(beginWord, 1));
        st.remove(beginWord);

            Pair curr = q.poll();
            String word = curr.word;
            int steps = curr.steps;
            
            if (word.equals(endWord)) return steps;
            
            for (int i = 0; i < word.length(); i++) {
                char[] replacedWordArray = word.toCharArray();
                for (char ch = 'a'; ch <= 'z'; ch++) {
                    replacedWordArray[i] = ch;
                    String replacedWord = new String(replacedWordArray);
                    
                    if (st.contains(replacedWord)) {
                        st.remove(replacedWord);
                        q.add(new Pair(replacedWord, steps + 1));
                    }
                }
            }
        }
        return 0;
    }

# Common Pitfalls
<Warning>
- **Removing from Set:** Not erasing the word from the set after pushing it to the queue will lead to infinite loops (cycles) and TLE errors.
- **Explicit Graph Construction:** Trying to build an explicit adjacency list for all words will result in an O(N^2 * M) time limit exceeded error for large inputs.
</Warning>
