# Theory & Concepts
Detecting a cycle in an undirected graph can be efficiently done using Breadth First Search (BFS). 

A cycle exists if, during our traversal, we encounter a node that has already been visited, and that node is **not the parent** (the node from which we just arrived).

### Intuition
When traversing an undirected graph, reaching an already-visited node means there's an alternative path to it. Since the graph is undirected, every edge `u-v` implies we can go from `u` to `v` and `v` to `u`. Thus, if we are at `v` (having come from `u`), `u` will naturally be marked as visited. This is a trivial "back-and-forth" and does not constitute a cycle. However, if we see a visited neighbor `w` that is NOT `u`, we've found a cycle!

To implement this with BFS, we store pairs of `(current_node, parent_node)` in the queue.

def detect_cycle_bfs(start, adj, visited):
    # Queue stores (node, parent)
    queue = deque([(start, -1)])
    visited[start] = True
    
    while queue:
        node, parent = queue.popleft()

            if not visited[neighbor]:
                visited[neighbor] = True
                queue.append((neighbor, node))

# Common Pitfalls
<Warning>
- Forgetting to pass the parent information into the queue.
- Confusing the directed cycle detection logic (which requires a `recursion_stack` or visited states like 0/1/2) with this undirected logic (which just needs a `parent` check).
</Warning>
