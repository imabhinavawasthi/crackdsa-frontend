# Theory & Concepts
An **Adjacency List** represents a graph as an array (or map) of lists. Each index `i` in the array corresponds to a vertex, and the list at `adj[i]` contains all of `i`'s neighbors.

For a weighted graph, the list contains pairs or objects holding both the neighbor vertex and the edge weight.

### Pros and Cons
**Pros:**
- Extremely memory-efficient for sparse graphs: requires `O(V + E)` space.
- Traversing all neighbors of a specific vertex `u` is fast: `O(degree(u))`.

**Cons:**
- Checking if an edge exists between `u` and `v` takes `O(degree(u))` time instead of `O(1)`.
- Slightly more overhead due to pointers/references in dynamic arrays or linked lists.

class Edge {
    int to, weight;
    Edge(int to, int weight) {
        this.to = to;
        this.weight = weight;

class AdjacencyList {
    int V;
    List<List<Edge>> adj;

    public AdjacencyList(int V) {
        this.V = V;
        adj = new ArrayList<>();
        for (int i = 0; i < V; i++) {
            adj.add(new ArrayList<>());
        }
    }

    public void addEdge(int u, int v, int weight, boolean directed) {

        if (!directed) {
            adj.get(v).add(new Edge(u, weight));
        }
    }

# Common Pitfalls
<Warning>
- In languages like C++, `vector<vector<int>>` can be slow if not initialized properly due to frequent reallocation. Use `.reserve()` if possible.
- When an edge is removed from an undirected graph, it must be removed from both `adj[u]` and `adj[v]`.
</Warning>
