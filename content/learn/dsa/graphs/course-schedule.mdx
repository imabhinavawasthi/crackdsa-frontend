# Theory & Concepts
The **Course Schedule** problems (often found on LeetCode as Course Schedule I and II) are the canonical applications of Topological Sorting.

You are given a total of `numCourses` and a list of `prerequisites` where `prerequisites[i] = [a, b]` indicates that you must take course `b` first if you want to take course `a`. 
- **Course Schedule I** asks: *Is it possible to finish all courses?* (Cycle Detection).
- **Course Schedule II** asks: *Return the ordering of courses you should take to finish all courses.* (Topological Sort).

### Core Intuition
We can model this as a **Directed Graph**:
- Each course is a node.
- A prerequisite relation `[a, b]` means course `b` must be completed before course `a`. We represent this as a directed edge: `b -> a`.
- If there is a cycle in this graph (e.g., `A` requires `B`, and `B` requires `A`), it is impossible to finish the courses.
- If it is a Directed Acyclic Graph (DAG), we can find an order to take the courses using Topological Sorting.

Kahn's Algorithm (BFS) is perfect here because it handles both cycle detection and topological sorting simultaneously.

# Common Pitfalls
<Warning>
- **Edge Direction:** A common mistake is building the edge backwards (`course -> prerequisite`). It MUST be `prerequisite -> course` so you can take the prerequisite first (in-degree 0).
- **Graph Construction:** The input is usually an edge list. You must manually construct the Adjacency List first.
</Warning>
