# Theory & Concepts
The **Dutch National Flag Algorithm** was proposed by Edsger Dijkstra to solve the problem of sorting an array consisting of three distinct elements (often represented as 0s, 1s, and 2s, or Red, White, and Blue—the colors of the Dutch flag). 

While you could simply sort the array using a standard $O(N \log N)$ algorithm, or count the occurrences of 0s, 1s, and 2s in a first pass and then overwrite the array in a second pass ($O(N)$ time, but two passes), Dijkstra's algorithm solves it in a **single pass** ($O(N)$ time) and strictly $O(1)$ space.

### The Core Intuition
The algorithm uses three pointers: `low`, `mid`, and `high`. These pointers dynamically partition the array into four regions during iteration:
1. `[0, low - 1]` contains all `0`s.
2. `[low, mid - 1]` contains all `1`s.
3. `[mid, high]` contains unexamined elements.
4. `[high + 1, N - 1]` contains all `2`s.

Initially, `low` and `mid` start at index `0`, and `high` starts at index `N - 1`. The `mid` pointer acts as our active iterator:
- If `nums[mid] == 0`: We swap `nums[mid]` with `nums[low]`. Since we know `nums[low]` was a `1` (or `mid` and `low` were pointing to the same `0`), we can safely increment both `low` and `mid`.
- If `nums[mid] == 1`: The element is already in the correct middle section. We just increment `mid`.
- If `nums[mid] == 2`: We swap `nums[mid]` with `nums[high]`. We decrement `high`. **Crucially, we do not increment `mid`** because the new element swapped into the `mid` position from `high` has not been examined yet.

The loop terminates when `mid > high`, meaning the unexamined region is empty.

    void sortColors(vector<int>& nums) {
        int low = 0;
        int mid = 0;
        int high = nums.size() - 1;
        
        while (mid <= high) {
            if (nums[mid] == 0) {
                swap(nums[low], nums[mid]);
                low++;
                mid++;
            } 
            else if (nums[mid] == 1) {
                mid++;
            } 
            else { // nums[mid] == 2
                swap(nums[mid], nums[high]);
                high--;
                // Note: mid is NOT incremented here
            }
        }
    }

# Common Pitfalls
<Warning>
- **Incrementing `mid` when encountering a 2:** This is the most frequent bug. When you swap `nums[mid]` with `nums[high]`, the element coming from `high` into `mid` is completely unexamined. If you increment `mid`, you might skip processing a 0 or a 2.
- **Loop Condition:** The loop condition must be `while (mid <= high)`. If you use `while (mid < high)`, you will leave the element at `high` unexamined, which will break the algorithm if that element needs to be swapped.
</Warning>
