# Theory & Concepts
A **Frequency Array** (or Hash Array) is a powerful and elegant precomputation technique used to count the occurrences of elements within an array or string. It serves as a lightweight alternative to a Hash Map when the range of possible values is relatively small and contiguous (e.g., lowercase English letters, digits 0-9, or integers in a small range `[0, K]`).

### The Core Intuition
Instead of searching through an array repeatedly—which often requires $O(N)$ time per query—we can use the values themselves as **indices** of a secondary array (the Frequency Array). The value at `freq[i]` simply stores the count of how many times the element `i` appeared in the original dataset.

If we have an array `[1, 2, 2, 4]`, its frequency array of size 5 (indices 0 to 4) would look like:
- `freq[0] = 0`
- `freq[1] = 1`
- `freq[2] = 2`
- `freq[3] = 0`
- `freq[4] = 1`

By spending $O(N)$ time and $O(K)$ space to build this array, we enable instantaneous $O(1)$ lookups for the frequency of any element.

### When to use Frequency Arrays
- **Characters:** Counting letter occurrences in strings (e.g., anagrams, palindromes). An array of size 26 is perfect for lowercase English letters `freq[char - 'a']`.
- **Small Integers:** Counting elements when constraints show $A[i] \le 10^5$ or similar.
- **Sorting:** It forms the basis of **Counting Sort**, allowing us to sort elements in linear $O(N)$ time when the range is bounded.

# Common Pitfalls
<Warning>
- **Out of Bounds Errors:** The most common mistake. Always ensure your `freq` array size is `MAX_VAL + 1`. If elements go up to 100, your array must be of size 101 to safely access index 100.
- **Negative Numbers:** You cannot directly use negative numbers as indices in C++ or Java. You must use an offset (e.g., `freq[val + OFFSET]`) or switch to a Hash Map.
- **Memory Limit Exceeded:** Never use a Frequency Array if the maximum value is extremely large (e.g., $10^9$). Creating an array of $10^9$ integers will cause memory limits to exceed; use a Hash Map instead.
</Warning>
