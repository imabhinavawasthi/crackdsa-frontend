# Theory & Concepts
The primary limitation of a standard **Static Array** is its fixed size. When you declare an array of size 10, it can only ever hold 10 elements. If you need an 11th, you are out of luck.

### Dynamic Arrays
To solve this, languages provide **Dynamic Arrays** (`std::vector` in C++, `ArrayList` in Java, `list` in Python). A dynamic array resizes itself automatically as you add elements to it.

### How Resizing Works (Capacity vs Size)
A dynamic array manages two variables under the hood:
- **Size:** The number of elements currently stored by the user.
- **Capacity:** The actual amount of memory allocated behind the scenes.

When you push an element and `Size == Capacity`, the dynamic array:
1. Allocates a **brand new array** in memory with double the capacity (`2 * Capacity`).
2. Copies all existing elements from the old array to the new one.
3. Deallocates the old array.
4. Appends the new element.

This reallocation is a heavy $O(N)$ operation, but because we double the capacity, it happens infrequently. As a result, the **amortized (average) time complexity** of appending an element remains $O(1)$.

#include <iostream>
#include <vector>
using namespace std;

class Solution {
public:
    void demonstrateVector() {
        vector<int> arr;
        cout << "Initial Capacity: " << arr.capacity() << endl;
        
        for (int i = 0; i < 5; i++) {

            cout << "Size: " << arr.size()

        }
    }
};`}
  java={`// Java ArrayList (Dynamic Array) Demonstration
import java.util.ArrayList;

class Solution {
    public void demonstrateArrayList() {
        // Initial capacity is generally 10
        ArrayList<Integer> arr = new ArrayList<>();
        
        for (int i = 0; i < 5; i++) {
            arr.add(i);
            System.out.println("Size: " + arr.size());
            // Java doesn't expose capacity directly
        }
    }
}`}

# Common Pitfalls
<Warning>
- **Reallocation Overhead:** If you know exactly how many elements you will insert, dynamically resizing multiple times wastes CPU cycles.
- **Pointer Invalidation:** In C++, reallocating a vector changes its base memory address. Any iterators or pointers pointing to old elements instantly become invalid and will cause crashes.
</Warning>
