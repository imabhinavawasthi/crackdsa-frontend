# Theory & Concepts
The **Prefix Sum** technique is a powerful array precomputation pattern. It involves creating an auxiliary array where `prefix[i]` stores the cumulative sum of all elements from index `0` up to index `i` of the original array.

When dealing with multiple range sum queries—asking for the sum of elements between indices `L` and `R`—a brute force approach would require an $O(N)$ traversal per query. For $Q$ queries, this results in $O(Q \times N)$ time.

By spending $O(N)$ time upfront to build a prefix sum array, we can answer any range sum query in **constant $O(1)$ time**. The sum of any subarray from `L` to `R` is calculated using a simple subtraction:
$\text{Sum}(L, R) = \text{prefix}[R] - \text{prefix}[L - 1]$. (If $L=0$, the sum is just $\text{prefix}[R]$).

# Code Implementation
<CodeBlock
  cpp="class NumArray {
    vector<int> prefix;
public:
    NumArray(vector<int>& nums) {
        int n = nums.size();
        prefix.assign(n + 1, 0);
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }
    }
    
    int sumRange(int left, int right) {
        return prefix[right + 1] - prefix[left];
    }
};"

# Common Pitfalls
<Warning>
- **Index Out of Bounds:** When calculating `prefix[R] - prefix[L - 1]`, accessing index `-1` will crash your code in languages like C++ or Java. A common trick is to make the prefix array 1-indexed (size N+1) to avoid manual boundary checks.
- **Integer Overflow:** If the array contains very large numbers, the cumulative sums can easily exceed 32-bit integer limits. Always consider using 64-bit integers (`long long` in C++, `long` in Java) for the prefix array.
</Warning>
