# Theory & Concepts
The **Two Sum** problem asks us to find two numbers in an array that add up to a specific target value. The brute-force approach involves checking all pairs of numbers, which results in an $O(N^2)$ time complexity.

To optimize this to linear $O(N)$ time, we can use a **Hash Map** to store the numbers we've seen so far. As we iterate through the array, we calculate the `complement` (i.e., `target - current_number`). If the `complement` exists in our Hash Map, we have found our pair! If not, we store the `current_number` and its index in the Hash Map and continue.

Alternatively, if the input array is already **sorted**, we can use the **Two Pointers** technique to solve the problem in $O(N)$ time and $O(1)$ space. We place a pointer at the beginning and another at the end, and adjust them based on the sum of their elements compared to the target.

    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> numMap;

    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> numMap = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            if (numMap.containsKey(complement)) {

            }
            numMap.put(nums[i], i);
        }
        return new int[]{};
    }

# Common Pitfalls
<Warning>
- Initializing the hash map with all array elements beforehand can lead to using the same element twice. It's crucial to check for the complement and *then* add the current element to the map in a single pass.
- Using a naive nested loop setup where the inner loop starts at `0` instead of `i + 1` can cause you to sum an element with itself.
</Warning>
