# Theory & Concepts
The **Coin Change** problem family typically asks two questions:
1. **Coin Change I**: What is the *minimum number of coins* needed to make a specific amount?
2. **Coin Change II**: What is the *total number of combinations* to make a specific amount?

### Core Intuition
Both are variations of the Unbounded Knapsack pattern since you have an infinite supply of each coin denomination.
For **Coin Change I**, your state tracks the minimum coins. Transition: `dp[i] = min(dp[i], dp[i - coin] + 1)`.
For **Coin Change II**, your state tracks the total ways. Transition: `dp[i] += dp[i - coin]`.

Because items can be reused indefinitely, we iterate the inner loops forwards (from `coin` to `amount`), carrying over the impact of multiple uses of the same coin.

# Common Pitfalls
<Warning>
- In Coin Change II, swapping the loops (iterating amount first, then coins) calculates permutations instead of combinations, double-counting identical combinations in different orders.
- Initializing the DP array with `INT_MAX` for Coin Change I without accounting for overflow when adding `1`. Use `amount + 1` or a sufficiently large safe value.
</Warning>
