# Theory & Concepts
Welcome to the most important mental framework in Dynamic Programming: **State and Transition**. DP is not about memorizing solutions to 100 problems; it's about mastering a systematic way to model a problem. Once you learn how to properly define states and transitions, any unseen DP problem becomes highly solvable.

### Defining the State
A **state** is a set of variables that uniquely describe a specific subproblem. 
Think of it as taking a snapshot of your problem at a particular moment in time.

- **Example 1:** "What is the max profit from day `i` to day `n`?" -> The state is `i`.
- **Example 2:** "What is the max profit if we are at index `i`, with a knapsack of remaining capacity `c`?" -> The state is `(i, c)`.

If your state variables do not contain enough information to make a decision, you need another variable. If they contain useless information, your state is too bloated and your program will run out of memory.

### The Transition (Recurrence Relation)
The **transition** is the mathematical relationship between a current state and its sub-states. It tells you how to combine answers to smaller problems to answer the current one.

Ask yourself: *"If I am at state `dp(i)`, what choices do I have, and how do they map to previously computed states?"*

- **Example (Fibonacci):** To know the `i`-th number, I transition from `i-1` and `i-2`. Thus, `dp(i) = dp(i-1) + dp(i-2)`.
- **Example (Robbing Houses):** I can either rob house `i` (and add `dp(i-2)`) OR skip it (and take `dp(i-1)`). Thus, `dp(i) = max(nums[i] + dp(i-2), dp(i-1))`.

# Code Implementation
Let's see how explicitly defining states and transitions makes coding a breeze. We'll use a generic skeleton that can be applied to almost any DP problem.

<CodeBlock
  cpp="class Solution {
public:
    int solve(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return 0;
        
        // 1. Define State: dp[i] represents the optimal answer up to index i
        vector<int> dp(n, 0);
        
        // 2. Base Cases
        dp[0] = nums[0];
        if (n > 1) {
            dp[1] = max(nums[0], nums[1]);
        }
        
        // 3. Transitions
        for (int i = 2; i < n; i++) {
            // Decision: Do we include nums[i] or not?
            int choice1 = nums[i] + dp[i - 2];
            int choice2 = dp[i - 1];
            dp[i] = max(choice1, choice2);
        }
        
        return dp[n - 1];
    }
};"

# Common Pitfalls
<Warning>
- **Bloated States:** Adding variables to your state that aren't strictly necessary. This inflates your space complexity from O(N) to O(N^2) or worse.
- **Circular Dependencies:** Failing to define a base case correctly can result in a transition that loops infinitely or points to uninitialized garbage data.
</Warning>
