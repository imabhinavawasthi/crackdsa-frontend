# Theory & Concepts
Welcome to the **Minimum Path Sum** lesson. We are now moving from 1D Dynamic Programming arrays to 2D matrices. If you understood the climbing stairs pattern, 2D grid problems are just the 2D equivalent.

### The Problem Statement
Given an `m x n` grid filled with non-negative numbers, find a path from the top-left to the bottom-right, which minimizes the sum of all numbers along its path.
*Constraint:* You can only move either down or right at any point in time.

### The Intuition & State Definition
Just like the 1D problems, we ask ourselves: *"If I am at a specific cell `(r, c)`, how did I get there?"*
Because we can only move down or right, we must have arrived at `(r, c)` from either:
1. The cell directly above it: `(r-1, c)`
2. The cell directly to its left: `(r, c-1)`

If we want the *minimum* path sum to reach `(r, c)`, we simply look at those two adjacent cells, pick the one with the smaller path sum so far, and add the current cell's value.

**State:** `dp[r][c]` represents the minimum path sum from `(0, 0)` to `(r, c)`.
**Transition:** `dp[r][c] = grid[r][c] + min(dp[r-1][c], dp[r][c-1])`

### Base Cases
- The starting cell `dp[0][0]` is just `grid[0][0]`.
- The top row: You can only reach these cells by moving right. `dp[0][c] = dp[0][c-1] + grid[0][c]`.
- The left column: You can only reach these cells by moving down. `dp[r][0] = dp[r-1][0] + grid[r][0]`.

# Code Implementation
We can solve this elegantly using a 2D array. However, because we only ever look at the current row and the previous row, we can optimize the space to 1D! Let's show the standard 2D approach, but note the optimization in the interview tips.

<CodeBlock
  cpp="class Solution {
public:
    int minPathSum(vector<vector<int>>& grid) {
        int m = grid.size();
        int n = grid[0].size();
        
        // Use the grid itself as the DP table to achieve O(1) extra space!
        // Initialize top row
        for (int c = 1; c < n; c++) {
            grid[0][c] += grid[0][c - 1];
        }
        
        // Initialize left column
        for (int r = 1; r < m; r++) {
            grid[r][0] += grid[r - 1][0];
        }
        
        // Fill the rest of the grid
        for (int r = 1; r < m; r++) {
            for (int c = 1; c < n; c++) {
                grid[r][c] += min(grid[r - 1][c], grid[r][c - 1]);
            }
        }
        
        return grid[m - 1][n - 1];
    }
};"
  java="class Solution {
    public int minPathSum(int[][] grid) {
        int m = grid.length;
        int n = grid[0].length;
        
        // We modify the grid in-place to save space
        
        // Top row
        for (int c = 1; c < n; c++) {
            grid[0][c] += grid[0][c - 1];
        }
        
        // Left column
        for (int r = 1; r < m; r++) {
            grid[r][0] += grid[r - 1][0];
        }
        
        // Compute for internal cells
        for (int r = 1; r < m; r++) {
            for (int c = 1; c < n; c++) {
                grid[r][c] += Math.min(grid[r - 1][c], grid[r][c - 1]);
            }
        }
        
        return grid[m - 1][n - 1];
    }
}"
  python="class Solution:
    def minPathSum(self, grid: list[list[int]]) -> int:
        m, n = len(grid), len(grid[0])

        for c in range(1, n):
            grid[0][c] += grid[0][c - 1]
            
        for r in range(1, m):
            grid[r][0] += grid[r - 1][0]

            for c in range(1, n):
                grid[r][c] += min(grid[r - 1][c], grid[r][c - 1])

# Common Pitfalls
<Warning>
- **Modifying Input Constraints:** In some strict interview environments, modifying the input array `grid` is considered a bad practice. Always ask the interviewer: *"Are there any side effects to modifying the input grid, or should I allocate a separate O(N) array?"*
- **Grid Out of Bounds:** Be extremely careful when initializing the top row and left column separately. A standard `for r... for c...` loop without proper bounds checks will throw index out of bounds on `r-1` or `c-1`.
</Warning>
