# Theory & Concepts
Welcome to the deep-dive on the **Climbing Stairs (Fibonacci Pattern)**. This pattern extends beyond just climbing stairs; it is the fundamental framework for any problem that asks: *"In how many distinct ways can I reach a target state, given a set of valid moves?"*

### Generalizing the Fibonacci Pattern
The standard Climbing Stairs problem allows steps of `1` or `2`. This yields the recurrence: `dp(n) = dp(n-1) + dp(n-2)`.

But what if you could take `1`, `2`, or `3` steps at a time?
Then, to reach step `n`, you could have jumped from `n-1`, `n-2`, or `n-3`.
The recurrence simply expands: `dp(n) = dp(n-1) + dp(n-2) + dp(n-3)`.

This pattern fundamentally relies on the **Rule of Sum in Combinatorics**. If an event can happen in $A$ mutually exclusive ways and another in $B$ mutually exclusive ways, the total ways the event can occur is $A + B$.

### The DP State
- **State:** `dp[i]` = the number of distinct ways to reach step `i`.
- **Transition:** `dp[i] = sum(dp[i - step])` for all valid `step` sizes.
- **Base Case:** `dp[0] = 1`. There is exactly 1 way to remain on the ground (do nothing).

# Code Implementation
Let's implement the generalized version where you can take up to `k` steps at a time. This proves you truly understand the pattern rather than just memorizing `prev1 + prev2`.

<CodeBlock
  cpp="class Solution {
public:
    int climbStairsWithKSteps(int n, int k) {
        vector<int> dp(n + 1, 0);
        dp[0] = 1; // Base case: 1 way to be at the ground
        
        for (int i = 1; i <= n; i++) {
            // Sum up the ways from all valid previous steps
            for (int step = 1; step <= k; step++) {
                if (i - step >= 0) {
                    dp[i] += dp[i - step];
                }
            }
        }
        
        return dp[n];
    }
};"

# Common Pitfalls
<Warning>
- **Misunderstanding `dp[0]`:** Setting `dp[0] = 0` will ruin the entire calculation because all subsequent steps build on the premise that `dp[step] = dp[0]` when taking a full jump from the ground. `dp[0]` must be 1.
- **Handling Constraints:** If $K$ is very large (e.g., $K = N$), the time complexity becomes $O(N^2)$. You can optimize this to $O(N)$ by keeping a running sum of the last $K$ elements!
</Warning>
