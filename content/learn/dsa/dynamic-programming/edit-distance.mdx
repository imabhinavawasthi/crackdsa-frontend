# Theory & Concepts
The **Edit Distance** (or Levenshtein Distance) problem asks for the minimum number of operations required to convert string `word1` into string `word2`. The allowed operations are insert a character, delete a character, and replace a character.

### Core Intuition
Similar to Longest Common Subsequence, we compare characters from the two strings.
- **Match**: If `word1[i-1] == word2[j-1]`, no operation is needed. `dp[i][j] = dp[i-1][j-1]`.
- **Mismatch**: If they differ, we consider all three operations and take the minimum + 1:
  1. **Insert**: Imagine we inserted a matching character into `word1`. We consume a character from `word2`. `dp[i][j-1]`
  2. **Delete**: Imagine we delete the character from `word1`. We consume a character from `word1`. `dp[i-1][j]`
  3. **Replace**: Imagine we replace the character in `word1` to match `word2`. We consume a character from both. `dp[i-1][j-1]`

So, `dp[i][j] = 1 + min(dp[i][j-1], min(dp[i-1][j], dp[i-1][j-1]))`.

# Common Pitfalls
<Warning>
- Forgetting to initialize the base cases (`dp[i][0] = i` and `dp[0][j] = j`). Converting a string to an empty string requires deleting all its characters!
- Incorrectly assigning the recurrence relations to the operations (e.g., swapping insert and delete state lookups).
</Warning>
