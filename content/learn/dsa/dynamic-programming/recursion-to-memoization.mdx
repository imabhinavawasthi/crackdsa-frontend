# Theory & Concepts
Welcome to the essential guide on **Recursion to Memoization (Top-Down)**. Dynamic Programming often strikes fear into the hearts of interview candidates, but at its core, it's just an optimization over plain recursion.

### The Naive Recursion Problem
When solving problems with a recursive approach, we often break down a large problem into smaller subproblems. However, in many cases, we end up solving the *exact same subproblem* multiple times. This leads to what we call an **overlapping subproblems** property, causing an exponential time complexity (e.g., $O(2^N)$).

### Enter Memoization (Top-Down)
Memoization is the process of caching the results of expensive function calls and returning the cached result when the same inputs occur again. 
1. **Top-Down:** We start from the main problem and recursively break it down.
2. **Cache (Memo):** We use a data structure, typically a hash map or an array, to store the answer to a subproblem the first time we compute it.
3. **Lookup:** Before doing any work in our recursive function, we check if the answer is already in the cache.

By doing this, we guarantee that each subproblem is computed exactly once, transforming an exponential time complexity into a polynomial one (often linear $O(N)$ or quadratic $O(N^2)$).

# Code Implementation
Let's illustrate this with the classic Fibonacci sequence problem, optimizing a $O(2^N)$ naive recursion to an $O(N)$ memoized solution.

private:
    int memoHelper(int n, vector<int>& memo) {
        if (n <= 1) return n;
        
        // If we have already computed this state, return it
        if (memo[n] != -1) {
            return memo[n];
        }
        
        // Compute and store in memo before returning
        memo[n] = memoHelper(n - 1, memo) + memoHelper(n - 2, memo);
        return memo[n];
    }
    
public:
    int fib(int n) {
        // Initialize memo array with -1 indicating uncomputed states
        vector<int> memo(n + 1, -1);
        return memoHelper(n, memo);
    }

# Common Pitfalls
<Warning>
- **Forgetting to Return the Cached Value:** Computing the answer, putting it in the cache, but failing to check the cache at the very beginning of your recursive function.
- **Cache Initialization:** Not initializing the cache correctly. In arrays, make sure to fill it with a value that cannot be an actual answer (like `-1`).
- **Stack Overflow:** Python and some other languages have strict limits on recursion depth. If $N$ is too large, the top-down approach might crash due to a Stack Overflow, even with memoization.
</Warning>
