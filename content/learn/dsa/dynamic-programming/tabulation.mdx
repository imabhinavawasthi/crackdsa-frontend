# Theory & Concepts
Welcome to the lesson on **Tabulation (Bottom-Up)**. If you have mastered memoization (top-down), tabulation is the natural next step. It is the ultimate form of dynamic programming, completely removing recursion to yield blistering fast execution times and allowing for insane space optimizations.

### What is Tabulation?
Tabulation involves solving a dynamic programming problem iteratively. Instead of starting from the massive, overarching problem and digging down recursively, we start at the absolute simplest base cases and build our way up systematically using a table (usually a 1D or 2D array).

### The Recipe for Tabulation
1. **Define the Table:** What does `dp[i]` or `dp[i][j]` represent?
2. **Initialize Base Cases:** Fill in the simplest known answers (e.g., `dp[0] = 0`).
3. **Determine the Traversal Order:** Since we are building from the ground up, we usually iterate from `1` to `N`. For 2D grids, this might mean looping row by row.
4. **State Transition:** Write the iterative rule that fills `dp[i]` using previously computed values like `dp[i-1]` or `dp[i-2]`.

### Why Tabulate?
No recursion means no call stack overhead and no risk of stack overflow errors. Furthermore, bottom-up implementations easily reveal whether space optimizations (like dropping a full $O(N)$ array for an $O(1)$ variable pair) are possible.

# Code Implementation

# Common Pitfalls
<Warning>
- **Off-By-One Errors:** Ensuring the size of your DP array is `N+1` when you need to access `dp[N]` is a very common tripping point.
- **Incorrect Traversal Direction:** In problems like the Knapsack Problem, traversing backwards is sometimes required to avoid reusing elements. Always be intentional about your loop direction.
</Warning>
