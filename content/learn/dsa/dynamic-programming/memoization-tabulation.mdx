# Theory & Concepts
Dynamic programming solutions can be implemented in two primary ways: **Memoization (Top-Down)** and **Tabulation (Bottom-Up)**. Knowing when and why to use each is critical for acing system design and algorithmic interviews.

### Memoization (Top-Down)
Memoization starts at the target problem and recursively breaks it down into smaller subproblems. Whenever a subproblem is solved, its result is saved in a cache (usually a hash map or an array). If the same subproblem is encountered again, the cached result is returned instead of recalculating it.

**Pros:**
- Easier to write if you already have a recursive solution.
- Only computes states that are actually needed (lazy evaluation).

**Cons:**
- Risk of recursion stack overflow for large inputs.
- Slight overhead from recursive function calls.

### Tabulation (Bottom-Up)
Tabulation takes the opposite approach. It starts with the smallest possible subproblems (base cases) and iteratively computes larger problems until the target problem is reached. It typically uses an array or matrix to build the solution.

**Pros:**
- No recursive overhead, generally faster constant time factors.
- No risk of stack overflow.
- Easier to optimize space (e.g., using only the previous row in a 2D matrix).

**Cons:**
- Might compute states that are never actually needed.
- Can be less intuitive to derive directly compared to a top-down tree.

# Code Implementation
Here is how you might solve a 1D DP problem (like finding the nth Fibonacci number) using both approaches to compare them.

    // Memoization (Top-Down)
    int memoHelper(int n, vector<int>& memo) {
        if (n <= 1) return n;
        if (memo[n] != -1) return memo[n];
        return memo[n] = memoHelper(n - 1, memo) + memoHelper(n - 2, memo);

        vector<int> dp(n + 1);
        dp[0] = 0;
        dp[1] = 1;
        for (int i = 2; i <= n; i++) {

# Common Pitfalls
<Warning>
- **Choosing Memoization for deeply nested problems:** In languages like Python, recursion limits will hit you fast. Tabulation is safer.
- **Unnecessary State Computation in Tabulation:** Sometimes the DP space is sparse, meaning only a fraction of states are needed. In such cases, top-down memoization might actually be faster because it only computes what it visits.
</Warning>
