# Theory & Concepts
Welcome to the lesson on the **House Robber Pattern**. This is arguably one of the most famous Dynamic Programming paradigms. It introduces the concept of **"Take it or Leave it"** decision making with adjacency constraints.

### House Robber I (Linear Street)
You are a professional robber planning to rob houses along a street. Each house has a certain amount of money stashed. The only constraint: adjacent houses have interconnected security systems. You cannot rob two adjacent houses.

**The DP State Transition:**
At any house `i`, you have exactly two choices:
1. **Rob it:** You get `nums[i]` but you cannot have robbed house `i-1`. So you add the max money from house `i-2`.
2. **Leave it:** You skip this house, meaning your max money is whatever you had up to house `i-1`.

Recurrence: `dp(i) = max(nums[i] + dp(i-2), dp(i-1))`

### House Robber II (Circular Street)
The street is now a circle. The first house and the last house are connected.
How do we solve this? Simple! The circular constraint means we cannot rob both house `0` and house `n-1`. Therefore, the optimal solution is the maximum of two separate subproblems:
1. Rob houses from `0` to `n-2` (ignoring the last house).
2. Rob houses from `1` to `n-1` (ignoring the first house).

# Code Implementation
Let's implement the robust $O(1)$ space solution for **House Robber II**, which implicitly covers the logic for House Robber I.

private:
    int robLinear(vector<int>& nums, int start, int end) {
        int prev2 = 0; // dp[i-2]
        int prev1 = 0; // dp[i-1]
        
        for (int i = start; i <= end; i++) {
            int current = max(prev1, nums[i] + prev2);
            prev2 = prev1;
            prev1 = current;
        }
        return prev1;
    }

public:
    int rob(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return 0;
        if (n == 1) return nums[0];
        if (n == 2) return max(nums[0], nums[1]);
        
        // Max of robbing 0 to n-2 OR robbing 1 to n-1
        return max(robLinear(nums, 0, n - 2), robLinear(nums, 1, n - 1));
    }
};"

# Common Pitfalls
<Warning>
- **Array bounds on tiny inputs:** If the array only has 1 element, you cannot slice it into `0` to `n-2` safely. Always explicitly handle base cases for `n=1` and `n=2`.
- **Greedy approach trap:** A common mistake is to sum all even indices and sum all odd indices and return the max. This fails on `[2, 1, 1, 2]` because the optimal choice is index 0 and index 3 (which sum to 4).
</Warning>
