# Theory & Concepts
The 0/1 Knapsack problem is a classic dynamic programming problem. You are given `N` items, each with a weight and a value, and a knapsack with a maximum weight capacity `W`. The goal is to maximize the total value of items you can put in the knapsack.
"0/1" means you can either take an item completely (1) or leave it (0). You cannot take fractions of an item, and you cannot take an item more than once.

### Core Intuition
The optimal substructure lies in evaluating each item:
- **Include the item**: Add its value to the result and subtract its weight from the remaining capacity. Find the maximum value for the remaining items and capacity.
- **Exclude the item**: Skip it and find the maximum value for the remaining items with the same capacity.

Take the maximum of these two choices. Overlapping subproblems arise because the same `(remaining items, remaining capacity)` state will be calculated multiple times. We can memoize or use tabulation to solve this in polynomial time.

# Code Implementation

public:
    int knapsack(vector<int>& wt, vector<int>& val, int n, int W) {
        vector<vector<int>> dp(n + 1, vector<int>(W + 1, 0));
        
        for (int i = 1; i <= n; i++) {
            for (int w = 1; w <= W; w++) {
                if (wt[i - 1] <= w) {
                    dp[i][w] = max(val[i - 1] + dp[i - 1][w - wt[i - 1]], dp[i - 1][w]);
                } else {
                    dp[i][w] = dp[i - 1][w];
                }
            }
        }
        return dp[n][W];
    }
};"

# Common Pitfalls
<Warning>
- Using a greedy approach (sorting by value/weight ratio) which only works for Fractional Knapsack, not 0/1 Knapsack.
- Forgetting to handle the base cases when the capacity is 0 or no items are left.
- In 1D DP space optimization, traversing the weight loop forwards instead of backwards, leading to an item being selected multiple times.
</Warning>
