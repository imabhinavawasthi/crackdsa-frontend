# Theory & Concepts
There are two primary paradigms when writing recursive functions: **Parameterized Recursion** and **Functional Recursion**. Understanding the difference is crucial for writing clean, bug-free recursive code.

### Parameterized Recursion
In Parameterized Recursion, the result is accumulated as arguments (parameters) passed from one recursive call to the next. The function itself often doesn't return anything (e.g., returns `void`). The final answer is typically printed or stored in a global/reference variable when the base case is hit.

### Functional Recursion
In Functional Recursion, the recursive function is expected to return a value. The current function call computes a piece of the answer, delegates the rest of the problem to a recursive call, and combines its own piece with the returned result. This approach generally leads to cleaner code that avoids side effects.

# Code Implementation
Let's see both approaches by calculating the sum of the first $N$ numbers.

<CodeBlock
  cpp="// Parameterized Recursion\nvoid sumParameterized(int i, int sum) {\n    if (i < 1) {\n        cout << sum << endl;\n        return;\n    }\n    sumParameterized(i - 1, sum + i);\n}\n\n// Functional Recursion\nint sumFunctional(int n) {\n    if (n == 0) return 0;\n    return n + sumFunctional(n - 1);\n}"
  java="// Parameterized Recursion\npublic void sumParameterized(int i, int sum) {\n    if (i < 1) {\n        System.out.println(sum);\n        return;\n    }\n    sumParameterized(i - 1, sum + i);\n}\n\n// Functional Recursion\npublic int sumFunctional(int n) {\n    if (n == 0) return 0;\n    return n + sumFunctional(n - 1);\n}"

# Common Pitfalls
<Warning>
- In Functional Recursion, forgetting to `return` the result of the recursive call.
- In Parameterized Recursion, mixing up pass-by-value and pass-by-reference can lead to unintended side effects or lost data.
</Warning>
