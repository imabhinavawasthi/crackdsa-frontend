# Theory & Concepts
Generating **Permutations** requires us to find all possible orderings of a given set of items. Unlike subsets, where order doesn't matter and we only move "forward" through the array, finding permutations means that at every step, we can pick *any* element from the array as long as we haven't picked it yet.

To achieve this, we use the backtracking template but with two critical differences from Subsets:
1. The `for` loop always starts at `0`, not at an `index`.
2. We must maintain a `used` boolean array (or a set/bitmask) to keep track of which elements are currently in our `path` so we don't reuse them.

When the size of our `path` equals the size of the input array, we have formed a complete permutation and can add it to our results.

# Code Implementation
Here is the standard backtracking approach using a boolean `used` array.

<CodeBlock
  cpp="class Solution {\npublic:\n    vector<vector<int>> permute(vector<int>& nums) {\n        vector<vector<int>> res;\n        vector<int> path;\n        vector<bool> used(nums.size(), false);\n        backtrack(nums, path, used, res);\n        return res;\n    }\n    \nprivate:\n    void backtrack(vector<int>& nums, vector<int>& path, vector<bool>& used, vector<vector<int>>& res) {\n        // Base case: permutation is complete\n        if (path.size() == nums.size()) {\n            res.push_back(path);\n            return;\n        }\n        \n        for (int i = 0; i < nums.size(); i++) {\n            if (used[i]) continue; // Skip already used elements\n            \n            used[i] = true;\n            path.push_back(nums[i]); // Choose\n            \n            backtrack(nums, path, used, res); // Explore\n            \n            path.pop_back(); // Un-choose\n            used[i] = false;\n        }\n    }\n};"
  java="class Solution {\n    public List<List<Integer>> permute(int[] nums) {\n        List<List<Integer>> res = new ArrayList<>();\n        boolean[] used = new boolean[nums.length];\n        backtrack(nums, new ArrayList<>(), used, res);\n        return res;\n    }\n    \n    private void backtrack(int[] nums, List<Integer> path, boolean[] used, List<List<Integer>> res) {\n        if (path.size() == nums.length) {\n            res.add(new ArrayList<>(path));\n            return;\n        }\n        \n        for (int i = 0; i < nums.length; i++) {\n            if (used[i]) continue;\n            \n            used[i] = true;\n            path.add(nums[i]);\n            \n            backtrack(nums, path, used, res);\n            \n            path.remove(path.size() - 1);\n            used[i] = false;\n        }\n    }\n}"

# Common Pitfalls
<Warning>
- Using `.contains()` on a List/Array to check if an element is used instead of a boolean array. This turns a $O(1)$ check into an $O(N)$ check, ruining the time complexity.
- Forgetting to reset `used[i] = false` during the un-choose (backtracking) step.
</Warning>
