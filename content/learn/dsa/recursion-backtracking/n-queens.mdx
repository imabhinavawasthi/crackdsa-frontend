# Theory & Concepts
The **N-Queens** puzzle is the quintessential backtracking problem. The objective is to place $N$ queens on an $N \times N$ chessboard such that no two queens attack each other. A queen can attack any piece in the same row, column, or diagonal.

Because no two queens can share the same row, we can place exactly one queen per row. Our recursive state becomes the current row we are trying to place a queen in.
For row `r`:
1. Loop through every column `c` from `0` to `N-1`.
2. Check if placing a queen at `(r, c)` is safe (no other queen in the same column or diagonals).
3. If safe, place the queen, and recurse to row `r + 1`.
4. If the recursive call returns (or fails), remove the queen and try the next column.

### Optimizing the "Is Safe" Check
A naive `isSafe` function loops through the board in $O(N)$ time. We can optimize this to $O(1)$ by using sets (or boolean arrays) to track occupied columns and diagonals.
- Main diagonal (top-left to bottom-right): `row - col` is constant.
- Anti-diagonal (top-right to bottom-left): `row + col` is constant.

# Code Implementation
Here is the implementation of N-Queens using optimized boolean arrays for constraint checking.

# Common Pitfalls
<Warning>
- Re-scanning the board vertically and diagonally every time taking $O(N)$ instead of using the $O(1)$ set/array optimization.
- Forgetting to handle negative indices when calculating the main diagonal (`row - col`) in languages like C++ or Java. (Adding `n` fixes this).
</Warning>
