# Theory & Concepts
Understanding the Recursion Tree and Call Stack is crucial for visualizing the execution flow of any recursive program. A **Recursion Tree** is a visual representation of the recursive calls made by a function. Each node in the tree represents a single function call, and the edges represent the calls made to child instances.

When visualizing a recursion tree:
- The **root** is the initial function call.
- The **leaves** are the base cases.
- The **height** of the tree corresponds to the maximum depth of the call stack (which determines space complexity).
- The total **number of nodes** generally dictates the time complexity.

The Call Stack grows as you traverse down the tree from the root to a leaf. When a leaf (base case) is reached, it returns its result to its parent, and the Call Stack shrinks (backtracking).

# Code Implementation
Here is an example computing the $N^{th}$ Fibonacci number, which generates a classic recursion tree.

# Common Pitfalls
<Warning>
- Overlapping subproblems! Notice that `fib(N-2)` might be calculated multiple times. Without memoization, recursion trees can explode exponentially.
- Failing to track the state correctly as you traverse down and up the recursion tree.
</Warning>
