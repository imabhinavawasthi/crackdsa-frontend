# Theory & Concepts
The generation of **Subsets** and **Permutations** forms the bedrock of combinatorial algorithms. While both use backtracking, they solve fundamentally different problems:

- **Subsets (Power Set):** You want to find all possible combinations of elements where order does *not* matter. `[1, 2]` is the same subset as `[2, 1]`. For an array of size $N$, there are exactly $2^N$ subsets.
- **Permutations:** You want to find all possible arrangements of elements where order *does* matter. `[1, 2]` is a different permutation than `[2, 1]`. For an array of size $N$, there are $N!$ permutations.

Understanding the difference in their Recursion Trees is crucial:
- The **Subsets Tree** is a binary tree where at each step, you either *include* or *exclude* the current element.
- The **Permutations Tree** is an $N$-ary tree where at each step, you loop through all available elements to pick the next one.

# Common Pitfalls
<Warning>
- Mixing up the `index` loop variable! Subsets loop starts from `index`, whereas Permutations loop always starts from `0` (and relies on the `used` array to avoid duplicates).
- Forgetting to make a deep copy of the `path` list when adding it to the `res` list. In many languages, arrays are passed by reference, so if you don't copy, the final list will be full of empty arrays.
</Warning>
