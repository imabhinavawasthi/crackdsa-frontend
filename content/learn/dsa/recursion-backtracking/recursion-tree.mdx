# Theory & Concepts
A **Recursion Tree** is an invaluable conceptual tool used to analyze the time and space complexity of recursive algorithms. It maps out the cascade of recursive calls spawned by a single initial call. 

In a recursion tree:
- **Nodes** represent the work done at a specific recursive call (excluding the recursive calls themselves).
- **Edges** represent the transition from a parent call to a child call.

By summing the work done at each level of the tree, you can determine the overall time complexity of the algorithm. This method is particularly useful for analyzing Divide and Conquer algorithms, such as Merge Sort or recursive mathematical formulas.

# Code Implementation
Let's consider an example where an algorithm divides the problem into two halves, taking $O(N)$ work at each step (similar to Merge Sort).

# Common Pitfalls
<Warning>
- Miscalculating the total work at a given level. For example, in Merge Sort, each node does less work, but the level as a whole always does O(N) work.
- Confusing the number of leaves with the total time complexity.
</Warning>
