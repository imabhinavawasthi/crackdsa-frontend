# Theory & Concepts

While a Hash Map stores data in *Key-Value* pairs, a **Hash Set** simply stores *unique Keys*. It acts like a mathematical set. It is built entirely on top of the Hash Map data structure (in Java, a `HashSet` actually just wraps a `HashMap` and maps every inserted key to a dummy value).

### When to use a Hash Set
- **Deduplication:** Removing duplicates from an array or a list.
- **Fast Lookups:** Checking if an element exists in a collection in $O(1)$ time. 
- **Set Operations:** Performing mathematical operations like Union, Intersection, and Difference between collections.

If you don't need to associate a specific value or a frequency count with an item, and you only care *whether or not it exists*, a Hash Set is more memory-efficient and semantically correct than a Hash Map.

# Common Pitfalls

<Warning>
- **Empty Initialization in Python:** Be careful! Initializing `my_set = {}` creates an empty dictionary. You must use `my_set = set()` to create an empty Hash Set.
- **Relying on Order:** Hash Sets do not guarantee insertion order. If you need a set that remembers the order of insertions, use `LinkedHashSet` in Java or Python's dict keys.
- **Adding Mutable Elements:** Never add mutable elements (like lists or arrays) to a set. Changes to the element will mess up its hash, effectively making it unreachable inside the set.
</Warning>
