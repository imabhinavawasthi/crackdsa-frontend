# Theory & Concepts
The problem of finding the number of subarrays that sum to a specific value $K$ is a classic application of the Prefix Sum + Hashing pattern. Given an array of integers and an integer $K$, we need to find the total number of continuous subarrays whose sum equals $K$.

A brute force approach would involve checking every possible subarray, leading to an $O(N^2)$ time complexity. However, by maintaining a running sum (prefix sum) as we iterate through the array, we can use a hash map to keep track of how many times we've seen each prefix sum. For any given current prefix sum, if `current_sum - K` exists in our hash map, it means there is a valid subarray ending at the current element that sums to $K$. The number of such subarrays is exactly the frequency of `current_sum - K` in our hash map.

# Code Implementation
<CodeBlock
  cpp="class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<int, int> counts;
        counts[0] = 1; // Base case
        int sum = 0, result = 0;
        
        for (int num : nums) {
            sum += num;
            if (counts.count(sum - k)) {
                result += counts[sum - k];
            }
            counts[sum]++;
        }
        
        return result;
    }
};"
  java="class Solution {
    public int subarraySum(int[] nums, int k) {
        Map<Integer, Integer> counts = new HashMap<>();
        counts.put(0, 1);
        int sum = 0, result = 0;
        
        for (int num : nums) {
            sum += num;
            if (counts.containsKey(sum - k)) {
                result += counts.get(sum - k);
            }
            counts.put(sum, counts.getOrDefault(sum, 0) + 1);
        }
        
        return result;
    }
}"

# Common Pitfalls
<Warning>
- Using a sliding window approach when the array can contain negative numbers. Sliding window only works for arrays with non-negative integers.
- Forgetting to initialize the map with `{0: 1}`. Without this, subarrays that start from index 0 and sum to K will not be counted.
- Only storing whether a prefix sum exists instead of its frequency. We need the frequency because multiple prefixes can have the same sum.
</Warning>
