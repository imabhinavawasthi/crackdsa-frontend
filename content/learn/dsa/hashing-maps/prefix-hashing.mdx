# Theory & Concepts
The **Prefix Sum + Hashing** pattern is a powerful technique used to solve subarray problems with optimal time complexity. A prefix sum is the cumulative sum of elements in an array from the beginning up to the current index. When combined with hashing, we can efficiently query past prefix sums to find subarrays that meet certain criteria (like having a specific sum or property).

The core idea is based on the mathematical property of prefix sums: if `prefix[i]` is the sum of elements from index `0` to `i`, and `prefix[j]` is the sum from `0` to `j` (where `i < j`), then the sum of the subarray from `i+1` to `j` is `prefix[j] - prefix[i]`. If we are looking for a subarray with sum `K`, we can re-arrange this to `prefix[j] - K = prefix[i]`. Thus, as we calculate the prefix sum at each step, we can use a hash map to check if we have previously seen a prefix sum equal to `prefix[j] - K`.

# Code Implementation

public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<int, int> prefixCounts;
        prefixCounts[0] = 1; // Base case: one way to have sum 0 (empty subarray)
        int currentSum = 0;
        int count = 0;
        
        for (int num : nums) {
            currentSum += num;
            if (prefixCounts.find(currentSum - k) != prefixCounts.end()) {
                count += prefixCounts[currentSum - k];
            }
            prefixCounts[currentSum]++;
        }
        return count;
    }
};"
  java="class Solution {
    public int subarraySum(int[] nums, int k) {
        HashMap<Integer, Integer> prefixCounts = new HashMap<>();
        prefixCounts.put(0, 1);
        int currentSum = 0;
        int count = 0;
        
        for (int num : nums) {
            currentSum += num;
            if (prefixCounts.containsKey(currentSum - k)) {
                count += prefixCounts.get(currentSum - k);
            }
            prefixCounts.put(currentSum, prefixCounts.getOrDefault(currentSum, 0) + 1);
        }
        return count;
    }

# Common Pitfalls
<Warning>
- Forgetting to initialize the hash map with the base case (e.g., `prefixCounts[0] = 1`). This is crucial to correctly count subarrays that start from the 0th index.
- Not handling negative numbers correctly. The prefix sum array is not monotonically increasing if negative numbers exist, so standard sliding window approaches fail. Prefix hashing is the correct approach here.
- Using a 2D array or nested loops to check all subarrays, which results in a suboptimal O(N²) or O(N³) time complexity.
</Warning>
