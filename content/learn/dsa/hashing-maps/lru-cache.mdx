# Theory & Concepts
A Least Recently Used (LRU) Cache is a common caching strategy that discards the least recently used items first when the cache reaches its capacity. To achieve $O(1)$ time complexity for both `get` and `put` operations, we need a combination of two data structures:
1. **Hash Map**: Provides $O(1)$ access to cache items using their keys.
2. **Doubly Linked List**: Keeps track of the recency of usage. The most recently used items are kept near the "head," while the least recently used drop to the "tail."

When we access or update an item, we move its corresponding node to the head of the list. When the cache is full and we need to insert a new item, we remove the node at the tail of the list and delete its key from the hash map.

        self.head.next = self.tail

        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

        self._remove_node(node)
        self._add_to_head(node)
        return node.val

# Common Pitfalls
<Warning>
- Using dummy head and tail nodes is highly recommended. Not using them forces you to write multiple `if (head == null)` edge cases, which is extremely bug-prone.
- Forgetting to delete the LRU key from the **hash map** when evicting a node from the linked list.
- Memory leaks in languages like C++. Always remember to `delete` nodes you've removed from the cache.
</Warning>
