# Theory & Concepts

Behind the magic of $O(1)$ lookups in Hash Maps and Hash Sets lies the **Hash Function** and **Collision Resolution** strategies. When you use built-in structures like `HashMap`, these mechanisms are hidden from you, but understanding them is heavily tested in system design and advanced DSA interviews.

### What is a Hash Function?
A hash function is an algorithm that maps an arbitrary key (a string, an object, a number) to a fixed-size integer. We then use the modulo operator (`hash % array_size`) to find the exact array index (bucket) where the value should be stored.

**Properties of a Good Hash Function:**
1. **Deterministic:** Same input always yields the same hash.
2. **Fast to Compute:** The function shouldn't be overly complex.
3. **Uniform Distribution:** It should map keys evenly across buckets to avoid grouping.

### What is a Collision?
When two entirely different keys produce the *same* array index after hashing, we have a **Collision**. Because the array slot is already occupied, we need a resolution strategy.

### Collision Resolution Strategies

**1. Chaining (Separate Chaining)**
Instead of storing directly in the array, each array bucket holds a Linked List (or another collection). When a collision occurs, we simply append the new key-value pair to the linked list in that bucket.
*Pros:* Simple to implement, never fills up entirely.
*Cons:* Memory overhead for pointers; cache performance is poor due to scattered linked list nodes.

**2. Open Addressing (Linear/Quadratic Probing)**
All elements are stored in the hash table array itself. If a bucket is occupied, we probe (search) for the next available empty bucket.
- **Linear Probing:** Look at `index + 1`, `index + 2`, etc.
- **Quadratic Probing:** Look at `index + 1^2`, `index + 2^2`, etc.
*Pros:* Very cache-friendly, no extra memory for pointers.
*Cons:* Can suffer from "clustering" (blocks of occupied buckets), and resizing is mandatory when the table gets full.

# Code Implementation

Here is how you might write a simple string hashing function (polynomial rolling hash), which is commonly used to minimize collisions for string keys.

<CodeBlock

#include <iostream>
#include <string>

using namespace std;

class HashFunction {
public:
    int computeHash(string key, int bucketSize) {
        long long hashValue = 0;
        long long p = 31; // Prime number
        long long p_pow = 1;
        long long m = 1e9 + 9;

        for (char c : key) {
            hashValue = (hashValue + (c - 'a' + 1) * p_pow) % m;
            p_pow = (p_pow * p) % m;
        }
        
        return hashValue % bucketSize;
    }
};

int main() {
    HashFunction hf;
    cout << hf.computeHash(\"hello\", 10) << endl;
    return 0;
}

# Common Pitfalls

<Warning>
- **Choosing Poor Primes:** If you write a custom hash function, always use prime numbers for multiplication constants and modulo bases. This drastically reduces the mathematical likelihood of periodic collisions.
- **Ignoring the Load Factor:** As elements get added, the ratio of (elements/buckets) increases. If this **Load Factor** exceeds a certain threshold (e.g., 0.75 in Java), the hash map must be **Resized** (doubling the buckets and rehashing everything) to maintain O(1) performance.
</Warning>
