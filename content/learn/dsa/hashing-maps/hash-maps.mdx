# Theory & Concepts
**Hash Maps** (known as Dictionaries in Python, or `unordered_map` in C++) are arguably the most essential data structure for coding interviews. They store data in `Key-Value` pairs and offer blazingly fast $O(1)$ average time complexity for insertions, deletions, and lookups.

The power of a Hash Map lies in its ability to instantly answer the question: *"Have I seen this element before, and if so, what information is associated with it?"* This makes them indispensable for tracking frequencies, mapping relationships between entities, and optimizing nested loops into single passes.

When you look at an array problem that has an $O(N^2)$ brute-force solution involving nested loops, your immediate instinct should be: **Can I use a Hash Map to store past values and turn this into an $O(N)$ solution?**

# Common Pitfalls
<Warning>
- Confusing a `Hash Map` with a `Tree Map` (like `std::map` in C++ or `TreeMap` in Java). Tree Maps maintain keys in sorted order but cost $O(\log N)$ for operations. Hash Maps do not guarantee order but operate in $O(1)$.
- Modifying a key object after inserting it into the map. This alters its hash code, making it impossible for the map to find it again, resulting in a memory leak and logical bugs.
- Iterating over a Hash Map assuming the elements will be retrieved in the order they were inserted. (Note: Python 3.7+ does maintain insertion order by default, but it's an exception, not the rule across languages).
</Warning>
