# Theory & Concepts
A **Hash Function** is a mathematical algorithm that maps data of arbitrary size (like strings, objects, or arrays) to a fixed-size integer. This integer is then used as an index in an underlying array (a Hash Table) to store the data, enabling extremely fast $O(1)$ lookups.

A perfect hash function assigns a unique index to every unique input. However, in reality, because the number of possible inputs is infinite and the array size is finite, two different inputs will eventually map to the same index. This event is called a **Hash Collision**.

To build a robust Hash Map, we must gracefully handle collisions. The two most common techniques are:
1. **Chaining (Separate Chaining)**: Each array index holds a linked list (or another data structure). When a collision occurs, the new key-value pair is simply appended to the list at that index.
2. **Open Addressing**: If the target index is occupied, the algorithm probes the array (e.g., using linear or quadratic probing) to find the next available empty slot.

# Common Pitfalls
<Warning>
- Using a weak hash function that causes clustered collisions, defeating the purpose of a Hash Map and degrading performance to O(N).
- Forgetting to handle negative keys in languages like Java or C++ where the modulo operator `%` can return negative values, leading to out-of-bounds array access. Use `abs(key) % size`.
- Not resizing the underlying array when the load factor gets too high. High load factors exponentially increase the probability of collisions.
</Warning>
