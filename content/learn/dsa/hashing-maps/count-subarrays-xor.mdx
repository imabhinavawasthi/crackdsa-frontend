# Theory & Concepts
The problem of finding the number of subarrays with a given XOR $K$ builds directly on the Prefix Sum + Hashing concept, but applies the Bitwise XOR operator instead of addition. 

Let $P[i]$ be the prefix XOR up to index $i$. The XOR sum of a subarray from index $i+1$ to $j$ is given by $P[j] \oplus P[i]$. We want this subarray XOR to be equal to $K$.
Therefore, $P[j] \oplus P[i] = K$.
Using the properties of XOR, we can XOR both sides by $P[j]$, which gives us:
$P[i] = P[j] \oplus K$.

This means that while traversing the array and maintaining a running prefix XOR $P[j]$, we can simply check our hash map to see how many times we've encountered the prefix XOR value of $P[j] \oplus K$ in the past.

    int solve(vector<int>& arr, int k) {
        unordered_map<int, int> prefix_xor_counts;
        prefix_xor_counts[0] = 1; // Base case
        int current_xor = 0;
        int count = 0;
        
        for (int num : arr) {
            current_xor ^= num;
            
            int target_xor = current_xor ^ k;
            if (prefix_xor_counts.find(target_xor) != prefix_xor_counts.end()) {
                count += prefix_xor_counts[target_xor];
            }
            
            prefix_xor_counts[current_xor]++;
        }
        
        return count;
    }
};"

# Common Pitfalls
<Warning>
- Misunderstanding XOR properties. Remember that if `A ^ B = C`, then `A ^ C = B` and `B ^ C = A`.
- Forgetting to initialize the hash map with `{0: 1}`. If a prefix itself forms the target XOR K, `current_xor ^ K` will be 0, so we must account for the initial 0 XOR state.
- Storing merely the existence of a prefix XOR instead of its frequency. Multiple prefixes can evaluate to the same XOR value!
</Warning>
