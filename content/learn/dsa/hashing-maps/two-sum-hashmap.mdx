# Theory & Concepts

**Two Sum** is arguably the most famous coding interview problem. Given an array of integers and a `target`, you must return the *indices* of the two numbers that add up to `target`.

### The Brute Force $O(N^2)$
The naive approach uses nested loops: pick an element at `i`, then iterate `j` from `i+1` to `N` to see if `nums[i] + nums[j] == target`. This is slow.

### The Hash Map $O(N)$
To optimize, we want to know: "If I am currently looking at `nums[i]`, does the array contain `target - nums[i]`?" 

Instead of searching the entire array to answer this, we can use a **Hash Map** to remember the numbers we have seen so far and their indices.
1. Iterate through the array.
2. For each number, calculate its `complement = target - num`.
3. Check if `complement` exists in the Hash Map.
   - If it does, boom! We found our pair. Return `[map.get(complement), current_index]`.
   - If it doesn't, put the current `num` and its `index` into the Hash Map and continue.

# Code Implementation

Here is the flawless, one-pass HashMap implementation of Two Sum.

#include <iostream>
#include <vector>
#include <unordered_map>

using namespace std;

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        // Map to store: value -> index
        unordered_map<int, int> numMap;
        
        for (int i = 0; i < nums.size(); i++) {
            int complement = target - nums[i];
            
            // If we have seen the complement before, we found our pair!
            if (numMap.count(complement)) {
                return {numMap[complement], i};
            }
            
            // Store the current number and its index
            numMap[nums[i]] = i;
        }
        
        return {}; // Should not reach here if guaranteed exactly one solution
    }
};

# Common Pitfalls

<Warning>
- **Using the same element twice:** If you populate the map completely *before* iterating, and the target is 6, looking at `3` might accidentally return its own index if you don't explicitly check `if (map.get(complement) != i)`. The one-pass solution naturally avoids this by only looking at numbers *previously seen*.
- **Returning values instead of indices:** Always double check the return type! Two Sum asks for indices.
</Warning>
