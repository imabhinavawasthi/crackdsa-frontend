# Theory & Concepts

A **Hash Map** (or Dictionary, Map, Hash Table) is one of the most crucial data structures you will encounter. It stores data in key-value pairs, providing remarkably fast data retrieval. 

At its core, a Hash Map uses a mathematical function called a **Hash Function** to compute an index (or "hash code") into an array of buckets or slots, from which the desired value can be found. 

### Why are Hash Maps so powerful?
- **O(1) Average Time Complexity**: Looking up, inserting, or deleting a value based on its key takes constant time on average.
- **Key-Value Mapping**: Perfect for problems where you need to associate an identifier (like a user ID, a string, or a coordinate) with a specific value or object.
- **Deduplication**: Automatically handles unique keys. If you insert a value with an existing key, it simply updates the value.

### How it works under the hood
1. **Hashing**: You pass a key into the hash function.
2. **Indexing**: The hash function spits out an integer. We take `integer % array_size` to find the exact array index.
3. **Storage**: We store the key-value pair at that index. If another key maps to the same index, a **Collision** occurs (handled typically via chaining with linked lists or open addressing).

# Common Pitfalls

<Warning>
- **Modifying Mutable Keys:** Never use mutable objects (like lists or other maps) as keys. If the object changes after being inserted, its hash code changes, and you'll lose the value in the map!
- **C++ unordered_map Worst-Case Hacks:** In competitive programming, attackers can feed specific test cases to cause O(N) worst-case collisions in `unordered_map`. Use `map` (which is a Red-Black Tree, O(log N)) or a custom hash function if you encounter TLE.
- **Null Values in Java:** `HashMap` allows one `null` key and multiple `null` values. However, `ConcurrentHashMap` and `Hashtable` do NOT allow `null` keys or values.
</Warning>
