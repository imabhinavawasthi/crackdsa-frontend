# Theory & Concepts

The standard Euclidean algorithm only computes the Greatest Common Divisor (GCD) of two numbers $A$ and $B$. However, sometimes we need more information.

**Bézout's Identity** states that for any two integers $A$ and $B$, there exist integers $X$ and $Y$ such that:
$A \cdot X + B \cdot Y = GCD(A, B)$

The **Extended Euclidean Algorithm** not only finds the GCD, but it also finds these coefficients $X$ and $Y$. 

### Why is this useful?
The primary use of the Extended Euclidean Algorithm in Competitive Programming and DSA is to find the **Modular Multiplicative Inverse**. 
If $GCD(A, M) = 1$, then:
$A \cdot X + M \cdot Y = 1$
Taking modulo $M$ on both sides:
$A \cdot X \equiv 1 \pmod M$

Thus, the coefficient $X$ is the modular inverse of $A$ modulo $M$!

### The Math Behind It
At the base case of our recursion (when $B = 0$), we know $GCD = A$.
At this point, the equation $A \cdot X + B \cdot Y = A$ is trivially satisfied if $X = 1$ and $Y = 0$.

As the recursion unwinds back to the top, we can update $X$ and $Y$ using the results from the child call ($X_1, Y_1$):
- $X = Y_1$
- $Y = X_1 - \lfloor \frac{A}{B} \rfloor \cdot Y_1$

# Code Implementation

Because we need to return three values (the GCD, X, and Y), implementation varies slightly by language.

<CodeBlock
  cpp="// C++ Implementation
#include <iostream>
using namespace std;

// Returns the GCD, and sets x and y via pass-by-reference
int extendedGCD(int a, int b, int &x, int &y) {
    if (b == 0) {
        x = 1;
        y = 0;
        return a;
    }
    
    int x1, y1;
    int d = extendedGCD(b, a % b, x1, y1);
    
    x = y1;
    y = x1 - y1 * (a / b);
    
    return d;
}"
  java="// Java Implementation
class MathUtils {
    // Java doesn't have pass-by-reference for primitives,
    // so we return an array: [gcd, x, y]
    public static int[] extendedGCD(int a, int b) {
        if (b == 0) {
            return new int[]{a, 1, 0};
        }
        
        int[] result = extendedGCD(b, a % b);
        int gcd = result[0];
        int x1 = result[1];
        int y1 = result[2];
        
        int x = y1;
        int y = x1 - y1 * (a / b);
        
        return new int[]{gcd, x, y};
    }
}"
  python="# Python Implementation
def extended_gcd(a, b):
    if b == 0:
        # Returns gcd, x, y
        return a, 1, 0
        
    gcd, x1, y1 = extended_gcd(b, a % b)
    
    x = y1
    y = x1 - y1 * (a // b)
    
    return gcd, x, y"

# Common Pitfalls

<Warning>
- **Handling Pass-by-Reference in Java/Python**: Unlike C++, Java and Python do not support pass-by-reference for primitive integers. You must return a tuple or an array to propagate the updated $X$ and $Y$ values up the call stack.
- **Negative Modulo**: When using Extended GCD to find a modular inverse, the resulting $X$ might be negative. You must adjust it: `x = (x % M + M) % M`.
</Warning>
