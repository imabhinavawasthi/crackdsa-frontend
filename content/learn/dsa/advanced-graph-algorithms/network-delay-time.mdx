# Theory & Concepts
The **Network Delay Time** problem is a classic application of the single-source shortest path algorithms. Given a network of `n` nodes, labeled from `1` to `n`, and a list of directed edges `times` where `times[i] = (u, v, w)` representing the time `w` it takes for a signal to travel from node `u` to node `v`. 

We start sending a signal from a given node `k`. The goal is to determine the minimum time it takes for all `n` nodes to receive the signal. If it's impossible for all nodes to receive the signal, we return `-1`.

### Core Intuition
This problem directly maps to finding the shortest path from a source node (`k`) to all other nodes. The "delay time" to reach any node is the shortest distance from `k` to that node. 
Once the shortest paths to all nodes are computed, the time for the *last* node to receive the signal is simply the maximum of these shortest paths. Thus, Dijkstra's Algorithm is the perfect tool for this problem, as all edge weights (times) are non-negative.

from collections import defaultdict

class Solution:
    def networkDelayTime(self, times: list[list[int]], n: int, k: int) -> int:
        adj = defaultdict(list)
        for u, v, w in times:
            adj[u].append((v, w))
            
        pq = [(0, k)]
        dist = {i: float('inf') for i in range(1, n + 1)}
        dist[k] = 0
        
        while pq:

# Common Pitfalls
<Warning>
- **1-Based Indexing:** The nodes are numbered from `1` to `n`. Make sure to initialize the arrays with size `n + 1` to prevent `IndexOutOfBounds` exceptions.
- **Disconnected Components:** Don't forget to check if there are any nodes that remain at `infinity` after Dijkstra finishes. If so, return `-1`.
- **Finding Maximum Time:** The answer isn't the distance to just a specific node, but the maximum distance across all nodes from the source.
</Warning>
