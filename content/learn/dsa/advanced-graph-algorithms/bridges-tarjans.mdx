# Theory & Concepts
A **Bridge** (or cut edge) is an edge in a graph whose removal increases the number of connected components. In network routing, bridges represent critical connections whose failure isolates parts of the network.

**Tarjan's Algorithm** for finding bridges uses a single Depth First Search (DFS) pass and maintains two arrays:
1. `tin[u]` (Time In): The timestamp when node `u` was first visited.
2. `low[u]` (Lowest Time): The lowest timestamp reachable from node `u` (including itself) using any path that goes down the DFS tree, and at most one back-edge (an edge pointing to an ancestor).

During DFS from $u$ to a neighbor $v$:
- If $v$ is already visited (and is not the parent), it's a back-edge. Update `low[u] = min(low[u], tin[v])`.
- If $v$ is unvisited, we traverse it and then update `low[u] = min(low[u], low[v])`. 
- **Bridge Condition:** After traversing $v$, if `low[v] > tin[u]`, it means the only way to reach $v$ (and its descendants) from $u$ is via the edge $(u, v)$. Therefore, $(u, v)$ is a bridge.

# Common Pitfalls
<Warning>
- **Back-edge Update:** When a visited neighbor is encountered, update using `tin[it]` (the time the neighbor was visited), not `low[it]`. Using `low` is mathematically flawed for bridges.
- **Skipping Parent:** Do not forget `if (it == parent) continue;`. Otherwise, the algorithm considers the immediate incoming edge as a valid cycle.
</Warning>
