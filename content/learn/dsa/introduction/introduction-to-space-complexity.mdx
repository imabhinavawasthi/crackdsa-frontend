# Theory & Concepts
When designing software, execution speed is only half the battle. High-performance systems are also bounded by **Memory (RAM)**. **Space Complexity** is the mathematical representation of how the total memory allocated by an algorithm grows as the input size `N` scales to infinity.

---

### 1. Total Space vs. Auxiliary Space
It is critical to distinguish between these two terms:
1.  **Total Space Complexity:** The entire memory footprint of the program, which includes the memory used to store the input data itself, plus any extra space declared.
2.  **Auxiliary Space Complexity:** The **extra or temporary memory** allocated by the algorithm to solve the problem, excluding the input data.

*   **SDE Standard:** In interviews, when asked for 'Space Complexity', recruiters are almost always looking for **Auxiliary Space Complexity**. They want to know how much *extra* memory your specific algorithm demands beyond the inputs it was given.

---

### 2. Common Space Complexity Tiers
*   **Constant Space: `O(1)`**
    *   The algorithm only allocates a few primitive variables (e.g., counters, indexes, temp sums) that do not depend on the input size `N`.
    *   *Example:* Iterative linear search, swapping two numbers.
*   **Linear Space: `O(N)`**
    *   The algorithm allocates a data structure (like an array, list, set, or map) that grows proportionally to the input size `N`.
    *   *Example:* Creating a duplicate array, copying elements to a Hash Set for O(1) lookup.
*   **Quadratic Space: `O(N^2)`**
    *   The algorithm allocates a two-dimensional grid or matrix of size `N * N`.
    *   *Example:* Declaring an adjacency matrix to model a graph of `N` nodes.

# Common Pitfalls
<Warning>
- **Confusing Total Space with Auxiliary Space:** Stating that a function takes O(N) space because the input array has size N. Remember, auxiliary space only counts the *extra* memory allocated by your algorithm.
- **Forgetting Call Stack Overhead:** Neglecting the stack frame memory of recursive calls. If your recursion goes N levels deep, your space complexity is O(N), not O(1)!
- **Ignoring String Operations:** Assuming string modifications are O(1). In many languages (like Java and Python), strings are immutable. Any modification (like appending inside a loop) creates a brand new string in memory, consuming linear space!
</Warning>
