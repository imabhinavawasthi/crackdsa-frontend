# Theory & Concepts
In software engineering, **efficiency** is not an optional polish; it is a core system requirement. At small scales (e.g., an array of 100 elements), a brute-force O(N^2) algorithm and an optimized O(N) algorithm both execute in a fraction of a millisecond. However, as inputs scale to production levels, this difference determines whether an application runs smoothly or crashes under load.

### 1. Brute Force vs. Optimized Solutions
A brute-force solution is the most straightforward, obvious approach to solving a problem. It usually involves checking every single possibility, which often leads to nested loops and quadratic O(N^2) or exponential O(2^N) runtime. 

An optimized solution, on the other hand, uses clever data structures or mathematical insights to reduce redundant operations, achieving linear O(N) or logarithmic O(log N) runtime.

### 2. The Scale Test: O(N^2) vs. O(N)
Let's see what happens as the input size N increases, assuming a standard CPU that executes **10^8 operations per second**:
*   **For N = 100:**
    *   O(N) operations: 100 (Instantaneous: ~0.000001 seconds)
    *   O(N^2) operations: 10,000 (Instantaneous: ~0.0001 seconds)
*   **For N = 10,000:**
    *   O(N) operations: 10,000 (Instantaneous: ~0.0001 seconds)
    *   O(N^2) operations: 100,000,000 (Noticeable delay: ~1 second)
*   **For N = 100,000:**
    *   O(N) operations: 100,000 (Instantaneous: ~0.001 seconds)
    *   O(N^2) operations: 10,000,000,000 (**System hangs:** ~100 seconds / 1.6 minutes!)
*   **For N = 1,000,000:**
    *   O(N) operations: 1,000,000 (Fast: ~0.01 seconds)
    *   O(N^2) operations: 1,000,000,000,000 (**Server Crashes:** ~10,000 seconds / 2.7 hours!)

This is why a brute-force approach is unacceptable in production environments. Choosing the right algorithm can be the difference between a responsive system and a crashed server.

bool hasDuplicateBrute(const std::vector<int>& nums) {
    for (size_t i = 0; i < nums.size(); i++) {
        for (size_t j = i + 1; j < nums.size(); j++) {
            if (nums[i] == nums[j]) return true;
        }
    }
    return false;
}

// 2. Optimized Approach: O(N) time, O(N) space
bool hasDuplicateOptimized(const std::vector<int>& nums) {
    std::unordered_set<int> seen;
    for (int num : nums) {
        if (seen.count(num)) return true;
        seen.insert(num);
    }
    return false;

# Common Pitfalls
<Warning>
- **Premature Optimization:** Writing overly complex code to optimize a step that executes on very small inputs. Use the constraints to guide your optimization choices!
- **Neglecting Space Complexity:** Designing a solution that is incredibly fast but uses so much memory it causes Out-Of-Memory (OOM) failures.
- **Hidden Complexities:** Assuming a line of code is O(1) when it secretly performs a linear scan (e.g., calling `.indexOf()` inside a loop).
</Warning>
