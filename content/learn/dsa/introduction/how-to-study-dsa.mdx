# Theory & Concepts
Many students study DSA by watching hours of videos without writing a single line of code, or by copying solutions the moment they get stuck. This creates an **illusion of competence**—you understand the solution when someone else explains it, but you cannot reproduce it from scratch. To study effectively, you must balance active practice, conceptual understanding, and systematic revision.

### 1. The Theory vs. Practice Balance
A common pitfall is spending too much time on either extreme. The ideal split is **30% Theory and 70% Practice**:
*   **Theory (30%):** Learn the structural mechanics, memory layouts, and basic operations (e.g., how a Binary Search Tree balances itself or how a Hash Map handles collisions).
*   **Practice (70%):** Solve problems yourself on an editor. Write out code line-by-line, compile it, make mistakes, debug them, and optimize your solutions.

### 2. The 30-Minute Sticking Rule
When practicing coding challenges, set a timer:
*   **0 to 15 Mins:** Analyze constraints, draw diagrams, write pseudocode, and dry-run.
*   **15 to 30 Mins:** Attempt to code and pass test cases.
*   **If stuck after 30 mins:** Do not copy the solution. Look for small hints (e.g., 'Try using Two Pointers' or 'Can a HashMap store prior values?').
*   **If completely stuck after 45 mins:** Read the editorial solution carefully, close it, wait 30 minutes, and then write the code from scratch on your own without looking back at the solution.

### 3. Spaced Repetition & Revision
Solving a hard problem once does not mean you have mastered it. If you do not revisit it, you will likely forget it within a month.
*   **The Cheat Sheet:** Document the core trick or pattern behind every hard problem you solve (e.g., 'Use prefix sum to find subarray equals K in O(N)').
*   **Review Cadence:** Re-attempt hard and medium problems you struggled with after **3 days**, then **7 days**, and then **30 days**.

# Common Pitfalls
<Warning>
- **Tutorial Hell:** Spending all your time watching tutorials without writing any code. The only way to learn coding is by coding.
- **Copying & Pasting:** Copy-pasting solutions to pass tests. This prevents you from building the muscle memory needed to debug code under pressure.
- **Grinding Without Direction:** Solving 500 easy LeetCode problems instead of systematically moving to medium and hard problems.
</Warning>
