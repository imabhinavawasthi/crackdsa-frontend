# Theory & Concepts
To evaluate code efficiency, you must analyze its loop structures. Loops control how many times computational instructions execute. Below are the four essential loop patterns you will encounter.

---

### 1. Single Loops: `O(N)`
If a loop iterates from `0` to `N` with constant increments, it executes `N` times, resulting in a linear **`O(N)`** time complexity.
```cpp
for (int i = 0; i < n; i++) {
    // Constant O(1) operations
}
```

### 2. Nested Loops: `O(N^2)`
When a loop is placed inside another loop, the total number of operations is the **product** of the iterations of both loops. If the outer loop runs `N` times and the inner loop runs `N` times, the complexity is `N * N = O(N^2)`.
```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        // O(1) operations run N * N times
    }
}
```
*   **The Triangular Variant:** What if the inner loop depends on the outer loop index? (e.g., `for (int j = 0; j < i; j++)`).
    *   The total iterations are `1 + 2 + 3 + ... + N = N(N + 1)/2`.
    *   Asymptotically, this simplifies to **`O(N^2)`** because we drop the constant division `/2` and focus on the dominant term.

### 3. Multiple Sequential Loops: `O(N + M)`
If loops run one after another, their complexities are **added**. It is a common beginner mistake to multiply these.
```cpp
for (int i = 0; i < n; i++) { /* O(N) work */ }
for (int j = 0; j < m; j++) { /* O(M) work */ }
```
*   The total time complexity is **`O(N + M)`** (or simply `O(N)` if `N == M`).

### 4. Index Multiplication/Division Loops: `O(log N)`
If a loop index is multiplied or divided by a factor in each step, the search space is cut proportionally, leading to a logarithmic **`O(log N)`** complexity.
```cpp
for (int i = 1; i < n; i = i * 2) {
    // Runs log2(N) times
}
```

# Visual Representation
```
SINGLE LOOP O(N):
  i = 0 -> 1 -> 2 -> 3 -> ... -> N-1  (Linear progression)

NESTED LOOP O(N^2):
  i = 0  =>  j = 0, 1, 2, ..., N-1
  i = 1  =>  j = 0, 1, 2, ..., N-1   (Square grid pattern)
  i = N-1 =>  j = 0, 1, 2, ..., N-1

LOGARITHMIC LOOP O(log N):
  i = 1 -> 2 -> 4 -> 8 -> 16 -> 32 -> ... -> N (Doubling step)
```

# Common Pitfalls
<Warning>
- **Multiplying Sequential Loops:** Confusing sequential loops with nested loops and stating the complexity is `O(N * M)` instead of `O(N + M)`.
- **Misidentifying Logarithmic Loops:** Assuming that any loop incrementing by 2 (e.g., `i = i + 2`) is logarithmic. This is still linear `O(N)`. Logarithmic loops must scale *multiplicatively* or *divisively* (e.g., `i = i * 2` or `i = i / 2`).
- **Ignoring Inner Method Complexity:** Assuming an inner function call is O(1) when it secretly contains its own linear scan, making the overall complexity O(N^2) instead of O(N).
</Warning>
