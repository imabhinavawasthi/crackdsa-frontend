# Theory & Concepts
To design scalable software, you must know the complexities of standard data layouts and algorithms. Below is a high-density reference sheet detailing the time and space complexities of core data structures, common operations, and sorting algorithms.

---

### 1. Data Structure Complexities
This table compares the average and worst-case time complexities of fundamental data structures:

```
+------------------+-------------------------+-------------------------+
| Data Structure   | Access / Search Time    | Insertion / Deletion    |
+------------------+-------------------------+-------------------------+
| Array / Vector   | O(1)   / O(N)           | O(N)   / O(N)           |
| Linked List      | O(N)   / O(N)           | O(1)   / O(1)           |
| Hash Map / Set   | O(1)   / O(1)  [Avg]    | O(1)   / O(1)  [Avg]    |
| Stack / Queue    | O(N)   / O(N)           | O(1)   / O(1)           |
| Binary Srch Tree | O(log N)/ O(log N)[Avg] | O(log N)/ O(log N)[Avg] |
+------------------+-------------------------+-------------------------+
```

*   **Note on Hash Maps:** Worst-case lookup can degrade to `O(N)` if many hash collisions occur, but it averages `O(1)` under standard load factor management.
*   **Note on Trees:** Worst-case lookup in a standard Binary Search Tree can degrade to `O(N)` if the tree becomes completely unbalanced (skewed). Balanced trees (like AVL or Red-Black Trees) guarantee `O(log N)` search time.

---

### 2. Sorting Algorithm Complexities
This table compares standard sorting algorithms:

```
+------------------+------------------+------------------+------------------+
| Sorting Algo     | Best Time        | Average Time     | Worst Time       |
+------------------+------------------+------------------+------------------+
| Merge Sort       | O(N log N)       | O(N log N)       | O(N log N)       |
| Quick Sort       | O(N log N)       | O(N log N)       | O(N^2)           |
| Heap Sort        | O(N log N)       | O(N log N)       | O(N log N)       |
| Bubble Sort      | O(N)             | O(N^2)           | O(N^2)           |
| Insertion Sort   | O(N)             | O(N^2)           | O(N^2)           |
+------------------+------------------+------------------+------------------+
```

*   **Space footprints:**
    *   **Merge Sort:** `O(N)` (requires extra memory to merge arrays).
    *   **Quick Sort:** `O(log N)` (due to recursive call stack depth).
    *   **Heap Sort / Bubble / Insertion:** `O(1)` (sorts in-place, highly space-efficient).

# Common Pitfalls
<Warning>
- **Assuming Linked List search is O(1):** Linked list *insertion* at a known node pointer is O(1), but *finding* that node requires a linear O(N) search from the head.
- **Relying on QuickSort Worst-Case:** Stating that QuickSort is always O(N log N). It degrades to O(N^2) if the pivot is chosen poorly (e.g. sorted arrays without randomized pivots).
- **Ignoring HeapSort Space Optimization:** Overlooking HeapSort's O(1) space advantage over MergeSort's O(N) space when working on memory-constrained systems.
</Warning>
