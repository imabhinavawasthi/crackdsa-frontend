# Theory & Concepts
Recursive algorithms solve problems by calling themselves with smaller inputs. Because they do not use standard loops, we cannot analyze them by counting simple iterations. Instead, we use two key concepts: **Recursion Trees** and **Stack Depth**.

---

### 1. Stack Depth & Space Complexity
Every time a function calls itself, the computer allocates a block of memory called a **stack frame** on the **Call Stack**. This frame stores the function's local variables and return address.
*   **The Rule of Stack Space:** The space complexity of a recursive algorithm is proportional to the **maximum depth** of the recursion tree (the maximum number of active frames on the stack at any given time), not the total number of calls.
*   If a function calls itself `N` times sequentially (e.g., counting down from `N` to `0`), the maximum depth is `N`, resulting in an **`O(N)`** auxiliary space footprint.

### 2. Tracing the Recursion Tree
To calculate the time complexity, we draw a **Recursion Tree** representing all recursive calls. We evaluate:
1.  **Branching Factor (B):** The number of recursive calls made inside each function execution.
2.  **Tree Depth (D):** The number of times we can divide the problem before hitting the base case.
3.  **Work per Node (W):** The constant or linear work done inside a single call (excluding the recursive calls).

*   **Total Time Complexity = Total Nodes * Work per Node.**

---

### 3. Example 1: Linear Recursion (Factorial)
```python
def factorial(n):
    if n <= 1: return 1
    return n * factorial(n - 1)
```
*   **Branching:** 1 call per execution.
*   **Depth:** `N` levels.
*   **Total Work:** `N` nodes * `O(1)` work = **`O(N)`** time.
*   **Space:** Maximum stack depth is `N`, so **`O(N)`** auxiliary space.

---

### 4. Example 2: Exponential Recursion (Fibonacci)
```python
def fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)
```
*   **Branching:** 2 calls per execution.
*   **Depth:** `N` levels.
*   **Total Nodes:** Each level doubles the number of nodes: `1 + 2 + 4 + 8 + ... + 2^N`.
*   **Total Work:** `2^N` nodes * `O(1)` work = **`O(2^N)`** exponential time.
*   **Space:** The call stack only tracks one path from root to leaf at a time. The maximum depth is `N`, so **`O(N)`** auxiliary space.

# Common Pitfalls
<Warning>
- **Ignoring Stack Space:** Assuming a recursive algorithm uses `O(1)` space because it doesn't declare new variables. The Call Stack itself consumes `O(N)` memory!
- **Overestimating Space Complexity:** Assuming the space complexity is proportional to the total number of recursive nodes (e.g. `O(2^N)` for Fibonacci). The stack only holds *active* frames along the current search path, which is bounded by the tree's height, `O(N)`.
- **Infinite Recursion:** Forgetting to define a proper base case, leading to infinite self-calls and a `StackOverflowError` crash.
</Warning>
