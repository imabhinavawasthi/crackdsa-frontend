# Theory & Concepts
Before building a house, an architect drafts a blueprint. Similarly, before writing complex algorithms, a software engineer creates a logical blueprint. **Flowcharts** and **Pseudocode** are the two primary tools used to plan, communicate, and structure computational logic before writing concrete code.

### 1. Algorithmic Thinking
Algorithmic thinking is the process of defining a clear sequence of steps to solve a problem. It requires:
1.  **Decomposition:** Breaking a task down into smaller, sequential steps.
2.  **Control Flow:** Deciding when to execute a step (sequence), when to choose between alternatives (selection/conditionals), and when to repeat a step (iteration/loops).

### 2. What is a Flowchart?
A flowchart is a visual representation of an algorithm. It uses standard geometric shapes connected by arrows to show the flow of control:
*   **Oval (Terminal):** Represents the `Start` and `End` of the algorithm.
*   **Parallelogram (Input/Output):** Represents reading input data or printing output results.
*   **Rectangle (Process):** Represents mathematical operations, assignments, or computations (e.g., `sum = a + b`).
*   **Diamond (Decision):** Represents conditional branches (e.g., `Is x > 0?`). It always has at least two exit paths (`Yes` and `No`).

### 3. What is Pseudocode?
Pseudocode is a detailed, informal description of an algorithm written in plain English, structured like code. It has no strict syntax rules, making it language-agnostic:
*   Use indentation to show scope (e.g., inside loops or conditional blocks).
*   Use descriptive action verbs like `Read`, `Compute`, `Initialize`, `Loop`, `If`, `Else`, and `Return`.
*   Avoid language-specific constructs like pointers or system calls.

                    (Yes)        (No)

                      v             v

# Common Pitfalls
<Warning>
- **Writing Language-Specific Pseudocode:** Including language-specific keywords like `std::vector<int>` or `ArrayList` in pseudocode. Keep it clean and language-agnostic!
- **Infinite Loops:** Designing a loop in a flowchart or pseudocode without a clear termination condition. Always ensure your loops eventually exit.
- **Vague Steps:** Writing steps like 'Solve the subproblem' without explaining *how*. Every step must be precise and executable.
</Warning>
