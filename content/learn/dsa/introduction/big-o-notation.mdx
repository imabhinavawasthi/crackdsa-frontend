# Theory & Concepts
In technical interviews and production design, we use **Big O Notation** as the standard notation to express computational complexity. Big O formally describes the mathematical **upper bound** of an algorithm's growth rate.

### 1. Formal Mathematical Definition
Formally, we write `f(N) = O(g(N))` if there exist positive constants `c` and `n0` such that:
`0 <= f(N) <= c * g(N)` for all `N >= n0`.

In simple English:
*   `f(N)` is the actual step count of your code.
*   `g(N)` is the simplifying complexity class (like `N` or `N^2`).
*   This definition states that once the input size `N` grows past a threshold (`n0`), the actual steps `f(N)` will *never* exceed `c * g(N)`. It establishes an absolute ceiling on runtime.

### 2. The Worst-Case Benchmark
Algorithms can perform differently depending on the structure of the input:
*   **Best Case (Big Omega - Ω):** The absolute fastest runtime. (e.g., searching for `5` in an array where the first element is `5` takes `O(1)` operations).
*   **Average Case (Big Theta - Θ):** The expected runtime over random inputs.
*   **Worst Case (Big O - O):** The maximum possible operations. (e.g., searching for `5` in an array where `5` is at the very end or not present at all takes `O(N)` operations).

**Why we focus on Worst Case:**
1.  **Guarantees:** It provides a solid performance guarantee. If your code is `O(N)`, you can confidently promise that it will never hang or time out beyond that linear limit.
2.  **Real-world Safety:** Systems crash when they hit worst-case scenarios, not when they hit best-case ones. We must design for resilience.

### 3. Rules of Asymptotic math
1.  **Drop Constant Multipliers:** `O(5N)` simplifies to `O(N)`. At infinity, a factor of 5 is negligible.
2.  **Keep the Dominant Term:** `O(N^2 + 100N + 500)` simplifies to `O(N^2)`. As `N` approaches infinity, `N^2` completely dwarfs `100N` and `500`.

# Common Pitfalls
<Warning>
- **Confusing Big-O and Average Case:** Assuming Big-O automatically represents average runtime. Big-O represents the *worst* possible outcome.
- **Keeping Constants in Final Answers:** Stating that a loop is `O(2N)` or `O(N/2)`. Always simplify constants to express clean complexity classes!
- **Overlooking Hidden Code Steps:** Assuming built-in library functions (like string concatenation or array containment checks) are O(1) when they secretly scale linearly.
</Warning>
