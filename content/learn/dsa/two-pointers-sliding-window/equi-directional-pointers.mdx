# Theory & Concepts
The **Equi-Directional Pointers** pattern (often called Slow and Fast Pointers, though distinct from cycle detection) is a variation of the Two Pointers technique where both pointers start at the same side of the array and move in the same direction, but at different speeds or based on different conditions.

This technique is predominantly used for **in-place array modifications**, such as removing duplicates from a sorted array, moving all zeros to the end, or filtering out specific elements, all while maintaining $O(1)$ space complexity.

### The Core Intuition
Imagine you have an array and you need to filter it. Instead of creating a new array to store the filtered results (which takes $O(N)$ space), you can conceptually divide the original array into two regions:
1. **Processed Region:** `[0, slow - 1]`. This region contains the final, correct elements.
2. **Unprocessed Region:** `[fast, N - 1]`. This region contains elements you haven't looked at yet.

The `fast` pointer acts as an explorer, examining every element one by one. The `slow` pointer acts as a gatekeeper. Whenever the `fast` pointer finds an element that *should* be kept, it hands it to the `slow` pointer. The `slow` pointer writes the element to its current position and then increments.

By the time the `fast` pointer reaches the end of the array, the processed region `[0, slow - 1]` contains the entire final result. The length of the new valid array is simply `slow`.

# Code Implementation

<CodeBlock
  cpp="class Solution {
public:
    // Example: Remove Duplicates from Sorted Array
    int removeDuplicates(vector<int>& nums) {
        if (nums.empty()) return 0;
        
        // 'slow' points to the index where the NEXT unique element should be written
        int slow = 1; 
        
        // 'fast' explores the array to find new unique elements
        for (int fast = 1; fast < nums.size(); fast++) {
            // If we find a new unique element
            if (nums[fast] != nums[fast - 1]) {
                nums[slow] = nums[fast]; // Write it to the 'slow' index
                slow++;                  // Increment the gatekeeper
            }
        }
        
        return slow; // The length of the array without duplicates
    }
};"

# Common Pitfalls
<Warning>
- **Pointer Initialization:** A common mistake is starting both `slow` and `fast` at `0`. In 'remove duplicates', the first element is always unique by definition, so we start both at `1` and compare `fast` with `fast - 1`. 
- **Overwriting Data Too Early:** If `slow` ever advances past `fast`, you would be overwriting unexamined data. This algorithm relies on the invariant that `slow <= fast` at all times.
- **Returning the Array vs. Length:** In-place modification problems often require returning the *new length* of the valid portion of the array, not the array itself. The elements past the new length don't matter.
</Warning>
