# Theory & Concepts
The **Variable Size Sliding Window** pattern is used to find the longest or shortest contiguous subarray (or substring) that strictly meets a specific condition (e.g., sum $\le S$, exactly $K$ distinct characters).

### The Intuition
Instead of fixing the window size, the window dynamically expands and contracts to satisfy the problem's constraints.
- **Expand:** We move the `right` pointer to add elements to our window until the condition is broken.
- **Shrink:** Once the condition is violated, we move the `left` pointer to remove elements until the condition is satisfied again.

### Core Mechanics
1. Initialize `left` and `right` to 0.
2. Maintain some state for the current window (e.g., running sum, frequency map).
3. Expand by incrementing `right` and updating the state.
4. Use a `while` loop to shrink the window from the `left` as long as the state is invalid.
5. Update the longest (or shortest) length recorded whenever the state is valid.

This ensures an $O(N)$ time complexity because both `left` and `right` pointers traverse the array exactly once, moving in only one direction.

public:
    int longestSubarrayWithSum(vector<int>& arr, int target) {
        int left = 0;
        int current_sum = 0;
        int max_len = 0;
        
        for (int right = 0; right < arr.size(); right++) {
            current_sum += arr[right];
            
            // Shrink the window while the condition is violated
            while (current_sum > target && left <= right) {
                current_sum -= arr[left];
                left++;
            }
            
            // Check if we hit the target sum
            if (current_sum == target) {
                max_len = max(max_len, right - left + 1);
            }
        }
        
        return max_len;
    }
};"

# Common Pitfalls
<Warning>
- **Updating the answer at the wrong time:** Make sure to update your `max_len` or `min_len` variable only when the window is valid.
- **Negative Numbers:** The standard variable sliding window using a sum constraint only works if all numbers are non-negative. If negative numbers are involved, the window might become valid again by expanding, requiring a HashMap (Prefix Sum) approach instead.
</Warning>
