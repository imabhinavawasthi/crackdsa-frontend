# Theory & Concepts
The **3Sum and 4Sum** problems are classic extensions of the Two Sum problem. While a Hash Map is often the best solution for Two Sum, applying Hash Maps to 3Sum or 4Sum often results in complex logic to avoid duplicate triplets/quadruplets and requires $O(N)$ extra space.

The elegant, optimal solution relies on **Sorting** the array first, and then using nested loops combined with the **Opposite Directional Pointers** pattern.

### The Core Intuition (3Sum)
To find three numbers that sum to 0 ($A + B + C = 0$), we can iterate through the array, fixing the first number $A$ at index `i`. 
Now, our problem reduces to finding two numbers $B$ and $C$ in the remaining subarray `[i+1, N-1]` such that $B + C = -A$. This is exactly the **Two Sum II** problem!

1. **Sort the array:** This allows us to use Opposite Directional Pointers and makes skipping duplicates trivial.
2. **Fix `A`:** Iterate `i` from $0$ to $N-3$.
3. **Two Pointers for `B` and `C`:** Initialize `left = i + 1` and `right = N - 1`. Move them towards each other just like in Two Sum II.
4. **Skip Duplicates:** This is the most crucial part. Since the problem usually requires *unique* triplets:
   - If `nums[i] == nums[i-1]`, skip the current `i`.
   - When a valid triplet is found, advance `left` and decrement `right` while skipping any adjacent identical values to prevent duplicate triplets.

### Extending to 4Sum
4Sum ($A + B + C + D = Target$) is the exact same logic, just with one more fixed variable. We use two nested loops to fix `i` and `j`, and then use `left = j + 1` and `right = N - 1` for the remaining two pointers. The time complexity becomes $O(N^3)$.

# Common Pitfalls
<Warning>
- **Duplicate Triplets:** The most common failure in 3Sum is failing to return strictly *unique* triplets. Make sure you skip duplicates for `i`, `left`, AND `right`.
- **Skipping `left` and `right` too early:** Only skip duplicates for `left` and `right` *after* you have found a valid sum and recorded it. If you skip unconditionally, you might miss pairs like `[-1, -1, 2]` if you skip the second `-1`.
- **Integer Overflow in 4Sum:** When adding four integers, the sum can easily exceed the 32-bit integer limit. Cast variables to `long` before adding them in C++ and Java.
</Warning>
