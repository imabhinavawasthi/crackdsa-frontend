# Theory & Concepts
The **Sliding Window Maximum** problem asks us to find the maximum element in every contiguous subarray of size `k` within an array `nums`. This combines a fixed-size sliding window with a monotonic data structure to achieve ultimate efficiency.

### The Intuition
The naive approach recalculates the maximum of `k` elements for every window, resulting in $O(N \times K)$ time. A better approach uses a Max Heap ($O(N \log K)$). But we can achieve $O(N)$ using a **Monotonic Deque** (Double-Ended Queue).

### The Monotonic Deque Strategy
We maintain a deque that stores **indices** of array elements in strictly decreasing order of their corresponding values.
1. When a new element enters the window, it's larger than some elements currently in the deque. Those smaller elements can *never* be the maximum for this or any future window because the new, larger element will leave the window *after* them. Thus, we pop them from the back of the deque.
2. We then push the new element's index to the back.
3. If the index at the front of the deque falls outside our current window boundary `[i - k + 1]`, we pop it from the front.
4. The maximum element for the current window is always at the front of the deque.

public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        vector<int> result;
        deque<int> dq;
        
        for (int i = 0; i < nums.size(); i++) {
            // Remove indices that are out of the current window
            if (!dq.empty() && dq.front() == i - k) {
                dq.pop_front();
            }
            
            // Remove smaller elements from the back as they are useless
            while (!dq.empty() && nums[dq.back()] <= nums[i]) {
                dq.pop_back();
            }
            
            // Add the current element's index
            dq.push_back(i);
            
            // Record the maximum for the window (which is always at the front)
            if (i >= k - 1) {
                result.push_back(nums[dq.front()]);
            }
        }
        
        return result;
    }

class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || k <= 0) return new int[0];
        
        int[] result = new int[nums.length - k + 1];
        Deque<Integer> dq = new ArrayDeque<>();
        
        for (int i = 0; i < nums.length; i++) {
            // Remove indices that are out of the current window
            if (!dq.isEmpty() && dq.peekFirst() == i - k) {
                dq.pollFirst();
            }
            
            // Remove smaller elements from the back as they are useless
            while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[i]) {
                dq.pollLast();
            }
            
            // Add the current element's index
            dq.offerLast(i);
            
            // Record the maximum for the window
            if (i >= k - 1) {
                result[i - k + 1] = nums[dq.peekFirst()];
            }
        }
        
        return result;
    }

# Common Pitfalls
<Warning>
- **Storing Values vs Indices:** Always store indices in the deque, not the values. Storing values makes it impossible to know when an element has fallen out of the sliding window.
- **Strictly Decreasing vs Non-Increasing:** Use strictly decreasing logic (`<=` when popping from back). Popping elements that are equal ensures we don't store redundant indices, maintaining optimal space.
</Warning>
