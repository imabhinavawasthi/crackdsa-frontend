# Theory & Concepts
The **Minimum Window Substring** problem asks us to find the shortest substring in a string `s` that contains all the characters of another string `t` (including duplicates). If no such substring exists, we return an empty string. This is considered the hardest classic Sliding Window problem, but the pattern remains the same.

### The Intuition
We are looking for the shortest substring, meaning we have a **Variable Size Sliding Window** seeking a specific condition (containing all characters of `t`).
1. We first count the required character frequencies from string `t`.
2. We iterate with a `right` pointer, adding characters to our window state and updating our current count of "matching characters" (let's call this `have`).
3. We need `have` to match `need` (the total number of unique characters in `t` required).
4. Once `have == need`, our window is valid! It contains everything. But is it the *shortest*?
5. We shrink the window from the `left` by advancing the `left` pointer. Before advancing, we check if removing the left character breaks the `have == need` condition. We record the substring length before it breaks.
6. We continue expanding and shrinking until the end of string `s`.

# Common Pitfalls
<Warning>
- **Comparing entire HashMaps:** Checking if the current window hashmap contains the target hashmap inside the `while` loop condition takes $O(A)$ where $A$ is the alphabet size, turning $O(N)$ into $O(N \times A)$. Instead, maintain a `formed` counter to track matched unique characters in $O(1)$ time.
- **Handling duplicate characters in `t`:** A target character might appear multiple times in `t`. Your `window_count` must meet or exceed the `target_count` exactly before incrementing `formed`.
</Warning>
