# Theory & Concepts
**Heapify** is the core operation used to maintain the heap property in a binary tree. It takes an array and a specific node index, assuming that the subtrees under that node already satisfy the heap property. It then percolates that node downwards until it finds its correct position.

**Build Heap** is the process of converting an arbitrary, unsorted array into a valid heap. 

### The Naive Approach
A simple way to build a heap from an array of N elements is to start with an empty heap and insert elements one by one. Since each insert takes `O(log N)` time, doing this for N elements yields a time complexity of `O(N log N)`.

### The Optimal Approach (Bottom-Up Heapify)
A much faster way is to use a bottom-up approach. We start from the last non-leaf node (index `(N/2) - 1`) and call `heapify` backwards up to the root (index `0`). By doing this, we guarantee that when we call `heapify` on a node, its left and right subtrees are already valid heaps.

# Common Pitfalls
<Warning>
- Calling `heapify` starting from index `0` downwards. This won't work because `heapify` assumes the subtrees are already valid heaps. You must iterate backwards from the last non-leaf node.
- Passing the wrong array size `n` to the `heapify` function during sorting operations, leading to out-of-bounds access.
</Warning>
