# Theory & Concepts
The **Top K Elements** pattern is a generalized approach for solving any problem that asks you to find the "Top K", "Smallest K", "K Most Frequent", or "K Closest" elements in a given dataset.

Whenever a problem asks for `K` extremums, your immediate thought should be **Heaps**. 

### The Core Strategy
1. **To find the K LARGEST elements:** Use a **Min-Heap** of size K.
2. **To find the K SMALLEST elements:** Use a **Max-Heap** of size K.

Why opposite? If you want the K largest elements, a Min-Heap keeps the smallest of those K elements at the root. If you see a new element larger than the root, it means the root can be discarded, and the new element takes its place. This brilliantly bounds our heap size to exactly `K`.

# Common Pitfalls
<Warning>
- Using a Max-Heap to find the K largest elements and pushing all N elements. This consumes O(N) space and takes O(N log N) time, defeating the optimization.
- Forgetting that the elements remaining in the Min-Heap will be popped in ascending order, not descending order. If the problem requires descending order, reverse the result array.
</Warning>
