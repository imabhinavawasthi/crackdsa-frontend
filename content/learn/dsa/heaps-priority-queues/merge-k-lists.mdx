# Theory & Concepts
**Merge K Sorted Lists** is a classic problem that tests your ability to efficiently manage multiple incoming streams of sorted data. Given an array of `k` linked lists, each sorted in ascending order, the goal is to merge them into a single sorted linked list.

### The Naive Approach
A naive approach would be to collect all nodes into an array, sort the array, and then reconstruct a new linked list. If `N` is the total number of nodes across all `k` lists, this takes `O(N log N)` time and `O(N)` auxiliary space. We can do much better.

### The Min-Heap Approach
Since each list is already sorted, the smallest overall element must be at the head of one of the `k` lists. 
We can maintain a **Min-Heap of size K** to keep track of the current head of each list.
1. Insert the head of all `k` lists into the Min-Heap.
2. Pop the minimum node, append it to our result list.
3. If the popped node has a next node, push that next node into the heap.
4. Repeat until the heap is empty.

    struct CompareNode {

            return p1->val > p2->val;
        }

public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        priority_queue<ListNode*, vector<ListNode*>, CompareNode> minHeap;

            if (node) minHeap.push(node);
        }
        
        ListNode dummy(0);
        ListNode* tail = &dummy;

            ListNode* minNode = minHeap.top();
            minHeap.pop();
            
            tail->next = minNode;
            tail = tail->next;
            
            if (minNode->next) {
                minHeap.push(minNode->next);
            }
        }
        return dummy.next;
    }

# Common Pitfalls
<Warning>
- In Python, `heapq` will try to compare the entire tuple. If two nodes have the same value, it will try to compare the `ListNode` objects, which will throw a `TypeError`. You must include an index or ID to act as a tie-breaker!
- Forgetting to check if `lists` contains null pointers initially. Always skip null nodes before pushing into the heap.
</Warning>
