# Theory & Concepts
Finding the **Kth Largest Element in an Array** is one of the most fundamental heap problems. It forms the basis of the "Top K" pattern.
The problem gives an unsorted array of integers and an integer `k`. The goal is to return the `k`th largest element.

### Intuition
While sorting the array in `O(N log N)` time and simply returning `arr[N-K]` is a valid brute-force approach, we can do better by maintaining a **Min-Heap of size K**.

By pushing elements into a Min-Heap, the smallest element of the heap sits at the root. If we keep the heap size to exactly `k`, then the root will naturally hold the `k`th largest element we've seen so far. If a new element is larger than the root, we pop the root and push the new element.

    public int findKthLargest(int[] nums, int k) {
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();
        for (int num : nums) {
            minHeap.add(num);
            if (minHeap.size() > k) {
                minHeap.poll();
            }
        }
        return minHeap.peek();
    }

# Common Pitfalls
<Warning>
- Using a Max-Heap of size N. While this works, popping K times takes O(K log N) after O(N) build heap. The Min-Heap of size K approach is generally preferred, especially for large streaming data, because space complexity is bounded to O(K).
- Misinterpreting Kth largest for Kth unique largest. Most problems assume duplicates are counted separately unless specified otherwise.
</Warning>
