# Theory & Concepts
The most surprising fact about heaps is that **building a heap from an unsorted array takes `O(N)` time**, not `O(N log N)`. This optimization is highly tested in interviews.

### Why is Build Heap O(N)?
When we perform the bottom-up `heapify` process:
1. Leaf nodes (which make up roughly half the tree, `N/2` nodes) don't need to be heapified at all. They are already valid heaps of size 1.
2. Nodes one level above the leaves (`N/4` nodes) can sift down at most 1 step.
3. Nodes two levels above (`N/8` nodes) can sift down at most 2 steps.
4. Only the root node (1 node) can sift down all `log N` steps.

If we sum the total maximum steps mathematically:
`N/4 * 1 + N/8 * 2 + N/16 * 3 + ...`
This series converges to exactly **`O(N)`**. 

Thus, transforming an arbitrary array in-place into a heap is extremely efficient.

    void heapify(vector<int>& arr, int n, int i) {
        int largest = i;
        int left = 2 * i + 1;
        int right = 2 * i + 2;

        if (left < n && arr[left] > arr[largest])
            largest = left;

        if (right < n && arr[right] > arr[largest])

        if (largest != i) {
            swap(arr[i], arr[largest]);
            heapify(arr, n, largest);
        }
    }

    void buildHeap(vector<int>& arr) {
        int n = arr.size();
        // Start from the last non-leaf node and move up to the root
        for (int i = n / 2 - 1; i >= 0; i--) {
            heapify(arr, n, i);
        }
    }

# Common Pitfalls
<Warning>
- Using `N log N` insertion method instead of the `O(N)` build heap method when initializing a heap from a given array.
- Standard libraries abstract this away (e.g., `heapq.heapify(arr)` in Python, or passing a vector to the `priority_queue` constructor in C++). Make sure you leverage these standard functions in an interview unless asked to implement them manually.
</Warning>
