# Theory & Concepts
The **Task Scheduler** problem asks us to determine the minimum CPU time needed to execute an array of tasks (represented by characters), given a cooling period `n` between two identical tasks.

### Intuition
To minimize idle time, we should always prioritize executing the task with the highest remaining frequency. If we do the most frequent tasks first, we spread them out over time and use less frequent tasks to fill the cooling gaps.

This naturally leads to a **Max-Heap** approach:
1. Count the frequencies of all tasks.
2. Push all non-zero frequencies into a Max-Heap.
3. In each cycle of length `n + 1`, pop tasks from the Max-Heap, execute them (decrement their frequency), and put them in a temporary queue.
4. After the cycle, push the tasks back into the Max-Heap if they still have remaining frequency.
5. Add the time spent in the cycle to a total counter.

# Common Pitfalls
<Warning>
- Implementing the simulation using arrays instead of heaps/queues, leading to a much slower O(N^2) complexity.
- Misunderstanding the cycle length. A cooling time of `n` means `n` *other* operations or idles must occur before the same task can run again, effectively creating a cycle length of `n + 1`.
</Warning>
