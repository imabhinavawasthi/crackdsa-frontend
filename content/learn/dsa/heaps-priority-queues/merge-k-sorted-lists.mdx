# Theory & Concepts
The **Merge K Sorted Lists** pattern is an extension of the classic two-pointer merge approach. While merging 2 lists takes `O(N)` time, extending this to `K` lists naive way would be very slow. Using a Priority Queue (Min-Heap) provides an elegant `O(N log K)` solution.

### How it relates to other concepts
This approach is identical to how the `K-way merge` algorithm works in external sorting, where chunks of data are sorted on disk, and a heap in memory merges them line by line without overflowing RAM.

    ListNode* mergeKLists(vector<ListNode*>& lists) {
        priority_queue<ListNode*, vector<ListNode*>, CompareNode> minHeap;

            if (node) minHeap.push(node);
        }
        
        ListNode dummy(0);
        ListNode* tail = &dummy;
        
        while (!minHeap.empty()) {
            ListNode* minNode = minHeap.top();
            minHeap.pop();
            
            tail->next = minNode;
            tail = tail->next;
            
            if (minNode->next) {
                minHeap.push(minNode->next);
            }
        }
        return dummy.next;
    }

# Common Pitfalls
<Warning>
- In Python, `heapq` will try to compare the entire tuple. If two nodes have the same value, it will try to compare the `ListNode` objects, which will throw a `TypeError`. You must include an index or ID to act as a tie-breaker!
- Forgetting to check if `lists` contains null pointers initially. Always skip null nodes before pushing into the heap.
</Warning>
