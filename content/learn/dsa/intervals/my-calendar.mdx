# Theory & Concepts
The **My Calendar** series on LeetCode tests your ability to dynamically track and query intervals as they are added one by one. Unlike standard interval problems where you receive the entire array of intervals upfront, here you must process a continuous stream of `.book(start, end)` requests.

### The Three Variations
- **My Calendar I**: Return `true` if the new event does *not* overlap with any existing events.
- **My Calendar II**: Return `true` if the new event does not cause a *triple* overlap. Double overlaps are fine!
- **My Calendar III**: Return the *maximum number of overlapping events* (the K-booking) across the entire calendar after every insertion.

### Core Intuition: TreeMap / Sweep Line
For dynamic interval problems, sorting an array every time an element is inserted takes $O(N \log N)$ per insertion, leading to $O(N^2 \log N)$ overall.

Instead, we can use a **TreeMap** (or a Sweep Line array in Python) to maintain a sorted map of timeline events!
- When an event starts at time `S`, we increment the timeline: `map[S]++`
- When an event ends at time `E`, we decrement the timeline: `map[E]--`

By iterating through the keys of this sorted map in chronological order, we can keep a running sum of active events. If the running sum ever violates our constraints (e.g., exceeds 1 for Calendar I, exceeds 2 for Calendar II), we know the booking is invalid.

Let's implement **My Calendar III**, as it generalizes the Sweep Line concept perfectly.

# Common Pitfalls
<Warning>
- **Rollback in I and II**: If a booking is invalid in Calendar I or II, you **must remove the provisional increments** from your map before returning `false`. `map[start]--; map[end]++;`.
- Not using a `TreeMap` / `std::map`. A standard `HashMap` does not maintain sorted keys, so the chronological sweep line will completely fail.
</Warning>
