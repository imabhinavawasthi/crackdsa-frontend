# Theory & Concepts
**The Skyline Problem** is widely considered the ultimate boss battle of the Intervals category. Given the `[left, right, height]` of several buildings, you must output the key points that form the outer silhouette (the skyline) of the city.

### Core Intuition
This requires a sophisticated marriage of two concepts: the **Sweep Line Algorithm** and a **Max-Heap (Priority Queue)**.

1. **Break into Events**: A building `[L, R, H]` has two events. At `L`, the height `H` is *introduced*. At `R`, the height `H` is *removed*. 
2. **Sweep Line**: We process all events from left to right.
3. **Max-Heap for Current Height**: We maintain a Max-Heap of the heights of all currently "active" buildings. The top of the heap is always the highest point of the skyline at the current sweep position.
4. **Detecting Changes**: If processing an event (either adding or removing a building) changes the max value in the heap, a new key point is formed on the skyline!

### The Tricky Tie-Breakers
When multiple events occur at the exact same `X` coordinate:
- If two buildings **start** at the same time, process the **taller** one first (so you don't draw an unnecessary lower point).
- If two buildings **end** at the same time, process the **shorter** one first.
- If one starts and one ends, process the **start** first.
By cleverly encoding start heights as negative numbers and end heights as positive numbers, standard sorting naturally handles all these edge cases!

                prevMaxHeight = currentMaxHeight;
            }
        }

  java="import java.util.*;

class Solution {
    public List<List<Integer>> getSkyline(int[][] buildings) {
        List<int[]> events = new ArrayList<>();
        for (int[] b : buildings) {
            events.add(new int[]{b[0], -b[2]}); // Start: negative height
            events.add(new int[]{b[1], b[2]});  // End: positive height
        }
        
        // Sort by X. If X is same, sort by height (handles all 3 edge cases!)
        Collections.sort(events, (a, b) -> {
            if (a[0] != b[0]) return Integer.compare(a[0], b[0]);
            return Integer.compare(a[1], b[1]);
        });
        
        List<List<Integer>> result = new ArrayList<>();
        // Max-Heap: passing reverse order comparator
        PriorityQueue<Integer> pq = new PriorityQueue<>((a, b) -> b - a);
        pq.offer(0); // Ground level
        
        int prevMax = 0;
        for (int[] event : events) {
            int x = event[0];
            int h = event[1];
            
            if (h < 0) {
                pq.offer(-h); // Add building
            } else {
                pq.remove(h); // Remove building
            }
            
            int currentMax = pq.peek();
            if (currentMax != prevMax) {
                result.add(Arrays.asList(x, currentMax));
                prevMax = currentMax;
            }
        }
        
        return result;
    }

        for L, R, H in buildings:

            while heap[0][1] <= x:

# Common Pitfalls
<Warning>
- Failing to sort tie-breakers correctly. Using `-height` for start events is an ingenious trick that naturally forces the sort to process taller buildings first on exactly identical `X` starts.
- Modifying a heap while iterating. In Python, removing arbitrary elements from a `heapq` breaks the heap invariant, which is why we must use "Lazy Deletion" (popping dead buildings off the top only when we evaluate the top).
</Warning>
