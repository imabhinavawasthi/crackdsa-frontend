# Theory & Concepts
The **Meeting Rooms II** problem is a massive leap forward in interval problems. Given an array of meeting time intervals `[starti, endi]`, you must find the **minimum number of conference rooms required**.

Unlike simply checking for overlaps, we now need to track the *maximum number of overlapping meetings at any single point in time*.

### Core Intuition: Two Main Approaches

1. **Min-Heap (Priority Queue) Approach**:
   - Sort the meetings by start time.
   - Use a Min-Heap to keep track of the *end times* of meetings currently occupying a room. The heap's root always gives the room that frees up the earliest.
   - For every new meeting, check if its start time is `>=` the heap's root (earliest end time). If it is, that room is free! Pop the root and push the new meeting's end time.
   - If it's not free (start time < root), allocate a new room by pushing the new end time to the heap.
   - The heap's size at the end is the number of rooms needed.

2. **Chronological Ordering (Two Pointers) Approach**:
   - Separate the start times and end times into two distinct sorted arrays.
   - Use two pointers: one for starts and one for ends.
   - Iterate through the start times. If `start[s] < end[e]`, a meeting has started before the earliest ending meeting finished, so we need a room.
   - If `start[s] >= end[e]`, a meeting has finished, freeing a room. Move the end pointer.

Both approaches are completely valid and run in $O(N \log N)$ time, but the chronological ordering uses $O(N)$ space more elegantly without needing heap overhead.

                rooms++;

# Common Pitfalls
<Warning>
- If you opt for the Min-Heap approach, don't accidentally push the entire interval into the heap; you only need to push the **end time**.
- Misinterpreting the problem as "finding the maximum number of non-overlapping intervals." This is about the *maximum depth of overlap*, not erasing overlaps!
</Warning>
