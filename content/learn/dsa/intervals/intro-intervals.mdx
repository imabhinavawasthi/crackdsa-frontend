# Theory & Concepts
Welcome to the fascinating world of **Intervals**. This topic is highly prevalent in technical interviews, often manifesting as scheduling problems, calendar applications, or geometric intersections.

An interval is simply a pair of numbers `[start, end]` representing a contiguous range. Problems typically provide a collection of these intervals, and your task is to merge overlapping ones, find intersections, count the maximum overlaps, or insert a new interval into a sorted list.

### The Golden Rule of Intervals
The overarching strategy for almost every interval problem boils down to **sorting**.
If the intervals are not provided in a sorted order, sorting them based on their `start` time (or occasionally `end` time) is your primary directive. Once sorted, processing intervals typically requires a single linear scan, comparing the current interval with the previously processed one to make decisions about overlaps.

Sorting reduces the brute-force complexity from $O(N^2)$ (checking all pairs) to a much more manageable $O(N \log N)$ followed by an $O(N)$ pass.

### Determining Overlaps
To check if two intervals `A = [startA, endA]` and `B = [startB, endB]` overlap (assuming they are sorted so `startA <= startB`), the condition is straightforward:
`startB <= endA`

If this holds true, the intervals intersect. The merged interval would then span `[startA, max(endA, endB)]`.

    // A simple framework to conceptualize processing sorted intervals
    void processIntervals(vector<vector<int>>& intervals) {
        if (intervals.empty()) return;
        
        // Sort intervals based on starting times
        sort(intervals.begin(), intervals.end());
        
        vector<int> currentInterval = intervals[0];
        
        for (int i = 1; i < intervals.size(); i++) {
            if (intervals[i][0] <= currentInterval[1]) {
                // Overlapping condition: start of next is less than or equal to end of current
                // Update current interval's end
                currentInterval[1] = max(currentInterval[1], intervals[i][1]);
            } else {
                // Non-overlapping: current interval is isolated
                // Save currentInterval and move to the next
                currentInterval = intervals[i];
            }
        }
    }
};"

# Common Pitfalls
<Warning>
- Confusing strict and non-strict inequalities. If intervals `[1, 2]` and `[2, 3]` are considered overlapping, use `<=`. If they are not (e.g., leaving a meeting exactly when the next starts), use `<`.
- Modifying the input array `intervals` while iterating through it. This is error-prone. Always maintain a separate list to collect your results.
- Forgetting to add the very last interval to your results list after the loop finishes.
</Warning>
