# Theory & Concepts
The **Insert Interval** problem asks you to insert a new interval into a list of *non-overlapping* and *already sorted* intervals, merging if necessary to maintain the non-overlapping property.

### Core Intuition
Since the given list of intervals is already sorted by start time and contains no overlaps, we do not need an $O(N \log N)$ sorting step. We can achieve an optimal $O(N)$ solution by breaking the problem down into three sequential phases:

1. **Before the overlap**: Any interval in the list that ends *before* the new interval starts has absolutely no chance of overlapping. We can safely add all these intervals directly to our result.
2. **During the overlap (The Merge Phase)**: We iterate through all intervals that overlap with the new interval. An interval overlaps if its start time is less than or equal to the new interval's end time. We continually update the new interval's bounds to encompass all overlapping intervals: `newStart = min(newStart, currentStart)` and `newEnd = max(newEnd, currentEnd)`.
3. **After the overlap**: Once we've moved past all overlapping intervals, we add the merged new interval to our result. Then, we add all remaining intervals in the list, as they are guaranteed to start *after* our merged interval ends.

# Common Pitfalls
<Warning>
- Re-sorting the array. Appending the interval and sorting the whole array results in an $O(N \log N)$ solution, which is suboptimal and a red flag for interviewers.
- Getting stuck on overlap bounds. Remember the clean condition: an interval overlaps if it starts *before or exactly when* the `newInterval` ends, AND it ends *after or exactly when* the `newInterval` starts.
</Warning>
