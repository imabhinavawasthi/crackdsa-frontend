# Theory & Concepts
A **Doubly Linked List** extends the standard Singly Linked List by adding a second pointer, `prev`, which points to the previous node in the sequence. 

This simple addition unlocks a massive performance benefit: **Bidirectional Traversal**. In a singly linked list, deleting a node given only its reference takes $O(N)$ time because you must start from the head to find its preceding node. In a doubly linked list, deletion is purely $O(1)$ because the node itself already knows its predecessor.

**Design Pattern: Sentinel Nodes (Dummy Head & Tail)**
Implementing a Doubly Linked List from scratch is notoriously prone to edge cases (e.g., adding to an empty list, removing the last item). By explicitly instantiating a dummy `head` and a dummy `tail` node right at the start, and connecting them (`head <-> tail`), you ensure that every real data node will always be sandwiched between two existing nodes. This completely eliminates null-pointer exceptions and simplifies the insertion/deletion logic.

# Common Pitfalls
<Warning>
- **Pointer Update Ordering:** When adding a new node, ALWAYS wire the new node's pointers (`newNode.next`, `newNode.prev`) first, before modifying the surrounding nodes. If you break the existing chain too early, you lose your references!
- **Garbage Collection:** In languages without garbage collection (like C++), deleting a node requires explicitly calling `delete node` to prevent memory leaks.
</Warning>
