# Theory & Concepts
**Reverse Nodes in k-Group** is a notoriously difficult Linked List manipulation problem. It combines multiple sub-problems: finding bounds, reversing a local sublist, and flawlessly reconnecting everything to the main chain.

We are tasked with reversing the nodes of a list `k` at a time. If the remaining nodes at the tail are fewer than `k`, they must remain un-reversed.

**Core Mechanism:**
1. Maintain a pointer just *before* the start of the current `k` group (`groupPrev`).
2. Fast-forward `k` nodes to find the end of the group (`kth`). If the end doesn't exist, we break.
3. Keep track of the node just *after* the `k` group (`groupNext`).
4. Perform a standard Linked List reversal tightly bounded between the start of the group and `groupNext`.
5. Wire the reversed segment back to `groupPrev` and `groupNext`.
6. Advance `groupPrev` to prepare for the next batch.

# Common Pitfalls
<Warning>
- **Orphaned Pointers:** During the bounded reversal, you must initialize `prev` to `groupNext` instead of `null`. This prevents disconnecting the tail of the newly reversed group from the un-reversed remainder of the list.
- **Updating the groupPrev:** After one successful reversal, ensure that `groupPrev` is correctly advanced to point to the node that originally started the group (which is now properly positioned at the very end of the reversed cluster).
</Warning>
