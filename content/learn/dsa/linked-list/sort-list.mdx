# Theory & Concepts
Sorting a Linked List in $O(N \log N)$ time poses a unique challenge because, unlike arrays, we lack random access to elements. This restriction makes algorithms like Quick Sort or Heap Sort difficult to implement efficiently.

The most natural fit for sorting a linked list is **Merge Sort**. Merge Sort strictly requires sequential access, dividing the list into two halves, sorting each recursively, and merging them back together. 

The strategy is twofold:
1. **Divide**: Use the Fast and Slow pointer technique to find the middle of the list. Break the list into two disconnected halves.
2. **Conquer**: Recursively sort both halves.
3. **Merge**: Iteratively merge the two sorted sublists using a Dummy Node to simplify edge cases.

# Common Pitfalls
<Warning>
- **Stack Overflow:** Make sure you sever the list into two separate halves by setting `slow.next = null`. Failing to do so will cause infinite recursion and crash your program.
- **Off-By-One Middle Finding:** When using fast/slow pointers, initialize `fast = head.next` instead of `fast = head`. This ensures the slow pointer accurately lands on the first node of the left half's end during an even-length list, guaranteeing the list physically shrinks during the recursion.
</Warning>
