# Theory & Concepts

The **Path Sum** series of problems tests your ability to track running totals as you traverse down a tree. This is a classic application of **Top-Down (Preorder)** traversal.

### Path Sum I (Root to Leaf Check)
You are asked to check if there is a root-to-leaf path that sums to a target. 
- You subtract the current node's value from the target as you go down.
- If you hit a leaf node and `target == node.val`, you return true.

### Path Sum II (Return all Paths)
Instead of just returning true/false, you must return all valid paths.
- You must maintain an array of the current path.
- When backtracking, you must remove the last element from the array to explore other branches (classic backtracking).

### Path Sum III (Any Node to Any Node Downwards)
The path no longer has to start at the root or end at a leaf, but it must go downwards.
- This is elegantly solved using **Prefix Sums** and a HashMap, exactly like the "Two Sum" or "Subarray Sum Equals K" array problems, applied to a tree!

# Common Pitfalls

<Warning>
- **Not Checking for Leaves:** A path MUST end at a leaf. If you just check `if (root == null && targetSum == 0)`, you will get false positives for paths that end at nodes with only one child. Always check `!root.left && !root.right`.
- **Negative Numbers:** Do not assume tree node values are always positive! You cannot prune the search just because `runningSum > target` if negative numbers are present.
</Warning>
