# Theory & Concepts
Serialization is the process of converting a data structure or object into a sequence of bits or string so that it can be stored in a file or memory buffer, or transmitted across a network connection link to be reconstructed later in the same or another computer environment.

For a Binary Tree, serialization means converting the tree into a string. Deserialization is the reverse process: parsing the string back into the original tree structure.

The most common approach is using a **Pre-order Traversal (DFS)**. When we visit a node, we append its value to our string. If the node is null, we append a special marker (like `N` or `#`) to signify the end of a branch. This preserves the exact structure of the tree, allowing us to unambiguously reconstruct it.

### Core Intuition
1. **Serialize (Encode):** Perform a pre-order traversal. Add a delimiter (e.g., `,`) between values. Use `#` for null nodes.
2. **Deserialize (Decode):** Split the string by the delimiter. Use a queue or an iterator. Read values one by one, recursively building the tree top-down, precisely mimicking the pre-order traversal.

# Common Pitfalls
<Warning>
- Forgetting to serialize the `null` pointers. Without them, you cannot determine the tree's structure.
- Not handling negative numbers properly if building a custom string parser instead of using standard split functions.
- Missing delimiters. For values with multiple digits like `12` and `3`, omitting delimiters creates ambiguity (`123`).
</Warning>
