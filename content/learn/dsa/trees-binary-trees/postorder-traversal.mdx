# Theory & Concepts

**Postorder Traversal** is a Depth-First Search (DFS) traversal where the processing of the current node occurs **after** processing its left and right children. The sequence is:
1. Recursively traverse the **Left** subtree.
2. Recursively traverse the **Right** subtree.
3. Visit the **Root** node.

### Why Postorder?
Postorder is considered a **Bottom-Up** approach. You use postorder traversal when the result of a parent node strictly depends on the results of its children. 

Common use cases:
- Calculating the height or depth of a tree.
- Finding the lowest common ancestor (LCA).
- Safely deleting a tree from memory (you must delete children before you delete the parent).

# Common Pitfalls

<Warning>
- **Iterative Implementation Complexity:** The iterative version of Postorder is the hardest of all three DFS traversals because you visit a node twice (once to go to the right child, and once to process the node itself).
- **Infinite Loops:** When implementing iteratively without marking visited nodes, it is very easy to fall into an infinite loop.
</Warning>
