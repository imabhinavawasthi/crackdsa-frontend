# Theory & Concepts

**Inorder Traversal** is a Depth-First Search (DFS) technique where the processing of the current node occurs **between** processing its left and right children. The sequence is:
1. Recursively traverse the **Left** subtree.
2. Visit the **Root** node.
3. Recursively traverse the **Right** subtree.

### The Magic of Inorder in BSTs
The most powerful property of Inorder traversal shines when applied to a **Binary Search Tree (BST)**. Because a BST maintains the property that left children are strictly less than the parent, and right children are strictly greater, **an Inorder traversal of a BST will always process the nodes in strictly sorted (ascending) order**.

Common use cases:
- Validating if a given binary tree is a valid Binary Search Tree.
- Finding the Kth smallest or largest element in a BST.
- Converting a BST to a sorted array or a doubly linked list.

# Common Pitfalls

<Warning>
- **Iterative Stack Logic:** The iterative version of Inorder is tricky. You must traverse down the left side completely, popping and processing nodes, then shifting to the right child.
- **Forgetting Previous Pointer:** When using Inorder to validate a BST, a common mistake is not keeping track of the previously visited node to compare values.
</Warning>
