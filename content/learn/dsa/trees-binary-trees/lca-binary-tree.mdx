# Theory & Concepts

The **Lowest Common Ancestor (LCA)** algorithm is a powerful tool in tree traversal. This lesson focuses on the generalized **Binary Tree** approach (where no ordering property is guaranteed).

### The Mechanics of General LCA
When we don't have a Binary Search Tree (BST), we have no clue whether `p` or `q` is in the left or right subtree. We must perform an exhaustive search. 

We use a **Bottom-Up (Postorder)** recursive strategy:
1. If the current node is null, return null.
2. If the current node is either `p` or `q`, return the current node immediately. (This implicitly covers the rule that a node can be an ancestor of itself).
3. Recursively call LCA on the left and right children.
4. If BOTH the left and right recursive calls return non-null nodes, it means `p` was found in one subtree and `q` in the other. Thus, the *current node* is the Lowest Common Ancestor!
5. If only one call returns a non-null node, we bubble that non-null node up the call stack.

# Common Pitfalls

<Warning>
- **Assuming Both Nodes Exist:** The standard algorithm assumes both `p` and `q` are guaranteed to exist in the tree. If one node might be missing, returning a match early will falsely identify it as the LCA. You would need a separate boolean flag to confirm both were found!
- **Value Matching vs Reference Matching:** Ensure you are comparing the node references (`root == p`), not just the values (`root.val == p.val`), especially if the tree allows duplicate values.
</Warning>
