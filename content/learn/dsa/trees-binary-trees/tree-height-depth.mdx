# Theory & Concepts

Understanding the dimensions of a tree is crucial for analyzing the time and space complexity of tree-based algorithms. The two most fundamental dimensional properties are **Depth** and **Height**.

### Depth of a Node
The **depth** of a node is the number of edges from the root node to that specific node. 
- The depth of the root node is always `0`.
- Depth is calculated in a **top-down** manner.

### Height of a Node
The **height** of a node is the number of edges on the longest path from that node to a leaf.
- The height of a leaf node is always `0`.
- Height is calculated in a **bottom-up** manner.
- The **Height of a Tree** is the height of its root node.

*Note: In some contexts (like LeetCode), height or depth is defined by the number of nodes on the path instead of edges, making a single-node tree have a height/depth of 1.*

# Common Pitfalls

<Warning>
- Using global variables to track the maximum height. It is much cleaner and less error-prone to return the height from the recursive function.
- Forgetting the base case `if (root == null)`, leading to a null pointer exception or infinite recursion.
- Mixing up edge-based and node-based definitions. Always clarify with your interviewer!
</Warning>
