# Theory & Concepts

**Preorder Traversal** is a Depth-First Search (DFS) pattern where the processing of the current node occurs **before** processing its children. The exact sequence is:
1. Visit the **Root** node.
2. Recursively traverse the **Left** subtree.
3. Recursively traverse the **Right** subtree.

### Why Preorder?
Preorder is considered a **Top-Down** approach. It is primarily used when you need to pass data from a parent node down to its children, or when the structure of the tree needs to be recorded or cloned before traversing deeper. 

Common use cases:
- Creating a deep copy (clone) of a tree.
- Serializing a tree (saving it to a string/file) so it can be deserialized later.
- Evaluating expression trees in certain prefix notations.

# Common Pitfalls

<Warning>
- **Iterative Implementation Errors:** While the recursive version is trivial, the iterative version using a stack is harder. A common mistake is pushing the left child before the right child. Because stacks are LIFO, you must push the right child first!
- **State Leakage:** Forgetting to clear or properly scope global variables if the traversal function is called multiple times.
</Warning>
