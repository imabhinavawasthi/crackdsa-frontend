# Theory & Concepts

The **Diameter of a Binary Tree** is the length of the longest path between any two nodes in a tree. This path may or may not pass through the root. The length of a path between two nodes is represented by the number of edges between them.

### The Core Intuition
The longest path through a specific node is simply the sum of the maximum depth of its left subtree and the maximum depth of its right subtree.
`Diameter passing through Node = maxDepth(Node.left) + maxDepth(Node.right)`

Since the true diameter of the tree could be entirely contained within a left or right subtree (and not pass through the main root), we must calculate this sum for *every* node. We can do this efficiently during a standard **Postorder Traversal** (Bottom-Up) where we compute heights.

# Code Implementation

<CodeBlock
  cpp="class Solution {
public:
    int diameterOfBinaryTree(TreeNode* root) {
        int maxDiameter = 0;
        calculateHeight(root, maxDiameter);
        return maxDiameter;
    }
    
private:
    int calculateHeight(TreeNode* node, int& maxDiameter) {
        if (node == nullptr) return 0;
        
        int leftHeight = calculateHeight(node->left, maxDiameter);
        int rightHeight = calculateHeight(node->right, maxDiameter);
        
        // Update the maximum diameter found so far
        maxDiameter = max(maxDiameter, leftHeight + rightHeight);
        
        // Return the height of the current node
        return 1 + max(leftHeight, rightHeight);
    }
};"

# Common Pitfalls

<Warning>
- **The O(N^2) Trap:** Calling a separate `height()` function for every single node in the tree. This recalculates heights repeatedly. Always merge the height calculation and diameter tracking into a single pass.
- **Node Count vs Edge Count:** The problem usually defines diameter by the number of edges. The number of edges is `leftHeight + rightHeight`. If it asked for nodes, it would be `leftHeight + rightHeight + 1`.
</Warning>
