# Theory & Concepts

A **Tree** is a non-linear hierarchical data structure consisting of nodes connected by edges. Unlike arrays and linked lists, which are linear, trees allow for the representation of hierarchical relationships.

### Key Terminology
- **Node**: An entity containing a value and pointers to its child nodes.
- **Root**: The topmost node of a tree, which has no parent.
- **Edge**: The link connecting two nodes.
- **Leaf**: A node with no children (its child pointers are null).
- **Parent**: A node that has at least one child.
- **Child**: A node extending from another node.
- **Subtree**: A structure consisting of a node and all of its descendants.

### Binary Trees
A **Binary Tree** is a specialized tree where every node has at most two children, typically referred to as the left child and the right child. This constraint makes binary trees highly predictable and forms the basis for more advanced structures like Binary Search Trees (BSTs) and Heaps.

# Common Pitfalls

<Warning>
- Confusing a general Binary Tree with a Binary Search Tree (BST). A standard binary tree has no ordering rules.
- Forgetting to handle the empty tree case (when root is null) in algorithms.
- Creating cyclic references. Trees must be directed acyclic graphs (DAGs).
</Warning>
