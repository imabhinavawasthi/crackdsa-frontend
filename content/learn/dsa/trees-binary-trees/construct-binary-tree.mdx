# Theory & Concepts

Constructing a Binary Tree requires two traversal arrays. The most common variation is constructing a tree from its **Preorder and Inorder** traversals.

### The Mechanics
To reconstruct a unique binary tree, you need:
1. **Preorder (or Postorder) array:** This tells you the **Root**. In a Preorder array, the first element is always the root. In Postorder, the last element is the root.
2. **Inorder array:** This tells you the **Structure**. Once you find the root in the Inorder array, everything to its left belongs to the left subtree, and everything to its right belongs to the right subtree.

### The Algorithm (Preorder + Inorder)
1. Pick the first element from the `preorder` array. This is our root.
2. Find the index of this root in the `inorder` array.
3. The number of elements to the left of this index tells us the size of the left subtree.
4. Recursively build the `root.left` passing the appropriate array boundaries.
5. Recursively build the `root.right` passing the remaining array boundaries.

*Optimization:* Searching for the root in the inorder array takes O(N) time, leading to an O(N^2) algorithm. We optimize this to O(N) by storing the inorder values and their indices in a HashMap!

# Common Pitfalls

<Warning>
- **Passing Slices Instead of Indices:** In Python, doing `inorder[:mid]` and `inorder[mid+1:]` creates new arrays at every step, ruining the space and time complexity. Always pass `left` and `right` integer boundaries!
- **Wrong Recursion Order (Postorder variation):** If you are constructing from Postorder + Inorder, the root is at the end of the postorder array. Because you read the postorder array backwards, you MUST construct `root.right` before `root.left`!
</Warning>
