# Theory & Concepts
In the **Recover Binary Search Tree** problem, you are given a BST where exactly two nodes have had their values swapped by mistake. Your goal is to recover the tree without changing its structure.

### Core Intuition
An **Inorder Traversal** of a valid BST must yield a strictly increasing sequence. If two nodes are swapped, there will be "dips" in this increasing sequence.
Suppose the correct sequence is `[1, 2, 3, 4, 5, 6]`.
If we swap `2` and `5`, we get `[1, 5, 3, 4, 2, 6]`.

Let's look at adjacent elements:
- `5 > 3` (First anomaly! The larger element `5` is out of place).
- `4 > 2` (Second anomaly! The smaller element `2` is out of place).

Thus, the strategy is to keep track of the `prev` node during an inorder traversal.
- The **first** swapped node is the `prev` node when the first anomaly is found.
- The **second** swapped node is the `curr` node when the second anomaly is found.
*(Note: If the swapped nodes are adjacent like swapping `3` and `4` to get `[1, 2, 4, 3, 5]`, there is only one anomaly, and the two swapped nodes are the `prev` and `curr` at that exact spot).*

    void inorder(TreeNode* node) {
        if (!node) return;
        
        inorder(node->left);
        
        if (prevElement && prevElement->val > node->val) {
            if (!firstElement) {
                firstElement = prevElement;
            }
            secondElement = node;
        }
        prevElement = node;
        
        inorder(node->right);
    }

# Common Pitfalls
<Warning>
- Stopping the traversal after finding the first anomaly. You must continue traversing because the second swapped node might be further down the sequence!
- Falsely assuming that the second anomaly's `prev` node is the second swapped node. It is the `current` node of the second anomaly that is the out-of-place small element.
</Warning>
