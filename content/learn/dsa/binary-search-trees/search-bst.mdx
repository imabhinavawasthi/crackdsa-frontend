# Theory & Concepts
Searching in a **Binary Search Tree (BST)** is one of the most fundamental operations. Because every node follows the rule `Left < Root < Right`, we can locate any element efficiently by discarding half of the tree at each step. This process is identical to performing **Binary Search** on a sorted array.

### Core Intuition
Starting from the root:
1. If the current node is `null`, the target does not exist in the tree.
2. If the current node's value equals the target, you've found it!
3. If the target is strictly **less** than the current node's value, the target *must* be in the left subtree.
4. If the target is strictly **greater**, it *must* be in the right subtree.

# Common Pitfalls
<Warning>
- Using recursion for searching. While valid and elegant, recursion consumes O(H) space on the call stack. The iterative approach is trivial to write and uses O(1) space.
- Unnecessarily traversing the entire tree (O(N) time) instead of exploiting the BST property to go left or right.
</Warning>
