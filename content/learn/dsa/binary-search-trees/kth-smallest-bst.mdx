# Theory & Concepts
Finding the Kth smallest element in a **Binary Search Tree (BST)** is one of the most classic interview questions because it elegantly combines tree traversal with the BST's inherent sorting property.

### Core Intuition
An **Inorder Traversal** (Left -> Root -> Right) of a BST visits the nodes in perfectly ascending order. Therefore, to find the Kth smallest element, we simply need to perform an inorder traversal and stop exactly at the $K$-th node we visit!

Instead of storing all elements in an array and then accessing the $K-1$ index (which takes $O(N)$ space), we can optimize the space by keeping a counter variable. Once the counter reaches $K$, we've found our answer.

    int kthSmallest(TreeNode* root, int k) {

    void inorder(TreeNode* node, int k, int& count, int& result) {

        inorder(node->left, k, count, result);
        
        count++;
        if (count == k) {
            result = node->val;
            return;
        }
        
        inorder(node->right, k, count, result);
    }
};"

# Common Pitfalls
<Warning>
- Storing the entire inorder traversal in an array, taking O(N) space. You should always aim for O(H) space by using an early-exit counter.
- Forgetting to stop the traversal once the Kth element is found, leading to unnecessary computation on the right subtrees.
</Warning>
