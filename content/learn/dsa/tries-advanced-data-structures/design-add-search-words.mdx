# Theory & Concepts
The **Design Add and Search Words Data Structure** problem tests your ability to adapt a standard Trie to handle wildcards. You need to support inserting words and searching for them, but with a twist: the search query can contain the '.' character, which matches *any* single letter.

### Core Intuition
Adding words remains exactly the same as a standard Trie. The difficulty lies entirely in the search method. 

When searching for a normal character, we proceed down the deterministic path. However, when we encounter a wildcard `.` character, we no longer know which path to take. The solution? **Backtracking / DFS (Depth-First Search)**. We must explore *every* available child node at that level to see if any path successfully matches the remainder of the query string.

If a match is found on any path, we return true. If all branches exhaust without a match, we backtrack and return false.

# Common Pitfalls
<Warning>
- Passing substrings down the recursive DFS (e.g., `word.substring(1)`) instead of passing an index variable. Substrings create a massive overhead in memory and time (O(L) per call), leading to TLE.
- Failing to properly handle the base case. The recursion must stop explicitly when `idx == word.length()` and return `node.isEndOfWord`.
</Warning>
