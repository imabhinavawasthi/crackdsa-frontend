# Theory & Concepts
The **Maximum XOR of Two Numbers** problem introduces a radically different application of the Trie: a **Bit Trie** (or Binary Trie). Instead of storing letters ('a' to 'z'), we store binary digits (`0` and `1`). 

### Core Intuition
The XOR operation (`^`) yields a `1` only when bits are *different*. To maximize the XOR of a number $X$ against an array, we want to pair $X$ with a number $Y$ such that their bits differ at the **most significant positions** (the highest bits).

A brute force approach comparing every pair takes $O(N^2)$.
Instead, we convert all numbers into 32-bit binary representations and insert them into a Trie where each node has only two children: `0` and `1`.
When we take a number $X$ and want to find its best pair $Y$:
1. We iterate through the bits of $X$ from highest (31) down to lowest (0).
2. At each step, we look at the Trie. If $X$'s bit is `0`, we passionately *want* to go down the `1` branch to get an XOR of `1`.
3. If that opposite branch exists, we take it! If it doesn't, we are forced to take the branch matching $X$'s bit (yielding an XOR of `0`).
4. This greedy traversal guarantees the absolute maximum XOR in strictly $O(32)$ time!

# Common Pitfalls
<Warning>
- Traversing from Least Significant Bit (LSB) to Most Significant Bit (MSB). This destroys the greedy approach! You must prioritize differing bits at the *highest* positions first.
- Not handling integer bounds correctly. `1 << 31` might overflow signed 32-bit integers in some C++ compilers. Ensure safe shifting or use unsigned types.
</Warning>
