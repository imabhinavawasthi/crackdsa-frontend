# Theory & Concepts
Welcome to **Fenwick Trees**, famously known as **Binary Indexed Trees (BIT)**. If Segment Trees felt like writing an encyclopedic amount of code, a Fenwick Tree is the minimalist wizard's alternative. 

### Core Intuition
A Fenwick Tree solves the exact same problem as a Segment Tree—Dynamic Range Sum Queries and Point Updates in O(log N)—but does so using bitwise operations and a strictly `N+1` sized array!

The genius of Fenwick trees lies in isolating the "Lowest Set Bit" (LSB) of an index to define intervals.
Every index `i` in the BIT array stores the sum of a specific range of elements. The size of this range is equal to the value of the Lowest Set Bit of `i`.

### The Magic Formula: `x & (-x)`
In two's complement binary arithmetic, `x & (-x)` isolates the lowest set bit.
- **Updating**: To add a value, we start at index `i` and move UP the tree by **adding** the LSB (`i += i & (-i)`).
- **Querying**: To get the prefix sum up to index `i`, we start at `i` and move DOWN by **subtracting** the LSB (`i -= i & (-i)`).

# Common Pitfalls
<Warning>
- Fenwick Trees **must be 1-indexed**. Using 0-indexing causes an infinite loop because `0 & (-0)` is 0, so the index never increments.
- Fenwick trees are naturally meant for prefix sums. Finding a range sum `[L, R]` requires querying `Query(R) - Query(L-1)`.
</Warning>
