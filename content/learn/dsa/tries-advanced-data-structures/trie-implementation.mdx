# Theory & Concepts
A **Trie** (pronounced "try", also known as a prefix tree) is a specialized tree data structure used for efficient retrieval of a key in a large dataset of strings. Unlike binary search trees where nodes store the entire key, in a Trie, each node represents a single character of a string.

### Core Intuition
- **Nodes and Edges**: Each node contains an array or hash map of pointers to its children (e.g., 26 pointers for lowercase English letters). The root node represents an empty string.
- **Paths Represent Words**: A path from the root to any node represents a prefix of a word or a complete word.
- **End-of-Word Marker**: Because prefixes can be valid words themselves (like "app" and "apple"), nodes also store a boolean flag (`isEndOfWord`) to mark the end of a valid dictionary word.

Tries excel at solving problems involving prefix matching, autocomplete systems, and spell checkers, drastically outperforming Hash Sets when looking for prefixes.

# Common Pitfalls
<Warning>
- Forgetting to explicitly mark `isEndOfWord = true` at the very end of the `insert` method.
- Confusing a `search` query with a `startsWith` query. `search` must check `isEndOfWord` at the final node, while `startsWith` does not.
- Allocating memory inefficiently. In languages like C++, dynamically allocating `new TrieNode()` 26 times per node can lead to Memory Limit Exceeded; it is better to allocate only when characters exist.
</Warning>
