# Theory & Concepts
**Word Search II** is an infamous, hard-level problem that perfectly bridges two massive domains: **Tries** and **DFS/Backtracking on Grids**. You are given an `m x n` board of characters and a list of words. Your goal is to find all words on the board simultaneously.

### Core Intuition
If we search the board for *each* word individually (Word Search I), the complexity becomes astronomical. We would re-scan identical paths on the board over and over.

Instead, we reverse the logic: we insert all words into a **Trie**. Then, we run DFS from *every* cell on the board exactly once. At each step on the board, we move simultaneously down the Trie.
- If the current character on the board exists in the Trie node's children, we continue DFS.
- If it doesn't exist, we instantly prune the search path (early stopping). 
- If we hit a node with `isEndOfWord`, we've found a word!

        if (r < 0 || c < 0 || r >= rows || c >= cols || board[r][c] == '#') return;
        
        char ch = board[r][c];
        int idx = ch - 'a';
        if (node->children[idx] == nullptr) return;
        
        node = node->children[idx];
        if (node->word != \"\") {
            result.push_back(node->word);
            node->word = \"\"; // Avoid duplicates
        }
        
        board[r][c] = '#'; // Mark visited
        dfs(board, r + 1, c, node);
        dfs(board, r - 1, c, node);
        dfs(board, r, c + 1, node);
        dfs(board, r, c - 1, node);
        board[r][c] = ch; // Backtrack
    }

# Common Pitfalls
<Warning>
- Using a `Set` to store results. Instead, optimize by setting `node.word = null` after finding a word to prevent duplicates and early prune future hits.
- Passing strings in DFS instead of storing the full word exclusively at the Trie leaf. This avoids string concatenation overhead during recursion.
- Forgetting to properly backtrack by restoring `board[r][c] = ch` before the DFS function returns.
</Warning>
