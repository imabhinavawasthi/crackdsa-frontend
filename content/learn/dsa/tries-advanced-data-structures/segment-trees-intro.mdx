# Theory & Concepts
Welcome to the lesson on **Segment Trees**. While Tries specialize in prefix searches, Segment Trees specialize in **Dynamic Range Queries**. 

### Core Intuition
Imagine you have an array `A = [1, 3, 5, 7, 9, 11]`. You are constantly asked two types of operations:
1. What is the sum of elements from index `L` to `R`?
2. Update the value at index `i` to `val`.

Using a raw array: Updates take `O(1)`, but range sums take `O(N)`.
Using a Prefix Sum array: Range sums take `O(1)`, but updates take `O(N)` because you must rebuild the sums.

A **Segment Tree** achieves a beautiful compromise: both updates and queries take exactly **O(log N)** time. 

### Structure
A Segment Tree is a full binary tree where:
- The **leaf nodes** represent the individual elements of the array.
- The **internal nodes** represent the merged result (sum, min, max, etc.) of their children.
- The root node represents the result of the entire array from `0` to `N-1`.

This hierarchical structure allows us to skip over large ranges by instantly grabbing the pre-calculated result of a parent node!

# Common Pitfalls
<Warning>
- Misallocating array space. A segment tree built over an array of size `N` generally requires an array of size `4 * N` to be safe from out-of-bounds errors due to tree depth.
- Confusing 0-indexed trees vs 1-indexed trees. In a 0-indexed tree, the children are `2i + 1` and `2i + 2`.
</Warning>
