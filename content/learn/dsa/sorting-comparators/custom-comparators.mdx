# Theory & Concepts
Welcome to the lesson on **Custom Comparators**. Knowing standard sorting algorithms is great, but in $95\%$ of actual coding interviews, you won't be writing a sort from scratch. Instead, you'll use your language's built-in `sort()` function. 

However, you will frequently need to sort **complex objects**, **2D intervals**, or **strings based on custom logic**. To do this, you must write a Custom Comparator.

### Core Intuition (Strict Weak Ordering)
When you write a custom comparator function `compare(A, B)`, the system asks: *"Should A be placed before B?"*
- Return **True / Negative** if `A` should come first.
- Return **False / Positive** if `B` should come first, OR if they are equal.

**CRITICAL RULE:** Comparators mathematically require **Strict Weak Ordering**. This means that if `A == B`, your comparator **MUST return False** (or 0). If you return `True` for equal elements, you violate the mathematical properties of the built-in sort (usually IntroSort or Timsort), which can result in an infinite loop or a `Segmentation Fault` during the interview!

# Code Implementation
<CodeBlock

class Solution {
public:
    // Custom logic: Sort ascending by 2nd element. If equal, sort descending by 1st element.
    static bool customCompare(const vector<int>& a, const vector<int>& b) {
        if (a[1] != b[1]) {
            return a[1] < b[1]; // Ascending by 2nd element
        }
        return a[0] > b[0];     // Descending by 1st element
    }

    void solve(vector<vector<int>>& intervals) {
        // Using a custom static function
        sort(intervals.begin(), intervals.end(), customCompare);

        // Alternatively, using a modern Lambda Function (Highly Recommended for Interviews)
        sort(intervals.begin(), intervals.end(), [](const vector<int>& a, const vector<int>& b) {
            if (a[1] != b[1]) return a[1] < b[1];
            return a[0] > b[0];
        });
    }
};"
  java="// Java Implementation
import java.util.*;

class Solution {
    public void solve(int[][] intervals) {
        // Using Arrays.sort with a custom Lambda Comparator (Java 8+)
        // Sort ascending by 2nd element. If equal, sort descending by 1st element.
        Arrays.sort(intervals, (a, b) -> {
            if (a[1] != b[1]) {
                return Integer.compare(a[1], b[1]); // Ascending
            }
            return Integer.compare(b[0], a[0]);     // Descending (note the reversed a and b)
        });
    }

    // Example with Object sorting
    class Student {
        int score;
        String name;
    }
    
    public void sortStudents(List<Student> students) {
        Collections.sort(students, (s1, s2) -> {
            if (s1.score != s2.score) return s2.score - s1.score; // Descending by score
            return s1.name.compareTo(s2.name);                    // Ascending by name
        });
    }
}"
  python="# Python Implementation
from functools import cmp_to_key

class Solution:
    def solve(self, intervals: list[list[int]]) -> None:
        # Python primarily uses the 'key' argument returning tuples for multi-level sorting.
        # Sort ascending by 2nd element. If equal, sort descending by 1st element (-x[0]).
        intervals.sort(key=lambda x: (x[1], -x[0]))

    # If you MUST use a traditional two-argument comparator (rare in Python 3):
    def advanced_solve(self, strings: list[str]) -> None:
        def custom_compare(a: str, b: str) -> int:
            if a + b > b + a:
                return -1 # a comes first
            elif a + b < b + a:
                return 1  # b comes first
            else:
                return 0  # equal

        strings.sort(key=cmp_to_key(custom_compare))"

# Common Pitfalls
<Warning>
- **Returning True for Equals (C++):** Writing `return a <= b` inside a C++ comparator will cause Undefined Behavior and likely crash the program. Always use `<` or `>`.
- **Integer Overflow (Java):** Instead of using `return a - b` which can overflow if `a` is heavily positive and `b` is heavily negative, always use `Integer.compare(a, b)`.
- **Static Class Methods (C++):** If you declare your comparator as a separate function inside a `class Solution`, it MUST be marked `static`. Otherwise, the invisible `this` pointer creates a signature mismatch with `std::sort`.
</Warning>
