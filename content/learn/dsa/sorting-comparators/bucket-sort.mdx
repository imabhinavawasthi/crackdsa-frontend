# Theory & Concepts
Welcome to the lesson on **Bucket Sort**. Bucket Sort is a distribution sort algorithm. Similar to Counting Sort, it skips standard element-to-element comparisons at the macro level, but unlike Counting Sort, it is highly effective for **floating-point numbers**.

### Core Intuition
The logic is divided into three steps:
1. **Scatter:** Create an array of empty "buckets" (which are typically dynamic lists or arrays themselves). Distribute the elements from the input array into these buckets based on a mathematical mapping (like multiplying a floating point number by $N$).
2. **Sort Inside:** Sort each individual bucket. Because the buckets are expected to be small, we typically use **Insertion Sort**, which is incredibly fast on tiny datasets.
3. **Gather:** Iterate through the buckets in order, and concatenate all the elements back into the original array.

The fundamental assumption of Bucket Sort is that the input is **uniformly distributed** over a range. If the data is clumped together, all elements will fall into a single bucket, completely destroying the algorithm's performance.

public:
    void bucketSort(vector<float>& arr) {
        int n = arr.size();
        if (n <= 0) return;

        // 1. Create n empty buckets
        vector<vector<float>> buckets(n);

        // 2. Scatter elements into different buckets
        for (int i = 0; i < n; i++) {
            // Mapping elements in range [0.0, 1.0) to bucket index
            int bucketIdx = n * arr[i]; 
            buckets[bucketIdx].push_back(arr[i]);
        }

        // 3. Sort individual buckets
        for (int i = 0; i < n; i++) {
            // Using standard sort (or insertion sort) for small buckets
            sort(buckets[i].begin(), buckets[i].end());
        }

        // 4. Gather all sorted buckets back into arr
        int index = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < buckets[i].size(); j++) {
                arr[index++] = buckets[i][j];
            }
        }
    }
};"

# Common Pitfalls
<Warning>
- **Non-Uniform Data:** The biggest pitfall is applying Bucket Sort to heavily clustered data. If $99\%$ of your data maps to a single bucket, you've just wasted $O(N)$ memory only to default back to an $O(N^2)$ sort.
- **Incorrect Mapping Function:** The formula `int bucketIdx = n * arr[i]` only works for floats cleanly distributed in the range $[0.0, 1.0)$. If your range is different, you MUST calculate the `max_val` and `min_val` to create a normalized mapping formula.
</Warning>
