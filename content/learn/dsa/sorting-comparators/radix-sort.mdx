# Theory & Concepts
Welcome to the lesson on **Radix Sort**. While Counting Sort is limited by the maximum value in an array (the range $K$), Radix Sort cleverly works around this limitation by sorting elements **digit by digit**. 

### Core Intuition
The standard approach is **LSD (Least Significant Digit) Radix Sort**. We start by sorting the numbers based entirely on their last digit (the 1s place). Then we sort them again based on the 10s place, then the 100s place, and so on up to the maximum number of digits.

**The Golden Rule:** The subroutine algorithm used to sort the individual digits MUST be a **stable sort**. If it is not stable, sorting by the 10s place will scramble the relative order previously established by the 1s place, ruining the entire algorithm. We almost exclusively use a modified **Counting Sort** for this subroutine because sorting digits means our range $K$ is always strictly $0-9$.

# Common Pitfalls
<Warning>
- **Unstable Subroutine:** If you attempt to use Quick Sort or an unstable version of Counting Sort for the digits, the algorithm will completely fail to sort the numbers.
- **Negative Numbers:** The standard implementation does not support negative numbers. A common workaround is to split the array into negatives and positives, sort them separately (treating negatives as positives), and then reverse/merge them.
- **Assuming it always beats O(N log N):** Radix Sort has a large constant factor. If $d$ is very large (e.g., sorting massive 64-bit integers), $d \times N$ can actually be slower than $N \log N$ in practical application.
</Warning>
