# Theory & Concepts
Welcome to the lesson on **Counting Sort**. Most sorting algorithms (Merge, Quick, Heap) are comparison-based, meaning their speed is mathematically bottlenecked at $O(N \log N)$. Counting Sort breaks this barrier and achieves a blazing $O(N)$ linear time complexity.

How? It completely skips comparing elements against each other.

### Core Intuition
Counting Sort only works on **discrete values** (like integers) that fall within a specific, relatively small range from $0$ to $K$.

The algorithm works in three main steps:
1. **Count Frequencies:** Iterate through the array and record how many times each distinct number appears using an auxiliary `count` array of size $K+1$.
2. **Prefix Sums:** Modify the `count` array by adding the previous count to the current count. This transforms the frequencies into **actual index positions**. For example, if `count[x] = 5`, it means the last occurrence of the number `x` belongs at index 4 (0-indexed).
3. **Stable Placement:** Traverse the original array **backwards** (to maintain stability). For each element, look up its correct position in the `count` array, place it in the output array, and decrement the `count` value for that number.

        for (int i = 0; i < arr.size(); i++) {

        }

# Common Pitfalls
<Warning>
- **Ignoring the K Factor:** Counting Sort is a disaster if $K$ is significantly larger than $N$. Sorting the array `[1, 1000000000]` takes $O(K)$ space and time, crashing your program for just 2 elements. Use it ONLY when $K = O(N)$.
- **Iterating Forwards for Placement:** In Step 3, if you iterate from `0 to N-1`, the sort will still work, but it will **lose its stability**. Iterating backward guarantees that duplicate elements retain their original relative order.
- **Negative Numbers:** Standard Counting Sort uses the values directly as array indices. If your array has negative numbers, you must find the minimum value and shift all elements up by an offset to make them strictly non-negative.
</Warning>
