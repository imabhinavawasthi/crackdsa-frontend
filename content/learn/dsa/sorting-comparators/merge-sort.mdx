# Theory & Concepts
Welcome to the lesson on **Merge Sort**. This is an incredibly powerful algorithm that forms the backbone of many built-in sorting libraries. It is a quintessential example of the **Divide and Conquer** paradigm.

### Core Intuition
The logic of Merge Sort can be broken down into three distinct steps:
1. **Divide:** Recursively divide the array into two halves until you reach sub-arrays of size 1. An array of size 1 is inherently sorted.
2. **Conquer:** The recursive calls return, providing you with two sorted sub-arrays.
3. **Combine (Merge):** Merge the two sorted sub-arrays together to form a single, fully sorted array.

The heart of the algorithm lies in the merge step. Merging two sorted arrays is efficient ($O(N)$ time) because you can use two pointers, repeatedly picking the smaller element from the front of either array.

# Common Pitfalls
<Warning>
- **Space Complexity Amnesia:** Forgetting that standard Merge Sort on arrays is NOT in-place and requires $O(N)$ extra memory. In an interview, allocating an array on every recursive step is inefficient; passing a single pre-allocated temp array is heavily preferred.
- **Off-by-one errors in `mid`:** Carelessly calculating mid or passing incorrect bounds (`mergeSortHelper(arr, mid, right)` instead of `mid + 1`) can cause infinite recursion.
- **Unstable Comparisons:** Using `L[i] < R[j]` instead of `L[i] <= R[j]` during the merge step ruins the stability of Merge Sort.
</Warning>
