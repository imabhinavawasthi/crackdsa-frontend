# Theory & Concepts
Welcome to the lesson on **Insertion Sort**. While it has a quadratic worst-case time complexity, Insertion Sort is highly regarded for its sheer speed when handling small arrays or partially sorted data. In fact, modern sorting libraries often fall back on Insertion Sort under the hood.

### Core Intuition
Insertion Sort works exactly like you would sort a hand of playing cards. You start with an empty left hand and the cards face down on the table. You remove one card at a time from the table and insert it into the correct position in your left hand. To find the correct position for a card, you compare it with the already sorted cards in your hand, from right to left.

Algorithmically, the array is conceptually split into a sorted and an unsorted part. Values from the unsorted part are picked and placed at the correct position in the sorted part by shifting larger elements one position to the right.

# Common Pitfalls
<Warning>
- **Off-by-one errors:** Forgetting that `i` should start from `1`, not `0`, since a single element is already trivially sorted.
- **Overwriting Data:** Failing to store the current element in a temporary `key` variable before shifting elements to the right. If you don't save it, it gets overwritten.
- **Swapping instead of Shifting:** Some implementations swap elements continuously until the item is in place. While logically sound, shifting elements right and writing the key once at the end is fundamentally faster because it reduces write operations.
</Warning>
