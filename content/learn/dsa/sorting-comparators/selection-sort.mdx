# Theory & Concepts
Welcome to the deep dive into **Selection Sort**. At its core, Selection Sort is one of the most intuitive and fundamental sorting algorithms you'll encounter. While it's rarely the fastest method for massive datasets, mastering it helps build a solid foundation in algorithmic thinking and array manipulation.

### Core Intuition
The algorithm works by logically dividing the array into two parts: a sorted subarray on the left and an unsorted subarray on the right. Initially, the sorted part is empty, and the unsorted part is the entire array.

In every iteration, the algorithm scans the unsorted subarray to **select** the smallest element. It then swaps this minimum element with the leftmost element of the unsorted subarray, effectively growing the sorted portion by one element. This process repeats until the entire array is sorted.

Selection sort is notable because it makes the absolute minimum number of swaps possible ($O(N)$), making it theoretically useful when write operations to memory are extremely costly.

# Common Pitfalls
<Warning>
- **Stability Issues:** Standard Selection Sort is an unstable sort. When you swap the minimum element with the first unsorted element, you might jump over equal elements, destroying their relative order.
- **Unnecessary Swaps:** Forgetting to check if `min_idx != i` before swapping can lead to redundant operations where an element is swapped with itself.
- **Performance Blindness:** It never breaks early. Even if the array is already sorted, Selection Sort will obliviously take $O(N^2)$ time.
</Warning>
